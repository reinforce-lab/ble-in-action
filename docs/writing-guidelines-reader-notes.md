# 読者層別Note 執筆ガイドライン（クイックリファレンス）

**最終更新**: 2026-05-29
**目的**: 各章に【読者層の方へ】Noteを適切に挿入するための指針。

## 読者層と関心事

- **ホビースト**: 一人で完結したい。学習のハードルを下げる、低コストルート（開発ボード・無料ツール）、コピペで動く実例。
- **ファーム開発者**: アプリ側とのすり合わせ。GATT構造・UUID命名規則・接続パラメータの事前合意、相手領域（アプリ）の概要把握。
- **アプリ開発者**: ファーム側とのすり合わせ。ファームで定義したUUID/GATTとの整合、デバッグでの問題切り分け。
- **企画者**: 可能性と制約の判断。BLEで何ができて何ができないか、アイディア発想軸（生体情報・装着部位・センサー・用途）、開発者との対話。

## 挿入ルール

- **形式**: `【○○の方へ】` で始め、立場別の視点・活用方法を1〜3段落。本文で説明済みの内容は繰り返さない
- **頻度**: 1章あたり **2〜4箇所**。自然な文脈で、技術説明の流れを分断しない。全章に無理に入れない
- **タイミング**: 章冒頭（その章の各層へのメリット）／技術的な選択の分岐点／実装の具体例／章末（次への橋渡し）

## 記述例

```markdown
【企画者の方へ】
ビーコンは「人の動線を可視化」する用途に強みがあります。小売の動線分析、
イベントの行動把握、オフィスの会議室利用モニタリングなど。センサーと
組み合わせれば、環境モニタリング＋位置情報の統合システムになります。
通信距離は約10〜30m、データ量は数〜数十バイト、電池寿命は設計次第で
数ヶ月〜数年が目安です。
```
