# 執筆ガイドライン：読者層別の配慮

**最終更新**: 2025-10-24  
**目的**: 各章執筆時に、3つの読者層（ホビースト、ファーム/アプリ開発者、企画者）への配慮を適切に織り込むためのガイドライン

---

## 基本方針

### 1. 序文での提示（簡潔・動機付け中心）
- 3つの読者層の特定と各層へのメリット明示
- 本書の活用方法の大枠
- 技術詳細は最小限、読み進める動機を与える

### 2. 各章での文脈に沿った言及（技術的・実践的）
- その章のトピックと自然に結びつける
- 繰り返し語ることで、理解を深める
- 読者は「自分の立場で」理解できる

## 読者層別の配慮ポイント

### ホビースト向けの配慮

#### 言及すべきタイミング
- **第5章「nRF52840開発環境」**: STEM教材（Adafruit Feather等）との比較、Arduino IDEルート
- **第6章「ペリフェラル実装」**: 既存ファームのカスタマイズ方法
- **第9章「iOS Core Bluetooth」**: Xcodeの基礎、一人で実装する際のTips
- **第12-15章（プロジェクト実践）**: 一人で完結させるためのステップ

#### 配慮の内容
- **学習のハードルを下げる**: 「STEM教材から始められる」ことを明示
- **全体像の把握**: 「ファームとアプリの両方を見通す」視点
- **低コストルート**: 開発ボード、無料ツールの紹介
- **実例重視**: コピペで動くサンプルコード

#### 記述例
```markdown
【ホビーストの方へ】
STEM教材（Adafruit Feather nRF52840等）を使う場合、
Arduino IDE + Adafruit nRF52ボードパッケージが最も簡単です。
本書ではnRF Connect SDKを使いますが、基本概念は共通です。
環境構築に時間をかけたくない場合は、Arduino IDE + Adafruit環境で
まず動かしてから、本格的な開発はSDKに移行する方法も有効です。
```

### ファーム/アプリ開発者向けの配慮

#### 言及すべきタイミング
- **第4章「ATT・GATT・プロファイル」**: GATT構造の事前設計の重要性
- **第6章「ペリフェラル実装」**: アプリ側の実装を意識したUUID設計
- **第9章「iOS Core Bluetooth」**: ファーム側で定義したUUIDとの整合性
- **第16-17章（デバッグ）**: ファーム/アプリ間の問題切り分け

#### 配慮の内容
- **すり合わせポイントの明示**: GATT構造、UUID命名規則、接続パラメータ
- **相手領域の理解**: 「アプリ開発者がファームを概要把握」「ファーム開発者がアプリを概要把握」
- **トラブル回避**: 事前設計、命名規則、ドキュメント化
- **デバッグ手法**: パケットキャプチャでの問題切り分け

#### 記述例（ファーム開発者向け）
```markdown
【ファーム開発者の方へ】
この段階でアプリ側の開発環境も確認しておくと、
後のすり合わせがスムーズです（第9章参照）。
特に、カスタムUUIDの命名規則を両者で事前に合意しておくと、
実装フェーズでの混乱を避けられます。
```

#### 記述例（アプリ開発者向け）
```markdown
【アプリ開発者の方へ】
ファーム側で定義したUUIDと一致させる必要があります。
ファーム開発者と、UUIDの命名規則を事前に合意しておきましょう
（16.2節のすり合わせプロセス参照）。
開発初期段階で、GATT構造の設計書（サービス、キャラクタリスティック、
UUID、データ型）を共有すると、手戻りが減ります。
```

### 企画者向けの配慮

#### 言及すべきタイミング
- **第1章「BLEとは何か」**: BLEの可能性と制約の概観
- **第2章「BLEの基本概念と用語」**: 標準プロファイル vs カスタムプロファイルの選択
- **第12-15章（プロジェクト実践）**: 実例からのアイディア発想法

#### 配慮の内容
- **可能性と制約**: 「何ができて、何ができないか」の判断軸
- **アイディア発想法**: 生体情報、装着部位、センサー、用途からの逆算
- **技術的実現可能性**: 「この企画は技術的に実現可能か」の判断材料
- **開発者との対話**: 技術者とのコミュニケーションを円滑にする知識

#### 記述例
```markdown
【企画者の方へ】
ビーコンは「人の動線を可視化」する用途に強みがあります。
- 小売: 店舗内の滞在時間・動線分析
- イベント: 来場者の行動パターン把握
- オフィス: 会議室の利用状況モニタリング

センサー（温湿度、人感）と組み合わせると、
環境モニタリング + 位置情報の統合システムが構築できます。

【技術的制約】
- 通信距離: 約10-30m（障害物により減衰）
- データ量: 小容量（数バイト〜数十バイト）が基本
- 電池寿命: 適切な設計で数ヶ月〜数年（用途による）

【発想のヒント】
ビーコンの「位置を知らせる」機能から、
「どこにいるか」ではなく「誰がどこにどのくらいいたか」の
時系列データを活用すると、新しい価値を生み出せます。
```

## 読者層別Note挿入のガイドライン

### 挿入タイミング
1. **章の冒頭**: その章で得られる知識が各読者層にどう役立つか
2. **技術的な分岐点**: 「標準プロファイル vs カスタム」など選択が必要な箇所
3. **実装の具体例**: コードやコマンドの説明時に、立場別のTips
4. **章の末尾**: 次のステップへの橋渡し

### 挿入頻度
- **過度に繰り返さない**: 1章あたり2-4箇所程度
- **自然な文脈で**: 技術説明の流れを分断しない
- **必要な箇所のみ**: 全ての章に無理に入れる必要はない

### 記述形式
```markdown
【読者層の方へ】
配慮の内容を1-3段落で簡潔に。
技術的な詳細は本文で説明済みの前提で、
立場別の視点や活用方法を追加する形。
```
