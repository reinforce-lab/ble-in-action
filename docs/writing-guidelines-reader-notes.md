# 読者層別Note 執筆ガイドライン

**最終更新**: 2026-06-20
**位置づけ**: 本書の読者層定義、読者層別Note、章別配慮マップの正本。表記・Markdown書式は [writing-style-guide.md](writing-style-guide.md)、本書全体の理念は [book-constitution.md](book-constitution.md) を参照。

## 目的

本書は、ファーム、アプリ、企画、ホビーストがBLEについて同じ言葉で対話できるようにすることを目指します。
読者層別Noteは、本文の主たる説明を分断せず、特定の立場の読者が「この知識を自分の作業でどう使うか」を理解するために置きます。

Noteは本文の要約ではありません。
本文で説明済みの内容を繰り返すのではなく、立場ごとの判断、注意点、活用方法を補います。

## 読者層

### ホビースト

ホビーストは、一人でファーム、アプリ、筐体、利用シーンまで試す読者です。
関心は、低コストで始められること、手元で動かせること、失敗したときに自分で切り分けられることにあります。

Noteでは、次の観点を補います。

- 開発ボード、無料ツール、既製センサーなど、始めやすい選択肢。
- コピペで試せる実験の入口。
- どこまで自作し、どこから既存ツールを使うとよいか。
- 失敗時に最初に確認する箇所。

### ファーム開発者

ファーム開発者は、GATT設計、消費電力、接続安定性、センサー連携、OTAなどを担当する読者です。
関心は、アプリ側と何を事前に合意すべきか、BLE仕様とSDK実装の差をどう扱うかにあります。

Noteでは、次の観点を補います。

- GATT構造、UUID、Characteristic、Descriptorの設計。
- 接続パラメータ、通知頻度、MTU、消費電力のトレードオフ。
- アプリ側に伝えるべき制約や前提。
- ログやパケットキャプチャで切り分ける観点。

### アプリ開発者

アプリ開発者は、iOS Core Bluetooth、Android、Web Bluetooth、LinuxなどからBLE機器を扱う読者です。
関心は、ファーム側で定義されたGATTとアプリ実装をどう合わせるか、OS固有の制約をどう見積もるかにあります。

Noteでは、次の観点を補います。

- ファーム側のUUID、Characteristic、Notify/Indicate、Read/Writeとの対応。
- OS権限、バックグラウンド動作、スキャン制約。
- Core BluetoothなどのAPIが、実際のBLE通信のどの層を隠蔽しているか。
- ファーム側へ確認すべき事項。

### 企画者

企画者は、BLEで何が実現でき、何が難しいかを判断したい読者です。
関心は、技術的可能性、制約、開発者との会話に必要な語彙、アイディアの広げ方にあります。

Noteでは、次の観点を補います。

- BLEで実現しやすい用途と、向いていない用途。
- 通信距離、データ量、電池寿命、OS制約など、企画に影響する制約。
- センサー、装着部位、利用シーンからの発想軸。
- 開発者に確認すべき問い。

## 挿入ルール

- Noteは `【○○の方へ】` で始める。
- 1つのNoteは1〜3段落にする。
- 1章あたり2〜4箇所を目安にする。
- 全章に無理に入れない。
- 技術説明の流れを分断する場合は入れない。
- 本文で説明済みの内容を繰り返さない。
- 同じ章で同じ読者層に向けたNoteを連続させない。

## 挿入しやすい場所

- 章冒頭: その章を各読者層がどう読むとよいかを示す。
- 技術的な選択の分岐点: どの立場が何を判断すべきかを示す。
- 実装例の直後: 例を自分の作業へ移すときの注意を示す。
- デバッグや制約の説明後: 問題の切り分けや合意事項を示す。
- 章末: 次章へ進む前に、立場別の持ち帰りを示す。

## 記述例

```markdown
【企画者の方へ】
ビーコンは、人の動線や物の所在をゆるやかに可視化する用途に向いています。
一方で、1 cm単位の位置精度や大量データの転送には向きません。
企画段階では、通信距離、更新頻度、電池寿命、スマートフォン側の制約を開発者に確認してください。
```

```markdown
【ファーム開発者の方へ】
Notifyの頻度は、アプリ側の描画頻度だけで決めないでください。
接続間隔、送信データ量、電池寿命、OS側の受信処理が同時に効きます。
アプリ開発者とは、必要な更新頻度と許容できる遅延を先に合わせておくと、後工程の調整が減ります。
```

## 点検項目

- Noteが本文の要約になっていないか。
- Noteが本文の直前・直後の説明と自然につながっているか。
- その読者層が次に判断できること、確認できることが増えているか。
- 章内でNoteが多すぎないか。
- 4つの読者層のうち、章の主題に関係の薄い層へ無理に書いていないか。
