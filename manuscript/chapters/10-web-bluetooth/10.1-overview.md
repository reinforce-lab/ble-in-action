## Web Bluetooth APIとは

**Web Bluetooth API** は、Webブラウザ上のJavaScriptコードからBluetooth LEデバイスと直接通信できるW3C仕様のAPIです。ネイティブアプリ（iOS/Androidアプリ）をインストールすることなく、URLにアクセスするだけでBLEデバイスを操作できるWebアプリを構築できます。

第9章のCore Bluetooth（iOS）と比較すると、提供する機能は同等ですが、アクセス経路が大きく異なります。

```
【Core Bluetooth（第9章）】
iOSアプリ → Core Bluetooth framework → BTServer daemon → BLE Controller

【Web Bluetooth API（本章）】
Webページ (JavaScript) → Web Bluetooth API → ブラウザ → OS Bluetooth Stack → BLE Controller
```

Webブラウザが仲介役となり、OSのBluetooth APIへのアクセスを抽象化します。


## ユースケース

Web Bluetooth APIが特に有効なユースケースを紹介します。

**プロトタイピングと評価**
- ネイティブアプリ開発なしに、BLEペリフェラルの動作確認ができる
- デバッグツールや設定ツールをWebアプリとして配布できる

**IoTデバイスの設定画面**
- ファームウェアアップデートのUI
- センサーの閾値設定、キャリブレーション

**プレゼンテーション・デモ**
- BLEセンサーのメーター表示をリアルタイムでWebページに表示
- インタラクティブな展示物の操作

**限界をわかった上で使う**
- ブラウザサポートが限定的（後述）
- バックグラウンド動作は不可（タブがアクティブな間のみ動作）
- Safariがサポートしないため、iPhoneユーザーには届かない


## セキュリティモデル

Web Bluetooth APIには重要なセキュリティ制約があります。

### ① HTTPS必須（またはlocalhost）

BLEへのアクセスは **セキュアなコンテキスト（Secure Context）** からのみ許可されます。HTTPサイトでは使用不可です。

```
https://your-app.example.com  ✅ HTTPS
http://your-app.example.com   ❌ HTTP（ブロックされる）
http://localhost:3000          ✅ localhost は例外
http://127.0.0.1:3000          ✅ loopback は例外
```

### ② User Gesture必須

`requestDevice()` は必ず **ユーザーの操作イベント**（ボタンクリックなど）のハンドラから呼ぶ必要があります。ページ読み込みや `setTimeout` から呼ぶとエラーになります。

```javascript
// ✅ ボタンクリックから呼ぶ（正しい）
document.getElementById('connectBtn').addEventListener('click', async () => {
    const device = await navigator.bluetooth.requestDevice(...);
});

// ❌ 自動実行（エラーになる）
window.onload = async () => {
    const device = await navigator.bluetooth.requestDevice(...); // Must be called from user gesture
};
```

### ③ デバイス選択UIはOS管理

デバイス選択ダイアログはブラウザ（OS）が表示します。Webアプリ側でUIをカスタマイズすることはできません。ユーザーが自分でデバイスを選択・承認する設計になっており、任意のデバイスへの無断アクセスを防いでいます。


## ブラウザサポート状況

（2025年時点）

| ブラウザ | プラットフォーム | サポート | 備考 |
|---|---|---|---|
| Chrome | macOS / Windows / Android | ✅ 完全対応 | メインの対応ブラウザ |
| Edge | macOS / Windows | ✅ 完全対応 | Chromiumベース |
| Opera | macOS / Windows | ✅ 対応 | Chromiumベース |
| Firefox | 全プラットフォーム | ❌ 未対応 | 実装予定なし（セキュリティポリシー上の懸念）|
| Safari | macOS / iOS | ❌ 未対応 | Appleはサポートしない方針 |
| Chrome (iOS) | iOS | ❌ 未対応 | iOS上のChromeはWebKitを使うためSafari同等 |

**重要**: iOSではSafariフォールバックのため、iOS端末ではWeb Bluetooth APIは動作しません。Android ChromeとPC（Chrome/Edge）が主要ターゲットです。


## Core Bluetoothとの対応関係

第9章のCore Bluetoothと本章のWeb Bluetooth APIの概念対応を整理します。

| 概念 | Core Bluetooth（iOS, Swift）| Web Bluetooth API（JavaScript）|
|---|---|---|
| BLE管理オブジェクト | `CBCentralManager` | `navigator.bluetooth` |
| デバイス選択 | アドバタイズ発見＋フィルタ | `requestDevice()` でダイアログ |
| ペリフェラル | `CBPeripheral` | `BluetoothDevice` |
| GATT接続 | `connect(peripheral)` | `device.gatt.connect()` |
| サービス | `CBService` | `BluetoothRemoteGATTService` |
| キャラクタリスティクス | `CBCharacteristic` | `BluetoothRemoteGATTCharacteristic` |
| 値の読み出し | `readValue(for:)` / delegate | `characteristic.readValue()` / Promise |
| 値の書き込み | `writeValue(_:for:type:)` | `characteristic.writeValue()` |
| Notify購読 | `setNotifyValue(_:for:)` | `characteristic.startNotifications()` + event |

処理の流れも基本的に同じです: **デバイス選択 → GATT接続 → サービス取得 → キャラクタリスティクス取得 → Read/Write/Notify**。


## 開発環境の準備

Web Bluetooth APIを使う開発に必要な環境は非常にシンプルです。

**必要なもの**:
- Chrome または Edge ブラウザ
- テキストエディタ（VS Code 推奨）
- HTTPS環境（ローカル開発はlocalhost可）

**ローカル開発サーバーの起動**:

```bash
# Node.jsがあれば
npx serve .           # http-serve

# Python3があれば
python3 -m http.server 3000

# どちらもhttp://localhost:3000でアクセス可能
```


**まとめ**

- Web Bluetooth APIはWebブラウザから直接BLEデバイスを操作できるW3C仕様API
- セキュリティ制約: **HTTPS必須** + **User Gesture必須** + デバイス選択はOS管理
- Chrome/Edge（非iOS）が主要対応ブラウザ。SafariとiOS Chromeは非対応
- APIの概念はCore Bluetooth（第9章）と対応しており、学習コストが低い
