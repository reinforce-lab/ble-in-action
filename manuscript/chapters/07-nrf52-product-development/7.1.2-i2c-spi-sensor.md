### 7.1.2 I2C／SPIでセンサーを使う {#sec:ch7-sensor-bus}

センサーとの接続では、バスから値を読めたことと、製品として有効な測定値を得たことを分けます。電源投入、初期化、測定開始、変換待ち、読み出し、単位変換、異常値判定という状態があります。

#### 7.1.2.1 Devicetreeからセンサーを取得する

ZephyrのSensor Subsystemへ対応するデバイスなら、アプリケーションはバス固有の転送手順ではなくSensor APIを使えます。

```dts
&i2c0 {
    status = "okay";

    environmental_sensor: bme280@76 {
        compatible = "bosch,bme280";
        reg = <0x76>;
    };
};
```

```c
#define SENSOR_NODE DT_NODELABEL(environmental_sensor)

static const struct device *const sensor = DEVICE_DT_GET(SENSOR_NODE);

static int sensor_init(void)
{
    return device_is_ready(sensor) ? 0 : -ENODEV;
}
```

`status = "okay"`、`compatible`、バス、アドレスがドライバーの生成条件になります。コンパイルできたことだけでは、実基板上の電源、Pull-up、アドレス設定、配線が正しいとは限りません。

#### 7.1.2.2 測定とValue変換を分ける

```c
static int read_measurement(int16_t *encoded)
{
    struct sensor_value value;
    int err;

    err = sensor_sample_fetch(sensor);
    if (err) {
        return err;
    }

    err = sensor_channel_get(sensor, SENSOR_CHAN_AMBIENT_TEMP,
                             &value);
    if (err) {
        return err;
    }

    *encoded = (int16_t)(value.val1 * 100 + value.val2 / 10000);
    return 0;
}
```

Sensor APIの値を、そのままGATTへ送ってはいません。第6章で決めた「0.01単位の符号付き16 bit」へ変換しています。範囲外、センサー未応答、変換失敗は、通常の測定値とは別のDevice EventやStatusで表します。

#### 7.1.2.3 SPIでも責任の分け方は同じ

SPIではChip Select、Clock polarity／phase、最大周波数が加わります。I2Cと電気的な仕組みは異なりますが、アプリケーションでは次の境界を保ちます。

- Devicetree: バス、pin、周波数、Chip Select
- ドライバー: レジスター操作と転送
- 製品ロジック: いつ測るか、失敗時にどうするか
- GATT: どの形式とタイミングで公開するか

センサーを交換してもGATTインターフェースを維持できれば、クライアントを同時に変更せずに済みます。
