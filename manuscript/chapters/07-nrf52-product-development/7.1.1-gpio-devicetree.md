### 7.1.1 GPIOとDevicetreeを使う {#sec:ch7-gpio-devicetree}

Zephyrでは、基板上のLEDやボタンをCソースへ直接ピン番号として埋め込まず、Devicetreeでハードウェアを記述します。アプリケーションは、node labelやaliasからデバイスとピン設定を取得します。

#### 7.1.1.1 LEDを出力に設定する

nRF52840 DKのLEDは、ボード定義の`led0` aliasから取得できます。

```c
#include <zephyr/device.h>
#include <zephyr/devicetree.h>
#include <zephyr/drivers/gpio.h>

#define LED_NODE DT_ALIAS(led0)

static const struct gpio_dt_spec led =
    GPIO_DT_SPEC_GET(LED_NODE, gpios);

static int led_init(void)
{
    if (!gpio_is_ready_dt(&led)) {
        return -ENODEV;
    }

    return gpio_pin_configure_dt(&led, GPIO_OUTPUT_INACTIVE);
}
```

`gpio_dt_spec`には、GPIO Controller、pin番号、Active Lowなどのflagsがまとまります。`gpio_pin_set_dt()`はflagsを考慮するため、LEDがActive Lowの基板でも論理値`1`を「有効」として扱えます。

```c
static int apply_led_state(uint8_t requested)
{
    int err = gpio_pin_set_dt(&led, requested != 0U);

    if (err == 0) {
        device_service_set_led_state(requested != 0U);
    }
    return err;
}
```

先にGPIO操作の結果を確認し、成功後にGATTのLED Stateを更新します。クライアントが要求した値と、製品が実際に適用できた状態を混同しないためです。

#### 7.1.1.2 ボタン割り込みを受け取る

ボタンは`sw0` aliasから取得し、入力と割り込みを設定します。

```c
#define BUTTON_NODE DT_ALIAS(sw0)

static const struct gpio_dt_spec button =
    GPIO_DT_SPEC_GET(BUTTON_NODE, gpios);
static struct gpio_callback button_callback;

static void button_pressed(const struct device *port,
                           struct gpio_callback *cb,
                           gpio_port_pins_t pins)
{
    k_work_submit(&button_work);
}
```

割り込みコールバックでは、製品状態の更新やNotifyをまとめて行わず、Work Queueへ要求を渡します。チャタリング対策が必要な場合も、割り込みを受けた時刻を記録し、遅延可能Workで入力を再確認します。

#### 7.1.1.3 製品基板ではoverlayで差し替える

開発ボードのaliasを利用すると、アプリケーションは特定のpin番号から離れられます。製品基板では、board定義またはoverlayで同じaliasを製品の回路へ対応づけます。

```dts
/ {
    aliases {
        product-led = &status_led;
        product-button = &user_button;
    };
};
```

KconfigはGPIOドライバーをビルドへ含めるかを選び、DevicetreeはどのGPIOをどう配線したかを表します。この二つを同じ設定ファイルのように扱わないことが、ボード移植の出発点です。
