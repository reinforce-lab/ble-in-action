## 物理層——電波・変調・40チャンネルの設計 {#sec:physical-layer}

<!-- topic: 導入——物理層の役割 -->

アプリケーションが「Notifyを送る」と指示したとき、最終的にデータを運ぶのは2.4GHzの電波です。電波のスイッチを切り替えて0と1を表し、それを受け取った相手が元のビット列に復元する——この「デジタルデータを電波にのせて送り届ける」という仕事を担うのが**物理層（Physical Layer, PHY）**です。

物理層の仕様は、通信できるかどうかという根本を決めます。何MHzの電波を使うか、どんな方式で変調するか、どの周波数チャンネルを使うか。これらはソフトウェアで後から変えられるものではなく、BLEというシステムの設計の前提になっています。


## 2.4GHz ISMバンド——国際的に使える開放帯域

<!-- topic: ISMバンドの特性と選択理由 -->

BLEが使う周波数帯は**2.400〜2.4835 GHz**です。この帯域は**ISMバンド（Industry-Science-Medical band）**と呼ばれ、産業・科学・医療用途向けに国際的に開放されています。電子レンジが加熱に2.45 GHzを使っているのも、このISMバンドです。

無線通信に使う周波数は本来、国が割り当てを管理しています。新しい無線技術を世界規模で展開するには、各国の認可を取る必要があり、それには大変な手間と時間がかかります。ISMバンドは既に国際的に開放されているため、BLEのように広い普及を目指す無線技術にとって都合の良い選択肢でした。Wi-FiやZigBeeも同じ理由で2.4GHz帯を使っています。

結果として、2.4GHz帯は多くの無線機器が混在する「にぎやかな周波数帯」になっています。BLEはこの混雑した帯域を前提として設計されており、混信を避けるための工夫が随所に盛り込まれています。


## GFSK変調——周波数シフトで0/1を表す

<!-- topic: GFSK変調の仕組み -->

情報を電波にのせることを**変調（Modulation）**と呼びます。BLEが採用している変調方式は**GFSK（Gaussian Frequency Shift Keying、ガウシアン周波数シフトキーイング）**です。

基本的な考え方は単純です。送るビットが0のときと1のときで、搬送波の周波数を少しずらします。BLEでは250 kHzの周波数偏移を使います——ビットが0なら搬送波より250 kHz低い周波数、ビットが1なら250 kHz高い周波数で送信します。受信側はこの周波数の高低を検出することで0と1を読み取ります。

名前の「Gaussian（ガウシアン）」は、ビットが切り替わる瞬間の波形をガウスフィルタで滑らかにしていることに由来します。フィルタなしで急峻に周波数を切り替えると、切り替えの瞬間に広い周波数帯域のノイズが発生し、隣接するチャンネルに干渉します。ガウスフィルタを通すことで周波数占有幅を抑え、40本の細いチャンネルが成立します。

1シンボル（1回の送信単位）は1ビットに対応し、シンボルレートは1 Mbpsです。つまり1秒あたり100万ビットを送受信できます。


## 40チャンネルの配置——Wi-Fi共存の設計

<!-- topic: チャンネル配置とアドバタイジングチャンネルの設計意図 -->

BLEは2.400〜2.480 GHzの80 MHz帯域を、2 MHz幅で40本のチャンネルに分割しています。

```
周波数 (GHz)
2.400                                              2.480
  │                                                  │
  ├─[0]─[1]─[2]─···─[10]──[37]──[11]─···──[38]──[12]─···─[36]──[39]─┤
  │       ↑ データチャンネル(0〜36)         ↑ ADVチャンネル           │
  │                                                                    │
  │   Wi-Fi ch1          Wi-Fi ch6         Wi-Fi ch11                 │
  │   (2.412 GHz)       (2.437 GHz)        (2.462 GHz)                │
```

40チャンネルの内訳は次のとおりです：

| 種別 | チャンネル番号 | 中心周波数 | 用途 |
|---|---|---|---|
| アドバタイジングチャンネル | 37 | 2.402 GHz | デバイス発見・接続要求 |
| アドバタイジングチャンネル | 38 | 2.426 GHz | デバイス発見・接続要求 |
| アドバタイジングチャンネル | 39 | 2.480 GHz | デバイス発見・接続要求 |
| データチャンネル | 0〜36 | 2.404〜2.478 GHz | 接続後の通信（周波数ホッピング） |

アドバタイジングチャンネルの3本（37 / 38 / 39）の配置は、Wi-Fiとの共存を意識した意図的な設計です。Wi-Fiでよく使われるチャンネル1（2.412 GHz）・チャンネル6（2.437 GHz）・チャンネル11（2.462 GHz）の中心付近を避けるように、帯域の両端と中央の隙間に配置されています。

BLEのデバイスを発見できなければ通信が始まりません。アドバタイジングチャンネルでの受信失敗はそのまま接続失敗を意味します。そのため、あらかじめWi-Fiとの干渉が少ないチャンネルに発見用の3本を固定し、接続後のデータ通信はホッピングで切り抜ける設計になっています。

データチャンネルの37本は**適応周波数ホッピング（AFH: Adaptive Frequency Hopping）**で使われます。コネクションイベントごとにチャンネルを次々と切り替えることで、特定チャンネルに混信があっても通信全体が止まることなく継続できます。AFHの詳細は[@sec:conn-establish]で扱います。


## パケットフォーマット——4要素の構造

<!-- topic: パケットの構造と各要素の役割 -->

BLEが送受信するパケットは、次の4要素で構成されています。

```
┌──────────────┬─────────────────────┬───────────────────┬──────────────┐
│   Preamble   │   Access Address    │       PDU         │     CRC      │
│    8 ビット   │      32 ビット       │   2〜39 オクテット  │   24 ビット   │
└──────────────┴─────────────────────┴───────────────────┴──────────────┘
```

**プリアンブル（Preamble）**は、パケットの先頭にある8ビットのビットパターンです。`10101010` または `01010101` の交互パターンが送られます。受信回路はこの繰り返しパターンを使い、2つの仕事をします。1つは**AGC（Automatic Gain Control、自動利得制御）**——受信した電波の強度に応じて増幅率を自動で調整する処理です。もう1つはビット同期——1マイクロ秒ごとにサンプリングするタイミングの基準を取る処理です。プリアンブルがなければ、増幅率の調整が終わるより前に続くデータが来てしまい、受信に失敗します。

**アクセスアドレス（Access Address）**は32ビットの識別子です。接続ごとにイニシエータがランダムに生成した値がここに入り、受信回路はこのアドレスが自分宛かどうかを判定します。アドバタイジングパケットは固定値 `0x8E89BED6` を使い、不特定多数が受信できます。データパケットは接続ごとのランダム値を使い、第三者には受信できません。

**PDU（Protocol Data Unit）**は2〜39オクテットの実データ部分です。アドバタイジングPDUか、データPDUかで内部フォーマットが異なります。PDUには**ホワイトニング**処理が施されます。0か1が長く連続すると受信回路の周波数追尾が狂うため、送受信回路内部で0/1をランダムに混ぜる変換をかけています。アプリケーションからはこの処理は見えません。

**CRC**は24ビットの巡回冗長検査符号で、PDUの誤り検出に使います。1・2・3・4・5ビットの誤りを検出できます。暗号化を使う場合はCRCに加えてMIC（Message Integrity Check）が追加され、改ざん検知もできます。

パケット全体の長さは80〜376ビットです。ビットレートが1 Mbpsなので、1パケットあたり80〜376マイクロ秒で送受信が完了します。


## BLEの物理層スペック——低出力の設計思想

<!-- topic: ビットレートと伝達距離の設計意図 -->

BLEの物理層の主要スペックをまとめます。

| 項目 | 値 |
|---|---|
| 周波数帯 | 2.400〜2.4835 GHz |
| ビットレート | 1 Mbps |
| 変調方式 | GFSK（250 kHz偏移） |
| 送信電力 | 10 μW〜10 mW（−20〜+10 dBm） |
| 伝達距離 | 約50 m（見通し、標準出力時） |
| チャンネル数 | 40本（2 MHz幅） |

1 Mbpsというビットレートは、音声や動画のストリーミングには不十分ですが、センサ値の読み取りや設定値の書き込みには十分です。BLEは大量のデータを長時間流し続ける通信ではなく、「必要なときに少量のパケットを素早く届ける」ことを目的として設計されています。

Bluetooth 5.0では、2 Mbpsの変調方式が追加されました。これはより速い通信のためではありません。ビットレートが2倍になれば、同じデータを送る時間が半分になり、高周波回路の稼働時間が半分になります。半導体素子の電力の大部分が2.4GHzの高周波信号を送受信する回路で消費されますから、これは電池の稼働時間を大きく伸ばします。物理層のビットレート向上は、BLEにおいては通信高速化ではなく、さらなる低消費電力のための技術なのです。

なお、パケットのPDUを直接読み書きするときは、バイトオーダーに注意が必要です。アドバタイジング・パケットのペイロードはビッグエンディアン（最上位バイトから）で送出されますが、GATTプロファイルのデータはリトルエンディアン（最下位バイトから）で送出されます。Wiresharkでパケットを解析する際に、このバイトオーダーの違いが混乱の原因になることがあります。
