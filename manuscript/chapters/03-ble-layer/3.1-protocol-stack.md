## BLEプロトコルスタックの全体構造 {#sec:protocol-stack}

Advertising、接続、ペアリング、GATT通信は、それぞれ独立した機能に見えます。Bluetooth Core Specificationでは、これらを一つの大きな処理として定義せず、役割の異なるプロトコルやプロファイルへ分けています。この構造が、BLEのプロトコルスタックです。

BLEプロトコルスタックの主な構成を[@fig:ble-protocol-stack]に示します。図の上側ほどアプリケーションが扱う機能に近く、下側ほど無線パケットの送受信に近くなります。

![BLEプロトコルスタックの全体構造。HostはL2CAP、SMP、ATT、GATTなどを担当し、ControllerはLink LayerとPHYを担当する。HCIは両者の境界である。GAPはAdvertising、接続、セキュリティなど複数の構成要素を使って機器の振る舞いを定める。](images/diagrams/ch03-ble-protocol-stack.png){#fig:ble-protocol-stack}

### Controllerは無線通信を実行する

Controllerは、PHYとLink Layerを担当します。

PHY（Physical Layer、物理層）は、ビット列を無線信号へ変換し、受信した無線信号からビット列を取り出します。LE 1M、LE 2M、LE Codedは、PHYの種類です。使用する周波数、変調、送信電力、受信感度など、無線回路に近い仕様もPHYに含まれます。

Link Layerは、PHYを使ってAdvertising PDUやData PDUを送受信します。Advertising、Scanning、接続の開始、接続イベントの時刻、チャンネル選択、受信確認、再送、Link Layerパケットの暗号化などを担当します。

接続イベントはマイクロ秒単位の時刻に従って進みます。Hostがパケットを送るたびに無線の開始時刻を指示するのではなく、ControllerがLink Layerの状態と時刻を管理します。

### Hostは通信手順とデータの意味を扱う

Hostには、L2CAP、SMP、ATT、GATTなどがあります。

L2CAP（Logical Link Control and Adaptation Protocol）は、一つのLink Layer接続を複数の上位プロトコルで共有できるようにします。受信したデータをCIDによってATTやSMPへ振り分け、上位のPDUを下位で運べる単位へ分割して再構成します。

SMP（Security Manager Protocol）は、ペアリングと鍵の準備を行います。機器の入出力能力、認証方法、公開鍵、確認値、鍵情報などを交換します。SMPが準備した鍵を使って、実際にLink Layerパケットを暗号化する処理はControllerが担当します。

ATT（Attribute Protocol）は、Attribute Handleを指定して値を読み書きするRequest、Response、Command、Notification、IndicationなどのPDUを定義します。

GATT（Generic Attribute Profile）は、ATTを使って、サービス、キャラクタリスティック、ディスクリプターを表現します。サービス探索やキャラクタリスティックの操作など、ATT PDUを組み合わせたProcedureも定義します。

### HCIはHostとControllerの境界になる

HCI（Host Controller Interface）は、HostとControllerの間でコマンド、イベント、データを交換するための標準インターフェースです。

Hostは、Advertisingの開始、接続の作成、暗号化の開始、PHYの変更などをHCI CommandでControllerへ要求します。Controllerは処理結果をHCI Eventで返します。接続中のL2CAPデータはHCI ACL Dataとして、Isochronous通信のデータはHCI ISO Dataとして、この境界を通ります。

パソコンとUSB Bluetoothアダプターのように、HostとControllerが別の機器へ分かれる場合は、HCIのデータがUSBなどを通ります。一つのBluetooth SoCに両方が収まる場合は、ソフトウェア内部の境界になります。物理的な構成が違っても、HostとControllerの責任はHCIを境に分かれています。

### GAPは複数の構成要素を使う

GAP（Generic Access Profile）は、図の中でほかのプロトコルと同じように一段だけ上へ積み重なる伝送レイヤーではありません。機器をどのように発見し、接続し、セキュリティを適用するかという振る舞いを定めます。

たとえば、Peripheralとして接続を受け付ける動作には、Advertisingを行うLink Layer、Advertising Data、接続確立手順、必要に応じたSMPと暗号化が関係します。Central、Peripheral、Broadcaster、ObserverというロールもGAPが定義します。

アプリケーションは、OSやSDKのAPIを通じてGAPやGATTの機能を利用します。Core Specificationは、アプリケーションとHostの間の共通APIまでは定めていません。そのため、同じBLE機能でも、Core Bluetooth、Android Bluetooth API、Zephyr Bluetooth APIでは呼び出し方が異なります。

### Advertising DataはGATTを通らない

図を上から下へ眺めると、すべてのデータがApplication、GATT、ATT、L2CAP、HCI、Link Layer、PHYの順に流れるように見えるかもしれません。しかし、この順序は接続中のGATT通信には当てはまっても、BLEのすべての通信には当てはまりません。

接続前のAdvertising Dataは、GATT、ATT、L2CAPを通りません。HostがHCIを通じてControllerへAdvertising Dataを設定し、Link LayerがAdvertising PDUとして送信します。SMPはL2CAPを使いますが、ATTを通りません。Link Layer Control PDUはHostのL2CAPを通らず、Controller間で交換されます。

プロトコルスタックは、すべてのパケットが必ず通る一本の経路ではありません。どの機能がどの処理を担当し、必要な通信がどの構成要素を使うかを表しています。

### Core Specificationで各構成要素を探す

Bluetooth Core Specification v6.3は、複数のVolumeとPartに分かれています。主な構成要素の参照位置を次に示します。

| 構成要素 | Core v6.3の主な位置 | 主な内容 |
|---|---|---|
| Architecture | Vol 1, Part A／Part B | スタックとデータトランスポートの全体構造 |
| GAP | Vol 3, Part C | ロール、発見、接続、セキュリティの振る舞い |
| L2CAP | Vol 3, Part A | チャンネル、多重化、分割と再構成、シグナリング |
| ATT | Vol 3, Part F | アトリビュートとATT PDU |
| GATT | Vol 3, Part G | サービス構造とGATT Procedure |
| SMP | Vol 3, Part H | ペアリング、鍵生成、鍵配布 |
| HCI | Vol 4, Part E | Command、Event、ACL Data、ISO Data |
| PHY | Vol 6, Part A | LE PHYと無線信号 |
| Link Layer | Vol 6, Part B | Advertising、接続、制御手順、パケット |

: BLEプロトコルスタックとCore Specificationの参照位置 {#tbl:core-spec-stack-parts}

仕様書を最初から順番に読む必要はありません。たとえば、GATTのWriteが無線で再送される仕組みを調べるなら、GATTだけでなくATT、L2CAP、Link Layerを参照します。ペアリング画面が表示された後に暗号化が始まらない問題なら、GAP、SMP、HCI、Link Layerが関係します。

仕様書の構成要素を知る目的は、用語を暗記することではありません。調べたい動作がどこで定義されているかを見つけ、ファームウェア、OS、Controllerのどこまで確認すべきかを判断することです。
