# BLEの通信アーキテクチャ——基本経路から拡張技術へ {#sec:ch3}

<!--

- レイヤーの一覧を暗記させず、仕様が通信を分割する理由と、拡張機能が変更する位置を理解させる。

第2章では、一台の周辺機器を見つけ、接続し、必要なら通信を暗号化して、GATTの値を操作するまでを追いました。その経路を知っていれば、温度を読む、LEDを点灯する、測定値をNotifyで受け取るといった製品を作れます。

では、数十KBのファームウェアを短時間で送りたい場合は、何を変えればよいのでしょうか。電波の速度を2倍にすれば、更新時間も必ず半分になるのでしょうか。遠くまで届けたい場合、送信電力を上げる以外の方法はあるのでしょうか。何千台もの機器へ接続せずにデータを送り、応答まで受け取るには、GATTのキャラクタリスティックを増やせばよいのでしょうか。

これらの問いは、GATTからPHYまでを一列に並べただけでは答えられません。Bluetooth Core Specificationは通信を、処理を担当するレイヤーだけでなく、physical channel、physical link、logical transport、logical link、L2CAP channelという通信路の性質でも分けています。同じ「チャンネル」という名前でも、周波数を指す場合と、上位プロトコルの振り分け先を指す場合があります。

最初に、この二種類の地図を重ねます。すると、LE 2M PHYは電波へビットを載せる方法を変え、Data Length ExtensionはLink Layerで一度に運べる長さを変え、Extended Advertisingは接続前のデータ経路を広げる、と位置づけられます。Isochronous Channelsは、通常のGATT通信が使うLE ACLとは異なる時間特性のlogical transportです。Channel Soundingは、GATTの値を読み書きして距離を求める機能ではなく、無線区間へ測距の手順を加えます。

初期のBLEは、小さな状態をAttributeとして公開し、必要なときだけ接続して操作する、簡潔な利用方法を中心に設計されました。その基本は現在も残っています。一方、後から加わった機能の中には、GATT中心の周辺機器という理解だけでは捉えられないものがあります。基本経路を捨てたのではなく、その下にあるBluetoothの通信アーキテクチャを使って、新しい通信路を加えてきたのです。
