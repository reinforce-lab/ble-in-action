## DFU 転送失敗パターン集

### パターン1: 転送速度が遅い / タイムアウトする

```
症状: DFU転送が10%付近で止まる、または異常に遅い（数十分かかる）

原因: pipelineDepth が1のまま（デフォルト）
```

```swift
// ✅ pipelineDepth を大きくしてスループット向上
let config = FirmwareUpgradeConfiguration(
    estimatedSwapTime: 45.0,
    pipelineDepth: 3,          // デフォルト1 → 3に増加
    byteAlignment: .fourByte
)
let manager = FirmwareUpgradeManager(transport: transport, delegate: self)
manager.start(package: package, using: config)
```

> MTUが244バイト(DLE)の場合、pipelineDepth=3で転送速度が約3倍（10KB/s → 30KB/s）になります。

### パターン2: SMP Error 8 (MGMT_ERR_ENOMEM)

```
原因: Secondary スロットのFlashへの書き込みバッファが不足
解決: pm_static.yml の secondary スロットサイズを確認
     CONFIG_MCUBOOT_BOOTLOADER_SIZE の値が Primary サイズと一致しているか確認
```

### パターン3: 転送完了後に古いファームウェアに戻る

```
原因: boot_write_img_confirmed() が呼ばれていない
     → MCUBootは起動後に confirmed でなければ自動ロールバックする
```

```c
/* ✅ アプリ起動時の必須処理 */
#include <dfu/mcuboot.h>

void main(void)
{
    /* アップデート後の最初の起動かどうか確認 */
    if (boot_is_img_confirmed() == 0) {
        /* 動作確認OKならconfirmedにする */
        int ret = boot_write_img_confirmed();
        if (ret < 0) {
            printk("ERROR: Confirmed書き込み失敗: %d\n", ret);
        }
    }
    /* ... 以下アプリ本体 ... */
}
```

### パターン4: DFUモードに入れない

```
原因1: MCUBootのSMP serverが起動していない
       → Kconfig に CONFIG_MCUMGR=y, CONFIG_MCUMGR_TRANSPORT_BT=y を確認

原因2: 書き込み権限不足（ボンディングが必要な設定になっている）
       → bt_gatt accessの定義でBT_GATT_PERM_WRITEが適切か確認
```

## BLE 通信の暗号化

### 暗号化（Encryption）vs 認証（Authentication）

| 設定 | 保護内容 |
|---|---|
| 暗号化なし | 平文通信、スニファで内容を見られる |
| コeEncryption（Just Works） | 通信内容は暗号化。MITMには無防備 |
| Authenticated encryption（Passkey/OOB） | 通信暗号化 + 中間者攻撃に耐性 |

### Zephyr でのペアリング設定

```c
/* Kconfig */
CONFIG_BT_SMP=y           /* Secure Manager Protocol を有効化 */
CONFIG_BT_PRIVACY=y       /* RPA (Resolvable Private Address) を使用 */

/* アプリコード: ペアリングコールバック設定 */
static const struct bt_conn_auth_cb auth_cb = {
    .passkey_display = auth_passkey_display,
    .passkey_entry   = NULL,      /* Just Works の場合は NULL */
    .cancel          = auth_cancel,
};

void app_init(void)
{
    bt_conn_auth_cb_register(&auth_cb);
    /* ペアリング要求を自動承認しない（ユーザー確認あり） */
    bt_conn_auth_info_cb_register(&auth_info_cb);
}
```

### Just Works vs Passkey Entry の選択基準

```
Just Works（簡易）:
  - ディスプレイなし、入力装置なしのデバイス向け
  - 暗号化はされるが、中間者攻撃に対して無防備
  - センサーデータの盗聴対策にはなるが、
    接続相手の偽装（なりすまし）は防げない
  → 用途: 一般的なIoTセンサー、ビーコン

Passkey Entry:
  - 6桁の数字入力で相手を確認
  - MITMに耐性がある
  → 用途: 鍵/ドアロックなど安全性が要求されるアプリ

Numeric Comparison（Secure Connections）:
  - 両デバイスに表示された6桁の数字が一致するか確認
  - セキュリティ最高レベル
  → 用途: 医療機器、決済関連デバイス
```

## Man-in-the-Middle (MITM) 攻撃への対処

MITM攻撃に対処するには、Passkey または Numeric Comparison ペアリングを使用し、ペアリング後の通信に暗号化を要求します。

```c
/* Characteristic にアクセス制限をかける */
BT_GATT_CHARACTERISTIC(
    &threshold_char_uuid,
    BT_GATT_CHRC_WRITE,
    /* 認証済みの暗号化接続のみ書き込みを許可 */
    BT_GATT_PERM_WRITE_AUTHEN,
    NULL, write_threshold, NULL
),
```

`BT_GATT_PERM_WRITE_AUTHEN` は認証済み（MITMフラグ付きペアリング）の接続のみ書き込みを許可します。`BT_GATT_PERM_WRITE_ENCRYPT` は暗号化接続なら（認証なしでも）許可します。

---

**まとめ**

| 問題 | 対処 |
|---|---|
| DFU転送が遅い/止まる | `pipelineDepth` を3以上に増やす |
| 転送後に古いFWに戻る | `boot_write_img_confirmed()` を忘れずに |
| DFUモードに入れない | Kconfig の `CONFIG_MCUMGR_TRANSPORT_BT=y` 確認 |
| 通信が盗聴される | `CONFIG_BT_SMP=y` + Encryption 有効化 |
| なりすまし接続を防ぎたい | Passkey Entry + `BT_GATT_PERM_WRITE_AUTHEN` |
