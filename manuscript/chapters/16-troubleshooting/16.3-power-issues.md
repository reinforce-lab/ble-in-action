## 電流消費の目安

nRF52840の主要モードでの消費電流（典型値、Vcc=3V）:

| モード | 消費電流 |
|---|---|
| System off (Deep sleep) | 0.4 µA |
| System on, CPU idle | 1.5 µA |
| アドバタイズ (1280ms間隔) | 約2 µA平均 |
| アドバタイズ (100ms間隔) | 約15 µA平均 |
| BLE接続中 (500ms interval) | 約10 µA平均 |
| BLE接続中 (7.5ms interval) | 約150 µA平均 |
| RF送信 (0dBm) | 5.3 mA |
| CPU フル稼働 | 4.8 mA |
| BME280 測定中 | 0.7 mA |


## よくある問題: 電池が数日で切れる

```
症状: 電池寿命が期待値（数ヶ月）より大幅に短い

確認ステップ:
1. アドバタイズ間隔の確認
   NG: BT_LE_ADV_PARAM(0, BT_GAP_ADV_FAST_INT_MIN_2, ...)
       → 30ms間隔。高電力消費
   OK: BT_GAP_ADV_SLOW_INT_MIN(1280ms)でスキャンモードを遅くする

2. Connection Intervalの確認
   NG: 7.5〜15ms (デフォルト)
   OK: 接続後にConnection Intervalを500ms〜1sに延ばす

3. CPUがsleepに入れているか確認
   CONFIG_PM=y が設定されているか確認
   ピーク電流は高くても、スリープ時間が長ければ平均電流は低い

4. センサー読み出し頻度の確認
   不要な polling は sleep blockerになる
```


## Connection Interval の最適化

```c
/* 接続後に Connection Interval を長くするよう要求 */
static void connected_cb(struct bt_conn *conn, uint8_t err)
{
    if (err) return;

    /* Connection Intervalを400ms〜1000msに更新要求 */
    struct bt_le_conn_param param = {
        .interval_min = 320,   /* 400ms = 320 × 1.25ms */
        .interval_max = 800,   /* 1000ms = 800 × 1.25ms */
        .latency = 4,          /* 4 Connection Event skip可（Slave Latency） */
        .timeout = 600,        /* Supervision Timeout: 6000ms */
    };
    int ret = bt_conn_le_param_update(conn, &param);
    printk("接続パラメータ更新要求: %d\n", ret);
}
```

`latency = 4` は Peripheral が4回に1回だけ応答すればよいという設定です。Notify送信がないときの消費電力を大幅に削減できます。


## アドバタイズ戦略

```
接続されていない間のアドバタイズ:
  - Fast advertising (100-200ms): 接続直後の30秒間
  - Slow advertising (1000-2000ms): それ以降

接続後:
  - アドバタイズ停止（bt_le_adv_stop()）
  - センサー読み出しタイマーを長くする（例: 1s → 5s）

切断時:
  - Slow advertising に戻る
```


## 電力プロファイリングツール

- **nRF PPK2** (Power Profiler Kit 2): Nordicの電流計測ボード（USB接続）
- **nRF Connect for Desktop > Power Profiler**: 電流波形をGUIで可視化

```
測定手順:
1. nRF PPK2 と nRF52840 DKを接続
2. nRF Connect → Power Profiler を開く
3. アプリを動作させながら電流波形を記録
4. 各フェーズ（アドバタイズ/接続/スリープ）の電流を確認
```


**まとめ**

- アドバタイズ間隔を長く（Slow: 1280ms）するだけで平均電流が10分の1になる
- Connection Intervalを500ms、Slave Latency=4にすると大幅に節電
- `CONFIG_PM=y` でCPUのパワーマネジメントを有効化
- nRF PPK2 + Power Profilerで実際の電流波形を計測して確認する
