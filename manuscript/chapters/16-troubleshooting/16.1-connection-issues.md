# 接続できない問題

<!-- topic: アドバタイズ設定, UUID不一致, 接続タイムアウト, 電波干渉 -->

---

## チェックリスト: 接続できない場合

```
□ ファームウェアがアドバタイズを開始しているか (シリアルログで確認)
□ bt_le_adv_start() の戻り値をチェックしているか
□ iOS/Android のアプリがスキャン対象のサービスUUIDとファームウェアのUUIDが一致しているか
□ nRF Connect アプリでデバイスが見える状態か
□ Bluetoothが有効か (CBManagerState == .poweredOn)
□ iOS: NSBluetoothAlwaysUsageDescription が Info.plist にあるか
□ Android: BLUETOOTH_SCAN 権限が付与されているか
```

---

## よくある原因1: UUIDの大文字・小文字不一致

```swift
// 問題: 大文字と小文字が混在
let uuid = CBUUID(string: "12345678-1234-5678-1234-56789ABCDEF0")

// ファームウェア側
BT_UUID_128_ENCODE(0x12345678, 0x1234, 0x5678, 0x1234, 0x56789ABCDEF0)
// → 0x56789abcdef0 (小文字) でアドバタイズされる

// 解決: CBUUIDは大文字小文字を無視するが、ログ確認時は統一
// 統一方針: すべて小文字のUUID文字列を使う
let uuid = CBUUID(string: "12345678-1234-5678-1234-56789abcdef0")
```

## よくある原因2: アドバタイズにサービスUUIDが含まれていない

iOSで `scanForPeripherals(withServices:)` でUUIDを指定してスキャンすると、そのUUIDをアドバタイズしているデバイスのみ見つかります。

```c
/* NG: サービスUUIDをアドバタイズデータに含めていない */
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS, BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    /* UUID が抜けている! */
};

/* OK: サービスUUIDを含める */
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS, BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA_BYTES(BT_DATA_UUID128_ALL,
        BT_UUID_128_ENCODE(0x12345678, 0x1234, 0x5678, 0x1234, 0x56789abcdef0)),
};
```

## よくある原因3: 接続数上限

nRF52840 + Zephyr のデフォルト同時接続数は `CONFIG_BT_MAX_CONN=1` です。すでに別のデバイスが接続済みの場合、新規接続を受け付けません。

```kconfig
# 最大接続数を増やす（複数のセントラルから同時接続）
CONFIG_BT_MAX_CONN=4
```

## よくある原因4: iOS の connect() はタイムアウトしない

iOSの `CBCentralManager.connect(_:options:)` は**タイムアウトしません**。デバイスが通信圏外に移動した場合でも、接続要求はキャンセルされずに永遠に保留されます。これはCore Bluetoothの仕様です。

開発中に「接続ボタンを押したが何も起きない」という症状に遭遇したら、デバイスがアドバタイズしていない、あるいは圏外であるにもかかわらず接続要求がペンディングされたまま放置されている可能性があります。

**接続タイムアウトを自前で実装してください。**

```swift
func connectWithTimeout(_ peripheral: CBPeripheral, timeout: TimeInterval = 10.0) {
    centralManager.connect(peripheral, options: nil)
    
    // 自前のタイムアウト
    DispatchQueue.main.asyncAfter(deadline: .now() + timeout) { [weak self] in
        guard let self = self else { return }
        if peripheral.state != .connected {
            self.centralManager.cancelPeripheralConnection(peripheral)
            print("接続タイムアウト: \(peripheral.name ?? "unknown")")
            // UI にエラーを表示
        }
    }
}
```

> **cancelPeripheralConnection**: ペンディング中の接続をキャンセルします。このメソッドを呼ばないと、圏外のデバイスへの接続試行がアプリの寿命まで残り続けます。バックグラウンドに移行した場合でも保留は有効なため、不要になった接続要求は必ずキャンセルしてください。

## よくある原因5: 電波干渉

2.4GHz帯はWi-Fi・電子レンジ・BLE共用です。チャンネル干渉で接続が不安定になる場合があります。

- Wi-Fiチャンネル1,6,11とBLEチャンネルは重複する領域がある
- 電子レンジ使用中は 2.4GHz 全帯域に広帯域ノイズが乗る
- BLEは **周波数ホッピング**（AFH）で多少回避できるが限界がある

対策:
- 接続中は **距離を近づける**（RSSI -70dBm以上が目安）
- Wi-Fiを5GHz帯に切り替えるだけで干渉が大幅に減る
- `CONFIG_BT_CTLR_TX_PWR_PLUS_4` で送信電力を上げる

## よくある原因6: スキャン対象のUUID指定の振る舞い

`scanForPeripherals(withServices:)` に複数のサービスUUIDを配列で指定した場合、**いずれか1つでも一致すれば**発見イベントが発生します（OR条件）。「すべてのUUIDをアドバタイズしているデバイスのみ発見」ではありません。

```swift
// この指定は「UUIDのAまたはBをアドバタイズしているデバイス」を発見する（OR条件）
centralManager.scanForPeripherals(
    withServices: [serviceUUID_A, serviceUUID_B],
    options: nil
)
```

ただし、アドバタイズデータに含まれるUUIDのみが対象です。接続後にしか存在しないサービスのUUIDを指定しても、そのサービスを基準にデバイスを発見することはできません。

---

**まとめ**

| 症状 | 原因 | 対策 |
|---|---|---|
| デバイスが表示されない | UUIDがアドバタイズに含まれていない | `BT_DATA_UUID128_ALL` を追加 |
| スキャンしても見つからない | 接続数上限 | `CONFIG_BT_MAX_CONN` を増やす |
| 接続が頻繁に失敗する | 電波干渉 | Wi-Fiを5GHzに変更、距離を近づける |
| 接続が永遠に保留 | iOS connect() タイムアウトなし | 自前タイムアウト + cancelPeripheralConnection |
| iOS で `unsupported` 状態 | Info.plist パラメータ不足 | `NSBluetoothAlwaysUsageDescription` を追加 |
