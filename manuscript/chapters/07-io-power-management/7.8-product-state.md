## 7.8 一つの製品として状態遷移を確認する {#sec:ch7-product-state}

最後に、起動から休止までを一つの状態遷移へ戻します。

```text
BOOT
  ├─ IOとセンサーを初期化
  └─ 保存設定を読み出す
        ↓
ADVERTISING
        ↓ 接続
CONNECTED
  ├─ Read／Write／Notify
  ├─ 定期測定
  └─ コマンド処理
        ↓ 切断
ADVERTISINGまたはIDLE
        ↓ 長期休止条件
SYSTEM OFF
        ↓ GPIOで復帰
BOOT
```

確認では、正常経路だけでなく次も試します。

- センサーが初期化できない
- 測定中に設定が変更される
- コマンド処理中に切断される
- Notifyを購読していない
- System OFF直前にイベントが発生する
- 復帰後に保存設定を読めない

第6章で作ったGATTの契約は保ったまま、内部の実装を物理デバイスへ接続できました。第8章では、このファームウェアを運用中に置き換える仕組みを追加します。

### 7.8.1 初期化の順序を決める

起動直後からAdvertisingを始めると、センサー初期化に失敗した製品へクライアントが接続する場合があります。製品として公開できる能力がそろってからAdvertisingを開始します。

```text
reset reasonを取得
  ↓
永続設定を検証
  ↓
GPIOとセンサーを初期化
  ↓
製品内部の初期状態を作る
  ↓
Bluetoothを初期化
  ↓
Advertising開始
```

一部センサーを利用できなくてもBLE経由で診断できる製品なら、縮退状態としてAdvertisingを開始し、FeatureやDevice Eventで能力不足を示します。「全部成功するまで起動しない」以外の選択肢も製品仕様です。

### 7.8.2 状態と所有者を表にする

同じ変数を複数のコールバックから変更しないよう、状態ごとに更新する処理を決めます。

| 状態 | 更新する処理 | 外部への公開 |
|---|---|---|
| LED State | 製品状態Work | Read、Notify |
| Measurement Value | 測定Work | Read、Notify |
| Measurement Interval | 設定適用処理 | Read |
| Command進行状態 | Command Work | Command Response |
| センサー異常 | エラー処理 | Device Event、診断情報 |

: 製品内部状態の更新責任 {#tbl:ch7-state-ownership}

### 7.8.3 電力状態を通信仕様へ反映する

System OFF中はBLE接続もAdvertisingも維持できません。クライアントから見れば、範囲外、電池切れ、System OFFはすべて「見つからない」状態に見える可能性があります。

休止へ入る前に切断理由や予定を通知できるか、利用者が物理操作で復帰できるか、復帰後に同じidentityとして再接続できるかを決めます。省電力状態はマイコン内部だけの実装ではなく、製品の利用方法へ現れます。
