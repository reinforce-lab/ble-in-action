## 7.7 System ON／System OFFと復帰条件を設計する {#sec:ch7-system-power}

nRF52840のSystem ONでは、CPUが停止しても、保持するRAMや有効な周辺機器、タイマー、無線に応じて電力を使います。Bluetooth接続を維持する待機はSystem ONの中で行います。

System OFFでは、SoCの大部分を停止します。GPIOのDETECTなど、対応する復帰源で起床するとリセットから起動します。実行位置をそのまま再開するスリープではありません。

### 7.7.1 製品状態から選ぶ

| 製品状態 | 接続 | 復帰要求 | 選択例 |
|---|---|---|---|
| 接続中 | 維持する | Connection Event | System ONで待機 |
| Advertising待機 | 送信する | Advertising Event | System ONで待機 |
| 長期保管 | 不要 | ボタン、外部信号 | System OFF |

System OFFへ入る前には、Advertisingや接続を終了し、必要な設定を保存し、GPIOの復帰条件を構成します。復帰後はBoot reasonを確認し、通常起動と区別して製品状態を復元します。

### 7.7.2 深い状態ほど復帰コストが増える

低い待機電流だけで選ぶと、起動処理、センサー初期化、再Advertising、再接続に必要な電力と待ち時間を見落とします。短時間ごとにSystem OFFへ入る構成が、System ONで待つ構成より有利とは限りません。

第9章では、待機区間だけでなく、復帰から処理完了までを含む電荷で比較します。
