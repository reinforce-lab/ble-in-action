## 7.3 割り込み、タイマー、Work Queueで処理を分ける {#sec:ch7-workqueue}

BLE Write、GPIO割り込み、タイマー満了は、製品に処理を要求する入口です。入口のコールバックで長い処理を行うと、同じ実行コンテキストを使うほかの処理を遅らせます。

### 7.3.1 入口では事実を保存する

コールバックでは、入力を検査し、必要な情報を保存してWork Queueへ渡します。

```text
ISR／BLE callback
  記録、最低限の検査、Workをsubmit
        ↓
Work handler
  センサー操作、状態遷移、GATT更新
```

第6章のCommand Requestもこの構成でした。GPIOやタイマーを追加しても、同じ原則を使います。

### 7.3.2 Delayable Workで測定周期を作る

```c
static void measurement_work_handler(struct k_work *work);
K_WORK_DELAYABLE_DEFINE(measurement_work, measurement_work_handler);

static void schedule_next_measurement(void)
{
    k_work_reschedule(&measurement_work,
                      K_MSEC(measurement_interval_ms));
}
```

Work handlerでは測定し、GATT Valueを更新してから次回を予約します。

```c
static void measurement_work_handler(struct k_work *work)
{
    int16_t value;
    int err = read_measurement(&value);

    if (err == 0) {
        device_service_set_measurement(value);
    } else {
        device_service_report_sensor_error(err);
    }

    schedule_next_measurement();
}
```

この例の周期は「前回処理が終わってから次回まで」です。厳密な時刻基準で測る必要がある場合は、基準時刻と遅延を記録し、処理時間によるずれを補正します。

### 7.3.3 共有状態を一か所で変更する

BLE Writeとボタン操作が同じLED Stateを変更する場合、複数のコールバックからGPIOを直接操作しません。製品イベントをWork Queueへ集め、一つの状態遷移関数から適用します。

これにより、同時に起きた操作の順序、コマンド処理中の再要求、切断中の状態変化を一か所で決められます。省電力以前に、イベント駆動は製品動作を再現可能にする構成です。
