## 接続管理とコールバック

<!-- topic: 接続コールバックの登録 -->

BLEデバイスがスマートフォンと接続・切断された時にアプリケーションコードに通知が来るよう、コールバックを登録します。NCSでは `bt_conn_cb_register()` または `BT_CONN_CB_DEFINE()` マクロを使います。

```c
/* 接続コールバック構造体 */
static struct bt_conn_cb conn_callbacks = {
    .connected    = on_connected,
    .disconnected = on_disconnected,
};

/* BLEスタック初期化後に登録 */
bt_conn_cb_register(&conn_callbacks);
```

あるいは `BT_CONN_CB_DEFINE` マクロ（NCS推奨）を使います。

```c
BT_CONN_CB_DEFINE(conn_callbacks) = {
    .connected    = on_connected,
    .disconnected = on_disconnected,
};
```

## connected / disconnected コールバックの実装

<!-- topic: LED制御とアドバタイジング再開 -->

```c
#include <zephyr/bluetooth/conn.h>
#include <dk_buttons_and_leds.h>

/* 接続ハンドルを保持（NULL = 未接続） */
static struct bt_conn *current_conn;

static void on_connected(struct bt_conn *conn, uint8_t err)
{
    if (err) {
        LOG_ERR("Connection failed (err %u)", err);
        return;
    }

    LOG_INF("Connected");
    current_conn = bt_conn_ref(conn);   /* 参照カウントを増やして保持 */

    /* 接続中はLED1点灯 */
    dk_set_led_on(DK_LED1);

    /* 接続中はアドバタイジング停止（省電力） */
    bt_le_adv_stop();

    /* センサー定期送信タイマーを開始 */
    start_sensor_timer();
}

static void on_disconnected(struct bt_conn *conn, uint8_t reason)
{
    LOG_INF("Disconnected (reason %u)", reason);

    /* 保持していた接続ハンドルを解放 */
    if (current_conn) {
        bt_conn_unref(current_conn);
        current_conn = NULL;
    }

    /* 切断時はLED消灯 */
    dk_set_led_off(DK_LED1);

    /* アドバタイジングを再開 */
    int adv_err = bt_le_adv_start(BT_LE_ADV_CONN,
                                   ad, ARRAY_SIZE(ad),
                                   sd, ARRAY_SIZE(sd));
    if (adv_err) {
        LOG_ERR("Advertising restart failed (err %d)", adv_err);
    } else {
        LOG_INF("Advertising restarted");
    }
}
```

`bt_conn_ref()` / `bt_conn_unref()` は接続オブジェクトの参照カウントを管理します。`bt_conn_ref()` なしに接続オブジェクトを保持すると、NCSが内部で解放した後にダングリングポインタになるため、必ず `bt_conn_ref()` でカウントを増やしてから保持します。

## 接続パラメータの取得と変更要求

<!-- topic: connection parameters -->

BLEの接続パラメータ（interval / latency / timeout）は接続後に確認・変更できます。

```c
static void on_connected(struct bt_conn *conn, uint8_t err)
{
    /* ... 省略 ... */

    /* 現在の接続パラメータを取得 */
    struct bt_conn_info info;
    bt_conn_get_info(conn, &info);

    if (info.type == BT_CONN_TYPE_LE) {
        LOG_INF("Conn interval: %u * 1.25ms = %.2fms",
                info.le.interval,
                info.le.interval * 1.25f);
        LOG_INF("Conn latency: %u", info.le.latency);
        LOG_INF("Conn timeout: %u * 10ms = %ums",
                info.le.timeout,
                info.le.timeout * 10);
    }

    /* 接続パラメータの変更要求（スマートフォンが承認すれば変更される） */
    const struct bt_le_conn_param param = {
        .interval_min = 24,   /* 30ms */
        .interval_max = 40,   /* 50ms */
        .latency      = 0,
        .timeout      = 400,  /* 4秒 */
    };
    bt_conn_le_param_update(conn, &param);
}
```

接続パラメータはペリフェラルが「希望」を提示しますが、セントラル（スマートフォン）が最終的に承認します。iOSの場合、Appleのガイドラインにより最小間隔15msに制限されています。

## 最大接続数の設定

<!-- topic: CONFIG_BT_MAX_CONN -->

デフォルトでは1つの接続のみ受け付けます。複数のセントラルから同時接続を受け付けるには `prj.conf` で設定します。

```kconfig
CONFIG_BT_MAX_CONN=3  # 最大3接続
```

ただし接続数を増やすとRAM使用量が増加します。`west build` のリンカーサマリーでSRAM使用量を確認してください。
