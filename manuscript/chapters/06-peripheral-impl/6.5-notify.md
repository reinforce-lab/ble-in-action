## Notifyの実装とCCCD管理

<!-- topic: Notify の仕組み -->

GATTのNotify（ノーティフィケーション）は、サーバ側が能動的にデータをクライアントへ送る機能です。センサーデータの定期送信、ボタン状態変化の通知など、クライアントがポーリングしなくてもリアルタイムに変化を検知できます。

Notifyには確認応答（Acknowledgment）がありません。確認応答ありの場合は Indicate（インディケーション）を使います。

```
Notify（確認なし）:        Indicate（確認あり）:
Device → Phone           Device → Phone
  notification              indication
                             ← confirmation
```

## BT_GATT_CCC によるCCCDの追加

<!-- topic: CCCD の定義 -->

クライアントはNotifyを受け取るかどうかを **CCCD（Client Characteristic Configuration Descriptor）** で制御します。ATT層では `0x0001`（Notify有効）または `0x0000`（Notify無効）を書き込む操作です。

NCSでは `BT_GATT_CCC` マクロで自動的にCCCDアトリビュートを追加できます。CCCDは必ずNotifyキャラクタリスティックの直後に配置します。

```c
/* CCCD変更コールバック */
static bool notify_enabled = false;

static void sensor_ccc_changed(const struct bt_gatt_attr *attr, uint16_t value)
{
    notify_enabled = (value == BT_GATT_CCC_NOTIFY);
    LOG_INF("Notify %s", notify_enabled ? "enabled" : "disabled");
}

/* サービス定義（6.2節の続き） */
BT_GATT_SERVICE_DEFINE(my_svc,
    BT_GATT_PRIMARY_SERVICE(MY_SERVICE_UUID),

    /* センサーキャラクタリスティック（Read + Notify） */
    BT_GATT_CHARACTERISTIC(MY_SENSOR_CHRC_UUID,
                           BT_GATT_CHRC_READ | BT_GATT_CHRC_NOTIFY,
                           BT_GATT_PERM_READ,
                           read_sensor, NULL, &sensor_val),
    /* CCCDはキャラクタリスティックの直後に置く */
    BT_GATT_CCC(sensor_ccc_changed,
                BT_GATT_PERM_READ | BT_GATT_PERM_WRITE),
);
```

## bt_gatt_notify() による送信

<!-- topic: notify 送信の実装 -->

`bt_gatt_notify()` でNotifyを送信します。送信するキャラクタリスティックのアトリビュートを渡す必要があります。

```c
/* アトリビュートを参照するためのヘルパーマクロ */
/* BT_GATT_SERVICE_DEFINE の第1引数名(my_svc)と
   キャラクタリスティックのインデックス(1)を指定 */
#define SENSOR_CHRC_ATTR (&my_svc.attrs[1])

/* センサー値を更新してNotifyを送る */
void notify_sensor_value(uint16_t new_value)
{
    sensor_val = new_value;

    if (!notify_enabled) {
        return;  /* クライアントがNotifyを有効にしていない場合はスキップ */
    }

    int err = bt_gatt_notify(NULL,               /* NULL = 全接続に送信 */
                             SENSOR_CHRC_ATTR,   /* 対象アトリビュート */
                             &sensor_val,         /* 送信データ */
                             sizeof(sensor_val)); /* データ長 */
    if (err) {
        LOG_ERR("Notify failed (err %d)", err);
    }
}
```

`bt_gatt_notify()` の第1引数に `NULL` を渡すと、接続中のすべてのクライアントに送ります。特定の接続にのみ送る場合は `struct bt_conn *` を指定します。

## 定期的なNotifyの実装

<!-- topic: k_timer を使った定期送信 -->

センサーデータを1秒ごとに送るには、Zephyrの `k_timer` または `k_work` を使います。

```c
#include <zephyr/kernel.h>

/* タイマーコールバック（ISRコンテキスト）→ work キューに委譲 */
static void sensor_work_handler(struct k_work *work);
static K_WORK_DEFINE(sensor_work, sensor_work_handler);

static void sensor_timer_handler(struct k_timer *dummy)
{
    /* ISRコンテキストではbt_gatt_notify()を直接呼べないため
       work キューに投げる */
    k_work_submit(&sensor_work);
}
static K_TIMER_DEFINE(sensor_timer, sensor_timer_handler, NULL);

static void sensor_work_handler(struct k_work *work)
{
    /* センサー値を読んで、Notifyを送る */
    uint16_t new_val = read_sensor_hw();   /* センサードライバを呼ぶ */
    notify_sensor_value(new_val);
}

/* タイマー開始（BLE接続後に呼ぶ） */
void start_sensor_timer(void)
{
    k_timer_start(&sensor_timer,
                  K_SECONDS(1),   /* 初回待ち時間 */
                  K_SECONDS(1));  /* 繰り返し間隔 */
}
```

`k_timer_handler` はISR（割り込みサービスルーチン）コンテキストで実行されるため、多くのZephyrAPIは呼び出せません。`k_work_submit()` でシステムワークキューに投げることで、スレッドコンテキストで実行します。
