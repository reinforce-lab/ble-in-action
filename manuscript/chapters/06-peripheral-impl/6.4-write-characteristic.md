## Writeキャラクタリスティックの実装

<!-- topic: Write callbackのシグネチャ -->

クライアントが `Write Request` または `Write Command` を送るとWriteコールバックが呼ばれます。コールバックの役割は `buf` のデータを検証・適用し、書き込んだバイト数（または負のエラーコード）を返すことです。

```c
static ssize_t write_callback(struct bt_conn *conn,
                              const struct bt_gatt_attr *attr,
                              const void *buf, uint16_t len,
                              uint16_t offset, uint8_t flags);
```

| 引数 | 意味 |
|---|---|
| `conn` | 書き込み元の接続オブジェクト |
| `attr` | ATTアトリビュート |
| `buf` | 書き込みデータへのポインタ |
| `len` | 書き込みデータのバイト数 |
| `offset` | 書き込み先オフセット（Prepare Write 用） |
| `flags` | `BT_GATT_WRITE_FLAG_PREPARE` or `0` |


## Write flagsの意味

<!-- topic: PREPARE / EXECUTE パターン -->

| フラグ | 意味 |
|---|---|
| `0` (フラグなし) | 通常のWrite Request（即時適用） |
| `BT_GATT_WRITE_FLAG_PREPARE` | Prepare Write Request（キューに書き込み） |
| `BT_GATT_WRITE_FLAG_EXECUTE` | Execute Write Request（キューを実行） |
| `BT_GATT_WRITE_FLAG_CMD` | Write Command（レスポンスなし） |

ほとんどの場合は `flags == 0` の通常Writeのみ対応すれば十分です。`BT_GATT_WRITE_FLAG_PREPARE` が来た場合はデータを一時保存し、`BT_GATT_WRITE_FLAG_EXECUTE` が来たタイミングで適用します（長大なデータや原子的書き込みが必要なケースで使います）。


## 基本的なWriteコールバックの実装

<!-- topic: 長さ検証と適用 -->

```c
/* LED制御値（0 = OFF, 1 = ON） */
static uint8_t led_state = 0;

static ssize_t write_led_ctrl(struct bt_conn *conn,
                              const struct bt_gatt_attr *attr,
                              const void *buf, uint16_t len,
                              uint16_t offset, uint8_t flags)
{
    /* Prepare Write には対応しない */
    if (flags & BT_GATT_WRITE_FLAG_PREPARE) {
        return 0;
    }

    /* オフセット検証 */
    if (offset != 0) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_OFFSET);
    }

    /* 長さ検証 */
    if (len != sizeof(led_state)) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_ATTRIBUTE_LEN);
    }

    /* 値の適用 */
    memcpy(&led_state, buf, sizeof(led_state));

    /* LED を実際に制御（BSPのAPIを使用） */
    if (led_state) {
        dk_set_led_on(DK_LED1);
    } else {
        dk_set_led_off(DK_LED1);
    }

    return len;
}
```

エラーコードには `BT_ATT_ERR_*` 定数を使います。クライアントにはATTエラーレスポンスとして返ります。


## 複数フィールドを持つ設定値の書き込み

<!-- topic: struct による複数値の書き込み -->

複数の設定値をまとめて書き込む場合、C構造体でペイロード形式を定義します。

```c
/* 設定値構造体 */
struct app_config {
    uint16_t interval_ms;   /* センサー取得間隔（ミリ秒） */
    uint8_t  threshold;     /* 通知閾値 */
} __packed;

static struct app_config config = {
    .interval_ms = 1000,
    .threshold   = 10,
};

static ssize_t write_config(struct bt_conn *conn,
                            const struct bt_gatt_attr *attr,
                            const void *buf, uint16_t len,
                            uint16_t offset, uint8_t flags)
{
    if (flags & BT_GATT_WRITE_FLAG_PREPARE) {
        return 0;
    }
    if (offset != 0 || len != sizeof(config)) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_ATTRIBUTE_LEN);
    }

    memcpy(&config, buf, sizeof(config));
    LOG_INF("Config updated: interval=%u ms, threshold=%u",
            config.interval_ms, config.threshold);
    return len;
}
```

`__packed` 属性はパディングを禁止し、ネットワーク送受信の構造体に使います。
