## Readキャラクタリスティックの実装

<!-- topic: Read callbackのシグネチャ -->

GATTのReadキャラクタリスティックに対して、クライアントが `Read Request` を送ると、NCSがReadコールバックを呼び出します。コールバックの役割は、要求されたデータを `buf` に書き込み、書き込んだバイト数を返すことです。

```c
static ssize_t read_callback(struct bt_conn *conn,
                             const struct bt_gatt_attr *attr,
                             void *buf, uint16_t len, uint16_t offset);
```

| 引数 | 意味 |
|---|---|
| `conn` | 要求元の接続オブジェクト |
| `attr` | ATTアトリビュート（`attr->user_data` でユーザーデータ取得） |
| `buf` | 書き込み先バッファ（NCS側が確保） |
| `len` | バッファの最大長 |
| `offset` | 読み出し開始オフセット（Read Blob Request 対応） |


## bt_gatt_attr_read() ヘルパー

<!-- topic: ヘルパー関数の活用 -->

ほとんどの場合、`bt_gatt_attr_read()` ヘルパーを使うことで `offset` 処理や境界チェックを自動化できます。

```c
static ssize_t read_sensor_value(struct bt_conn *conn,
                                 const struct bt_gatt_attr *attr,
                                 void *buf, uint16_t len, uint16_t offset)
{
    /* attr->user_data = &sensor_val（BT_GATT_CHARACTERISTIC で指定したポインタ） */
    const uint16_t *value = attr->user_data;

    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             value, sizeof(*value));
}
```

`bt_gatt_attr_read()` は:
1. `offset` が値の長さを超えていないかチェック
2. `buf` に `offset` 以降のデータをコピー
3. コピーしたバイト数を返す

バイト数がATT_MTU（デフォルト23バイト、最大メッセージ長）に収まるかどうかもNCS内部で処理されます。


## センサー値の動的更新とRead

<!-- topic: 実際のセンサー値を返すパターン -->

温度センサーの値を毎回最新値で返すサンプルです。

```c
/* 温度値（× 100で整数化: 2350 → 23.50℃） */
static int16_t temperature_centidegrees = 0;

/* 温度センサーを読んで値を更新する（センサードライバや割り込みから呼ぶ） */
void update_temperature(int16_t value)
{
    temperature_centidegrees = value;
}

/* Read callback */
static ssize_t read_temperature(struct bt_conn *conn,
                                const struct bt_gatt_attr *attr,
                                void *buf, uint16_t len, uint16_t offset)
{
    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             &temperature_centidegrees,
                             sizeof(temperature_centidegrees));
}
```

スマートフォンがこのキャラクタリスティックを読むと、常に最新の `temperature_centidegrees` が返ります。値がリトルエンディアンで送られることに注意してください（BLEは原則リトルエンディアン）。


## バッテリーレベルの実装例

<!-- topic: 標準プロファイルの利用 -->

バッテリーレベルはBluetooth SIGの **Battery Service** が定義しています。NCS では `CONFIG_BT_BAS=y` で有効化するだけで、Battery Level キャラクタリスティックが自動的に追加されます。

```kconfig
# prj.conf
CONFIG_BT_BAS=y
```

```c
/* main.c または battery.c */
#include <zephyr/bluetooth/services/bas.h>

/* バッテリーレベルを更新（0〜100） */
bt_bas_set_battery_level(85);
```

`bt_bas_set_battery_level()` を呼ぶと、次回クライアントが Battery Level を読んだときに最新値が返ります。BASはNotifyも内蔵しているため、後述の Notify 実装を自分で書く必要がありません。
