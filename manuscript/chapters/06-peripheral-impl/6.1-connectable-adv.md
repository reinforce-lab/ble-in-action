## 6.1 接続可能アドバタイジング

<!-- topic: 接続可能アドバタイジングへの変更 -->

第5章のHello World では `BT_LE_ADV_NCONN`（接続不可）を使っていました。スマートフォンからの接続を受け付けるには `BT_LE_ADV_CONN`（接続可能）に変更します。

```c
/* 接続可能アドバタイジング */
err = bt_le_adv_start(BT_LE_ADV_CONN,
                      ad, ARRAY_SIZE(ad),
                      sd, ARRAY_SIZE(sd));
```

`BT_LE_ADV_CONN` は `BT_LE_ADV_CONN_FAST_1` などの省略形で、アドバタイジング間隔・タイプ・フィルタポリシーをまとめたパラメータセットです。

## アドバタイジング間隔の設定

<!-- topic: 間隔とトレードオフ -->

アドバタイジング間隔は接続のしやすさと消費電力のトレードオフです。

| 定数 | 間隔 | 用途 |
|---|---|---|
| `BT_LE_ADV_CONN_FAST_1` | 30–60ms | 初期接続時（素早い発見） |
| `BT_LE_ADV_CONN_FAST_2` | 100–150ms | 通常使用 |
| `BT_LE_ADV_CONN` | 100–150ms | `CONN_FAST_2` の別名 |
| 低消費電力カスタム | 1000–10000ms | 電池駆動・バックグラウンド待機 |

間隔を細かく制御する場合は `bt_le_adv_param` 構造体を使います。

```c
static const struct bt_le_adv_param adv_param = {
    .options     = BT_LE_ADV_OPT_CONNECTABLE,
    .interval_min = BT_GAP_ADV_FAST_INT_MIN_2,   /* 100ms */
    .interval_max = BT_GAP_ADV_FAST_INT_MAX_2,   /* 150ms */
};

err = bt_le_adv_start(&adv_param, ad, ARRAY_SIZE(ad), sd, ARRAY_SIZE(sd));
```

## Advertisement Data と Scan Response Data の使い分け

<!-- topic: AD と SD の2つのペイロード -->

BLEアドバタイジングには2つのペイロードがあります。

```
スキャン側の動作：
1. デバイスが Advertisement Data（AD）を受信
   → RSSI確認、フィルタリング
2. スキャン要求（Scan Request）を送信
3. デバイスが Scan Response Data（SD）を返す
   → 追加情報を受信
```

- **Advertisement Data（AD）**: 31バイト。常に送信されます。Flags・デバイス名・サービスUUIDなど、デバイスを識別する最低限の情報を入れます。
- **Scan Response Data（SD）**: 31バイト。スキャン要求を受けた時のみ送信されます。完全なデバイス名・メーカー固有データなど补足情報に使います。

```c
/* Advertisement Data */
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  (BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR)),
    /* 16-bit サービスUUID（省略形）をアドバタイズ */
    BT_DATA_BYTES(BT_DATA_UUID16_ALL,
                  BT_UUID_16_ENCODE(BT_UUID_DIS_VAL)),
};

/* Scan Response Data */
static const struct bt_data sd[] = {
    /* 完全なデバイス名 */
    BT_DATA(BT_DATA_NAME_COMPLETE,
            CONFIG_BT_DEVICE_NAME,
            sizeof(CONFIG_BT_DEVICE_NAME) - 1),
};
```
