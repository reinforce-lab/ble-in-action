## 5.3 nRF52840 DKのボード接続とデバッガ操作

<!-- topic: ボード構成の説明 -->

nRF52840 DK（Development Kit、型番 PCA10056）は、nRF52840 SoCが搭載された公式開発ボードです。実際のプロダクトに比べてSoCの全機能にアクセスしやすいレイアウトになっており、開発の初期段階では最適な選択です。

```
nRF52840 DK（PCA10056）の主要部品配置

 ┌────────────────────────────────────────────────────────┐
 │  [USB J-Link]  [USB nRF]    Arduino互換ピンヘッダ       │
 │      │              │                                   │
 │  J-Link OB ←→ nRF52840 SoC ←→ アンテナ（PCBパターン）│
 │  （JTAGデバッガ）    │                                   │
 │                  ボタン × 4  LED × 4                   │
 │                  Arduino互換ピンヘッダ                  │
 └────────────────────────────────────────────────────────┘
```

**USB J-Linkコネクタ**（ボード左上のUSBポート）: オンボードJ-Linkデバッガ用。PCとこちらのUSBで接続します。書き込み・デバッグ・RTTログ出力はここ経由です。

**USB nRFコネクタ**（ボード右側のUSBポート）: nRF52840のUSB 2.0に直結するコネクタ。USB CDCやUSB HIDのテストに使います。本章では使いません。

**ボタン（SW1〜SW4）**: サンプルコードでよく使われるボタン入力。`BSP（Board Support Package）`でGPIO番号が割り当て済みです。

**LED（LED1〜LED4）**: 接続ステータスや動作確認に使います。同様にBSPで定義済み。

## J-Link接続の確認

<!-- topic: PC接続後の確認手順 -->

J-LinkのUSBコネクタ（左上のUSB）でDKとPCを接続します。ドライバは nRF Command Line Tools インストール時に自動インストールされます。

接続後、端末で`nrfjprog`コマンドを実行してボードを認識しているか確認します。

```bash
$ nrfjprog --ids
12345678   ← ボードのシリアル番号（9桁の数字）
```

番号が表示されれば接続成功です。複数ボードが接続されている場合は、複数の番号が表示されます。

J-Linkのバージョンも確認しておきます。

```bash
$ JLinkExe -?
SEGGER J-Link Commander V7.xx ...
```

**表示されない場合のチェックポイント**:
1. USBケーブルが「J-Link」側のUSB（左上）に接続されているか
2. nRF Command Line Toolsがインストールされているか（`nrfjprog`コマンドが見つからない場合）
3. Windowsの場合、デバイスマネージャーで「SEGGER J-Link」として認識されているか

## RTT Viewerでのログ確認

<!-- topic: RTT ログ -->

**RTT（Real-Time Transfer）**は、J-Linkが提供するデバッグ用の双方向通信チャネルです。JTAGデバッグ接続を使って、シリアル（UART）ポートなしにリアルタイムでSoCからログを受信できます。

RTTをZephyrで使うには `prj.conf` に以下を追加します（5.4節のサンプルでは設定済みです）。

```kconfig
CONFIG_USE_SEGGER_RTT=y
CONFIG_RTT_CONSOLE=y
CONFIG_UART_CONSOLE=n
```

RTTログを受信するには、nRF Connect for DesktopのSerial Terminal（またはJLinkRTTViewer）を使います。

```
nRF Connect for Desktop → Serial Terminal → RTT → Connect
→ ボードのログが流れ続ける
```

`LOG_INF("Hello BLE\n")` のようにコードに書いたログが、フラッシュ後すぐに確認できます。UARTポートへの配線が不要なため、開発ボードでのデバッグでは積極的に使います。

## west flash と west debug

<!-- topic: フラッシュとデバッグの操作 -->

ビルドが成功したら `west flash` でボードに書き込みます。

```bash
# プロジェクトディレクトリで
$ west build -b nrf52840dk_nrf52840
$ west flash
-- west flash: rebuilding
-- west flash: using runner jlink
...
Flashing nrf52840dk_nrf52840
```

`west flash --recover` は、SoCのセキュリティ設定（Access Port Protection）でフラッシュが保護されている場合に使います。工場出荷直後など初回使用時に必要なことがあります。

デバッグが必要な場合は `west debug` でGDBサーバーを起動し、GDBクライアントから接続します。VS Codeの「nRF Connect」拡張機能を使う場合は、サイドバーの「Debug」ボタンから直接デバッグセッションを開始できます（GDB・OpenOCDの設定を自動生成してくれます）。
