## 最初のBLEプログラム：アドバタイジングを送信する

<!-- topic: ゴール設定 -->

本節のゴールは「スマートフォンからデバイス名 `My BLE Device` が見えること」です。BLEの通信は後の章で詳しく実装しますが、まずアドバタイジングを送信し、デバイスが機能していることを確認します。


## プロジェクトの作成

<!-- topic: nRF Connect for VS Code を使ったサンプル作成 -->

nRF Connect for VS Codeのサイドバーから新しいアプリケーションを作成します。

```
サイドバー「nRF Connect」→ Applications → Create New Application
→ Template: peripheral（BLEペリフェラルのサンプル）
→ Application Name: hello_ble
→ Location: 任意のディレクトリ（例: ~/ncs/apps/hello_ble）
```

`peripheral` サンプルは NCS に付属する最小構成のアドバタイジング実装で、そのままビルドして動作確認できます。本節ではこれをベースに、設定を変えながら仕組みを理解します。


## prj.conf の設定

<!-- topic: Kconfig フラグ -->

`prj.conf` はKconfigフォーマットのビルド設定ファイルです。`CONFIG_*=y` でソースファイルのコンパイル・機能の有効化を制御します。

```kconfig
# prj.conf（hello_ble）
CONFIG_BT=y                        # BLEスタック全体を有効化
CONFIG_BT_PERIPHERAL=y             # ペリフェラルロールを有効化
CONFIG_BT_DEVICE_NAME="My BLE Device"  # アドバタイズするデバイス名
CONFIG_BT_DEVICE_APPEARANCE=0      # Generic Unknown (外観)

# ログ出力（RTT経由）
CONFIG_USE_SEGGER_RTT=y
CONFIG_RTT_CONSOLE=y
CONFIG_UART_CONSOLE=n
CONFIG_LOG=y
CONFIG_BT_LOG_LEVEL_INF=y
```

`CONFIG_BT=y` だけでは、ペリフェラルのアドバタイジング機能は含まれません。`CONFIG_BT_PERIPHERAL=y` を追加することで、`bt_le_adv_start()` などのペリフェラルAPIが使えるようになります。


## main.c の実装

<!-- topic: bt_enable / bt_le_adv_start の2ステップ -->

NCSでのBLE処理は、大きく「BLEスタックの初期化（`bt_enable`）」と「アドバタイジングの開始（`bt_le_adv_start`）」の2ステップに分かれます。

```c
/* src/main.c */
#include <zephyr/kernel.h>
#include <zephyr/bluetooth/bluetooth.h>
#include <zephyr/bluetooth/hci.h>
#include <zephyr/logging/log.h>

LOG_MODULE_REGISTER(main, LOG_LEVEL_INF);

/* アドバタイジングデータ（AD）の定義 */
static const struct bt_data ad[] = {
    /* Flags: LE General Discoverable, BR/EDR Not Supported */
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  (BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR)),
    /* デバイス名: CONFIG_BT_DEVICE_NAME から自動設定 */
    BT_DATA(BT_DATA_NAME_COMPLETE,
            CONFIG_BT_DEVICE_NAME,
            sizeof(CONFIG_BT_DEVICE_NAME) - 1),
};

/* bt_enable() のコールバック関数 */
static void bt_ready(int err)
{
    if (err) {
        LOG_ERR("Bluetooth init failed (err %d)", err);
        return;
    }

    LOG_INF("Bluetooth initialized");

    /* アドバタイジングを開始 */
    err = bt_le_adv_start(BT_LE_ADV_NCONN,     /* non-connectable */
                          ad, ARRAY_SIZE(ad),    /* ADデータ */
                          NULL, 0);              /* SRデータなし */
    if (err) {
        LOG_ERR("Advertising failed to start (err %d)", err);
        return;
    }

    LOG_INF("Advertising started: \"%s\"", CONFIG_BT_DEVICE_NAME);
}

int main(void)
{
    int err;

    LOG_INF("Starting Hello BLE...");

    /* BLEスタックの初期化。完了したら bt_ready() が呼ばれる */
    err = bt_enable(bt_ready);
    if (err) {
        LOG_ERR("bt_enable failed (err %d)", err);
        return 0;
    }

    /* メインループ（ここでは何もしない） */
    while (1) {
        k_sleep(K_SECONDS(1));
    }

    return 0;
}
```


## BT_DATA マクロの説明

<!-- topic: アドバタイジングペイロードの構造 -->

`BT_DATA` マクロはBLEアドバタイジングの「AD Structure」を構築します。AD Structureは「タイプ＋データ」のペアで、1パケット（31バイト）の範囲内に複数詰め込まれます。

```
AD Structure:
┌──────────────────────────────────────┐
│ Length (1B) │ Type (1B) │ Value (nB) │
└──────────────────────────────────────┘

BT_DATA_BYTES(BT_DATA_FLAGS, 0x06)  → Length=2, Type=0x01, Value=0x06
BT_DATA(BT_DATA_NAME_COMPLETE, ...) → Length=1+name長, Type=0x09, Value=名前
```

| マクロ | 用途 |
|---|---|
| `BT_DATA_BYTES(type, ...)` | バイト列を直接指定 |
| `BT_DATA(type, ptr, len)` | ポインタと長さで指定 |
| `BT_DATA_FLAGS` (`0x01`) | タイプ: Flags |
| `BT_DATA_NAME_COMPLETE` (`0x09`) | タイプ: Complete Local Name |
| `BT_DATA_UUID16_ALL` (`0x03`) | タイプ: 16-bit Service UUIDs |


## ビルドとフラッシュ

```bash
# プロジェクトディレクトリで
$ west build -b nrf52840dk_nrf52840
...
[100%] Linking C executable zephyr/zephyr.elf
[100%] Built target zephyr/zephyr.elf

$ west flash
-- west flash: using runner jlink
Flashing nrf52840dk_nrf52840
```

フラッシュ後、nRF Connect for DesktopのSerial Terminal（RTTモード）を開くと以下のようなログが流れます。

```
[00:00:00.321,000] <inf> main: Starting Hello BLE...
[00:00:00.348,000] <inf> main: Bluetooth initialized
[00:00:00.348,000] <inf> main: Advertising started: "My BLE Device"
```


## スマートフォンでの動作確認

<!-- topic: nRF Connect for Mobile での確認 -->

スマートフォンに「nRF Connect for Mobile」アプリをインストールし、スキャンを開始します。

```
nRF Connect for Mobile
→ Scanner（スキャン）
→ デバイス一覧に "My BLE Device" が表示される
→ RSSI値 -XX dBm が示していれば電波を受信中
```

デバイス名が表示されれば成功です。BLE アドバタイジングが正常に動作しています。
