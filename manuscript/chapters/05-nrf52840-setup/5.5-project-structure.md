## 5.5 プロジェクト構成とビルドシステム

<!-- topic: 最小プロジェクト構成 -->

NCS/Zephyrプロジェクトの最小構成は3ファイルです。大規模なアプリケーションでも基本構造は同じで、ここに `boards/` や `include/` などが追加されていく形になります。

```
hello_ble/
├── CMakeLists.txt    ← ビルドターゲットとソースファイルの定義
├── prj.conf          ← Kconfig：機能のON/OFFと設定値
└── src/
    └── main.c        ← アプリケーションコード
```

---

## CMakeLists.txt

<!-- topic: CMakeLists の最小構成 -->

```cmake
# CMakeLists.txt
cmake_minimum_required(VERSION 3.20.0)
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})

project(hello_ble)

target_sources(app PRIVATE src/main.c)
```

`find_package(Zephyr ...)` でZephyrのCMakeシステムを取り込みます。`ZEPHYR_BASE` 環境変数はwestが自動設定します。

複数ソースファイルを追加する場合:

```cmake
target_sources(app PRIVATE
    src/main.c
    src/ble.c
    src/sensor.c
)
```

## prj.conf（Kconfig）

<!-- topic: Kconfig の仕組み -->

`prj.conf` はZephyrのKconfigシステムへの入力ファイルです。`CONFIG_*=y` で依存ソースモジュールのコンパイルが有効化されます。

```kconfig
# 記法
CONFIG_BT=y          # 有効化（ブール）
CONFIG_BT_MAX_CONN=4 # 数値設定
CONFIG_BT_DEVICE_NAME="My BLE Device"  # 文字列設定
# CONFIG_SENSOR=y    # コメントアウト（無効）
```

KconfigはBLEスタックだけでなく、I2C、SPI、センサードライバ、タイマー精度など、ZephyrのほぼすべてのモジュールをON/OFFします。`west build -t menuconfig` でGUIベースの設定ブラウザを起動できます。

```bash
$ west build -t menuconfig   # ncurses GUIでKconfigを操作
$ west build -t guiconfig    # GTK GUIの場合
```

## ビルド成果物のディレクトリ構造

<!-- topic: build/ ディレクトリ -->

`west build` を実行すると `build/` ディレクトリが生成されます。

```
build/
├── zephyr/
│   ├── zephyr.elf    ← デバッグ情報付きELFバイナリ（GDB用）
│   ├── zephyr.hex    ← Intel HEX形式（west flash で書き込む）
│   ├── zephyr.bin    ← バイナリイメージ
│   └── zephyr.map    ← リンカーマップ（メモリ使用量の確認に使う）
├── CMakeCache.txt    ← CMakeキャッシュ（ボード設定など）
└── build.ninja       ← ビルドシステム（Ninja）ファイル
```

メモリ使用量は `.map` ファイルや `west build` の最後に表示されるリンカーサマリーで確認できます。

```
Memory region    Used Size  Region Size  %age Used
      FLASH:       54692 B       1 MB      5.22%
       SRAM:       15432 B     256 KB      5.88%
```

nRF52840はFlash 1MB・SRAM 256KBあるため、BLEスタック全体を含めても十分な余裕があります。

## LOG_INF / LOG_ERR を使ったデバッグ

<!-- topic: Zephyr Logging モジュール -->

Zephyrのロギングモジュールでは、ソースファイルの先頭でモジュールを登録し、各レベルのログを出力します。

```c
/* ファイル先頭でモジュールを登録 */
#include <zephyr/logging/log.h>
LOG_MODULE_REGISTER(my_module, LOG_LEVEL_DBG);

/* 各レベルのログ出力 */
LOG_DBG("デバッグ: value=%d", val);    /* 開発時の詳細ログ */
LOG_INF("情報: connected");            /* 通常の動作ログ */
LOG_WRN("警告: RSSI低下 %d dBm", rssi);
LOG_ERR("エラー: bt_enable failed (err %d)", err);
```

`prj.conf` で出力レベルを制御できます。

```kconfig
CONFIG_LOG=y
CONFIG_BT_LOG_LEVEL_INF=y   # BLEスタックのログをINF以上に
CONFIG_LOG_DEFAULT_LEVEL=3  # 3=INF, 4=DBG
```

RTT経由でリアルタイムに出力されるため、UART配線なしに `LOG_INF` でいつでもデバッグできます。これはZephyr開発の大きな利点のひとつです。
