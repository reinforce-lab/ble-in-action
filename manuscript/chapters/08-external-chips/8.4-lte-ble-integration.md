## LTE + BLE 統合（nRF9160 + nRF52840）

<!-- topic: nRF9160 と nRF52840 の役割分担 -->

Nordic の nRF9160 は LTE-M / NB-IoT 対応の SiP（System in Package）です。単体でも動作しますが、BLE は持っていません。nRF52840 と組み合わせることで、セルラー通信（LTE-M）と BLE 近距離通信を同時に使うデバイスを実現できます。

```
LTE + BLE 統合構成

  クラウド（AWS IoT / nRF Cloud）
       ↕ LTE-M（セルラー）
  ┌──────────────┐
  │  nRF9160     │ ←「空」に繋がる側
  │  LTE-M SiP   │
  └──────┬───────┘
         │ UART（AT コマンド / SMP over UART）
  ┌──────▼───────┐
  │  nRF52840    │ ← 「人」に繋がる側
  │  BLE Stack   │
  └──────┬───────┘
         │ BLE（Bluetooth Low Energy）
  スマートフォン
```

**典型的なデータフロー**:
1. スマートフォンが BLE 経由でコマンドを nRF52840 へ送信
2. nRF52840 が UART 経由で nRF9160 へ転送
3. nRF9160 が LTE-M でクラウドへ送信
4. クラウドからの応答が逆順で戻ってくる

## nRF9160 ↔ nRF52840 の UART 通信

<!-- topic: アプリ間通信の実装 -->

nRF9160 と nRF52840 は UART で接続されており、Nordic 独自の **SMP（Simple Management Protocol）** または **カスタム AT コマンド** でやりとりします。

```c
/* nRF52840 側：UART経由で nRF9160 へコマンド送信 */
#include <zephyr/drivers/uart.h>

static const struct device *uart_dev =
    DEVICE_DT_GET(DT_NODELABEL(uart0));

void send_to_nrf9160(const char *at_cmd)
{
    /* UART に AT コマンドを書き込む */
    for (size_t i = 0; at_cmd[i]; i++) {
        uart_poll_out(uart_dev, at_cmd[i]);
    }
    uart_poll_out(uart_dev, '\r');
    uart_poll_out(uart_dev, '\n');
}

/* 呼び出し例 */
send_to_nrf9160("AT+CEREG?");   /* LTE 登録状態を問い合わせ */
```

## BLE OTA + LTE クラウド更新フロー

<!-- topic: MCUmgr / SMP による DFU フロー -->

Thingy:91 では以下の DFU（ファームウェア更新）フローを使えます。

```
スマートフォン（nRF Connect Device Manager アプリ）
    │  BLE（SMP over BLE）
    ▼
  nRF52840（BLE → UART SMP ブリッジ）
    │  UART（SMP over UART）
    ▼
  nRF9160（ファームウェア更新受信・適用）
```

`CONFIG_MCUMGR=y` と `CONFIG_BT_SMP=y` を有効化することで、nRF52840 が BLE SMP サーバとして機能します。スマートフォンの「nRF Connect Device Manager」アプリから直接 nRF9160 のファームウェアを更新できます（詳細は14章 OTA実装で改めて解説します）。
