# 外部チップ連携の全体像

<!-- topic: 1チップ vs 2チップ構成 -->

BLE デバイスのハードウェア構成は「nRF52840 が単体でアプリケーションも処理する構成」と「nRF52840 は BLE だけを担当して別チップがメイン処理をする構成」の2つに大別されます。

```
構成パターン

パターンA（1チップ）:             パターンB（2チップ）:
┌──────────────────┐            ┌─────────┐    ┌──────────────┐
│  nRF52840        │            │  メインMCU  │ HCI │  nRF52840   │
│  App + BLE Stack│            │  (STM32等) │←──→│  BLE Stack  │
│  CPU + Radio     │            └─────────┘UART └──────────────┘
└──────────────────┘
  ↓ センサー接続（I2C/SPI）
                                パターンC（LTE統合）:
                                ┌──────────┐ UART ┌──────────────┐
                                │ nRF9160  │←──→│  nRF52840   │
                                │ LTE-M/NB │      │  BLE Stack  │
                                └──────────┘      └──────────────┘
```

| 構成 | 向いているケース |
|---|---|
| **1チップ** | コスト・サイズ優先。処理量が少ないセンサー送信デバイス・キー入力デバイスなど |
| **2チップ（HCI）** | 既存のメインMCUにBLEを追加したい。Linuxボードへの組み合わせなど |
| **LTE統合** | フィールドセンサー・資産追跡など、セルラー通信とBLE近距離を両立したい場合 |

## 接続インターフェースの選択基準

<!-- topic: I2C / SPI / UART の使い分け -->

| バス | 配線数 | 最大速度 | 特徴 |
|---|---|---|---|
| **I2C** | 2本（SDA/SCL） | 400kHz〜1MHz | 複数デバイスを1本のバスで接続。低速・短距離 |
| **SPI** | 4本（MOSI/MISO/SCK/CS） | 数十MHz | 高速。デバイスごとにCSが必要。IMU・ディスプレイ向き |
| **UART** | 2本（TX/RX）+ 任意でRTS/CTS | 〜4Mbps | 簡単・距離が出せる。HCI接続・ATコマンドなど |

センサー（温度・湿度・加速度）の多くは I2C または SPI を持ちます。Zephyr はどちらも標準ドライバで対応しています。

## ハードウェア設計の実践的な注意点

<!-- topic: アンテナ・筐体・電源・認証 -->

外部チップ連携の前に、BLEハードウェア設計における実践的な注意点を確認しておきます。

### アンテナの設置位置

nRF52840 DKのような開発ボードは基板上にPCBアンテナが搭載されています。製品設計では、筐体が**電波を通す素材（樹脂など）**であることを確認します。筐体が金属の場合、またはアンテナが電池やモータなどの金属部品で覆われる場合は、ケーブル付きの外付けアンテナを使用し、筐体の外側にアンテナを設置します。アンテナ一体型の無線モジュールと外付けアンテナの両方の構成で電波法認証を取得している無線モジュールがありますから、筐体設計の初期段階で確認しておくべきです。

### BLEモジュールへの電源供給

メインボードがスリープ状態に入ると、周辺回路の電源が落とされてBLEモジュールが動かなくなる場合があります。BLEデバイスは外部からいつでも接続・操作したいものですから、無線通信が必要な間はBLEモジュールに電源が供給され続けることを確認します。BLEモジュール自体のスリープ電流は数μA程度（第7章参照）ですから、電源を供給したままでも電池寿命への影響は微小です。

### 電波法認証とBluetooth SIG製品登録

BLEは電波を送信する技術ですから、自国の電波法に従った認証が必要です。認証取得済みの無線モジュールを使えば、その認証を製品に流用できます。集積回路から無線通信回路を設計する場合は、製品としての電波法認証取得が必要です。試作段階であっても、電波が外部に漏れる環境での動作には電波法の対応が必要です。

また、製品販売時にはBluetooth SIGへの製品登録が必要です。Bluetoothの特許および商標の利用許諾を得るための登録で、無登録のまま販売すると特許および商標の無断使用となります。製品開発が始まった段階で、Bluetooth SIGが認定した専門家（BQC: Bluetooth Qualification Consultant）に相談することをお勧めします。

## Zephyr の Device Tree（DTS）概要

<!-- topic: DTS の基本概念 -->

Zephyr ではハードウェア構成を **Device Tree（DTS）** という設定ファイルで記述し、ドライバがそれを読んでリソースを割り当てます。

```
src/main.c（アプリ）
      ↓  sensor_sample_fetch()
Zephyr ドライバ（bme280_i2c.c）
      ↓  I2C read/write
Device Tree（nrf52840dk_nrf52840.dts）
      ↓  i2c0: i2c@40003000 { ... }
nRF52840 ハードウェア（TWI0ペリフェラル）
```

センサーを追加するには `boards/nrf52840dk_nrf52840.overlay` ファイルに追記します（open-overlay パターン）。

```dts
/* boards/nrf52840dk_nrf52840.overlay */
&i2c0 {
    status = "okay";
    compatible = "nordic,nrf-twim";
    sda-pin = <26>;
    scl-pin = <27>;

    bme280@76 {
        compatible = "bosch,bme280";
        reg = <0x76>;
        label = "BME280";
    };
};
```

overlay ファイルはプロジェクトディレクトリ内に置きます。`west build` 時に自動で読み込まれます。
