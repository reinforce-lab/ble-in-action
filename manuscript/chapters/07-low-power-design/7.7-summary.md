## まとめと第8章への橋渡し {#sec:ch7-summary}

<!-- topic: 章のまとめ -->

[@sec:ch7]では、nRF52840 + NCS のペリフェラルに低消費電力設計を適用しました。


## 達成した最適化の整理

```
消費電力最適化の構造

┌──────────────────────────────────────────────────────┐
│ Kconfig: CONFIG_PM=y                                  │
│  → アイドル時に自動的に System On スリープへ         │
├──────────────────────────────────────────────────────┤
│ アドバタイジング戦略（二段階）                        │
│  Fast（100ms × 30秒）→ Slow（1s × 3分）→ 停止        │
│  接続が来た時点で adv 停止                            │
├──────────────────────────────────────────────────────┤
│ 接続パラメータの交渉（Idle 時）                       │
│  interval=200ms, latency=9 → 実質2秒に1イベント      │
├──────────────────────────────────────────────────────┤
│ 電流測定（PPK2）                                      │
│  → アイドル平均5μA 確認 → CR2032で数年動作可         │
└──────────────────────────────────────────────────────┘
```


## 低消費電力設計チェックリスト

- [ ] `CONFIG_PM=y` を設定し、アイドル時のベースライン電流を確認（1〜5μA 目標）
- [ ] `CONFIG_UART_CONSOLE=n` にしてUARTが常時起動していないか確認
- [ ] アドバタイジング間隔を用途に合わせて設定（長期待機は1000ms以上）
- [ ] 二段階アドバタイジング（Fast→Slow→停止）を実装
- [ ] 接続パラメータ更新要求を `on_connected` から発行
- [ ] PPK2またはデジタルマルチメーターで平均電流を実測
- [ ] バッテリー容量と平均電流から動作時間を推算
- [ ] ( 必要なら ) Battery Service でスマートフォンに残量通知

## 第8章へ：外部チップとの連携

[@sec:ch7]まで、nRF52840 単体のBLEペリフェラル実装を学びました。実際のプロダクトでは、nRF52840だけで処理が完結することは少なく、センサーICやLTEモデムなどの外部チップと連携するケースがほとんどです。

[@sec:ch8]では以下を学びます。

- **SPI/I2C接続のセンサー**（温度センサー・加速度センサー）をZephyrドライバを使って取得し、BLE Notifyで送信する
- **2チップ構成（HCIインターフェース）**: 高性能なメインCPU（例：STM32）と nRF52840 を HCI（UART/SPI）で接続してBLEコントローラとして使うパターン
- **LTE + BLE 統合**: LTEモデムチップ（nRF9160）と nRF52840 を組み合わせてセルラー通信とBLE近距離通信を同時使用するパターン
- トラブルシューティング：外部チップ連携でのGPIOレベル・プルアップ・電源シーケンスの落とし穴
