## BlueZ の概要

**BlueZ** はLinuxカーネルで標準的に使われるBluetoothスタックです。Raspberry PiやUbuntu PCのBLEは基本的にBlueZを通じて動作します。

```
┌───────────────────────────────────────────────────────┐
│            アプリケーション (Python / C / Go)           │
├───────────────────────────────────────────────────────┤
│              D-Bus (IPC バス)                          │
├───────────────────────────────────────────────────────┤
│  bluetoothd  ←─ BlueZ デーモン (メインプロセス)         │
├───────────────────────────────────────────────────────┤
│     HCI (Host Controller Interface)                    │
├───────────────────────────────────────────────────────┤
│  Bluetooth コントローラ (USB ドングル / 内蔵モジュール)  │
└───────────────────────────────────────────────────────┘
```

Androidと異なり、BlueZはすでにLinuxカーネルに含まれているため追加インストールは不要です。Raspberry Pi OSでは標準でBlueZが有効です。


## 作業前の確認

```bash
# Bluetoothサービスの状態確認
sudo systemctl status bluetooth

# Bluetoothデバイス一覧
hciconfig -a
# hci0: Type: Primary  Bus: USB
#       BD Address: DC:A6:32:XX:XX:XX

# ドライバが認識されているか
hcitool dev
# Devices:
#         hci0    DC:A6:32:XX:XX:XX
```


## bluetoothctl の基本操作

`bluetoothctl` はインタラクティブなBluetooth管理ツールです。スキャン・接続・ペアリングが行えます。

```
$ sudo bluetoothctl
[bluetooth]# power on          # アダプタの電源ON
[bluetooth]# agent on          # ペアリングエージェント起動
[bluetooth]# scan on           # BLEスキャン開始
[NEW] Device C0:26:DA:XX:XX:XX BLEInAction_Sensor
[bluetooth]# scan off
[bluetooth]# connect C0:26:DA:XX:XX:XX
[BLEInAction_Sensor]# info C0:26:DA:XX:XX:XX
Device C0:26:DA:XX:XX:XX (random)
        Name: BLEInAction_Sensor
        Services:
                00001800-0000-1000-8000-00805f9b34fb (Generic Access)
                12345678-1234-5678-1234-56789abcdef0 (Custom Temp Service)
[BLEInAction_Sensor]# menu gatt
[BLEInAction_Sensor]# list-attributes C0:26:DA:XX:XX:XX
...
[BLEInAction_Sensor]# select-attribute /org/bluez/hci0/dev_.../service.../char...
[BLEInAction_Sensor:/...char...]# read
[BLEInAction_Sensor]# quit
```


## hcitool と gatttool（旧来のコマンド）

`hcitool` と `gatttool` はBlueZ 5.52以降では非推奨ですが、今でも多くの環境にインストールされています。ローレベルなデバッグに便利です。

```bash
# BLEアドバタイズのスキャン
sudo hcitool lescan
# LE Scan ...
# C0:26:DA:XX:XX:XX BLEInAction_Sensor

# アドバタイズデータの取得（raw）
sudo hcitool leinfo --le --bredr C0:26:DA:XX:XX:XX

# gatttool: インタラクティブモード
sudo gatttool -b C0:26:DA:XX:XX:XX -I
> connect
Attempting to connect to C0:26:DA:XX:XX:XX
Connection successful
> primary
attr handle: 0x0001, end grp handle: 0x0007 uuid: 00001800-...
attr handle: 0x0010, end grp handle: 0x001c uuid: 12345678-...

# キャラクタリスティクスの読み出し（ハンドルを指定）
> char-read-hnd 0x0011
Characteristic value/descriptor: 09 01

# Write
> char-write-req 0x0015 1400   # 0x0014 = 20 (閾値20.00°C in little-endian)
```

ハンドル値はサービス発見で得られる属性ハンドルです。プロダクション環境ではUUIDを使う `bluetoothctl` や後述の `bleak` を優先してください。


## Raspberry Pi 4での実装例

Raspberry Pi 4 (Broadcom BCM2711, 内蔵BT 5.0) でのベストプラクティスを示します。

```bash
# 依存パッケージのインストール
sudo apt-get update
sudo apt-get install -y bluetooth bluez bluez-tools

# bluetoothd の設定変更 (experimental features を有効化)
sudo nano /etc/bluetooth/main.conf
# [Policy]
# AutoEnable=true
# [GATT]
# Cache=always   ← サービスキャッシュを有効化

# 再起動
sudo systemctl restart bluetooth
```

BLE操作を非rootユーザーで行うにはユーザーを `bluetooth` グループに追加します。

```bash
sudo usermod -aG bluetooth $USER
# 再ログインが必要
```


## BlueZ のバージョン確認

BlueZ 5.54以降（Raspberry Pi OS Bullseye以降に同梱）では、D-Bus APIが安定しており `bleak` が安定動作します。

```bash
bluetoothd --version
# bluetoothd 5.66
```


**まとめ**

- BlueZはLinuxの標準Bluetoothスタック。D-Bus経由でアプリが操作する
- `bluetoothctl` でスキャン・接続・GATT操作がインタラクティブに行える
- `hcitool` / `gatttool` は非推奨だがデバッグに有用
- Raspberry Pi 4は内蔵BT 5.0でBlueZにより動作する
- プログラムからBLEを使うにはPython bleakライブラリが最も手軽
