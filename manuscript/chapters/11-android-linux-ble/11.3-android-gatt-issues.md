## Read・Write・Notify の実装

### キャラクタリスティクスの読み出し

```kotlin
private fun readTemperature(gatt: BluetoothGatt, service: BluetoothGattService) {
    val tempChar = service.getCharacteristic(
        UUID.fromString("12345678-1234-5678-1234-56789abcdef1")
    )
    if (tempChar != null) {
        gatt.readCharacteristic(tempChar)   // 結果は onCharacteristicRead に来る
    }
}
```

### キャラクタリスティクスへの書き込み

```kotlin
private fun writeThreshold(gatt: BluetoothGatt, service: BluetoothGattService, threshold: Short) {
    val threshChar = service.getCharacteristic(
        UUID.fromString("12345678-1234-5678-1234-56789abcdef3")
    )
    if (threshChar != null) {
        val value = ByteBuffer.allocate(2)
            .order(ByteOrder.LITTLE_ENDIAN)
            .putShort(threshold)
            .array()

        // API 33+: writeCharacteristic(char, value, writeType)
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
            gatt.writeCharacteristic(
                threshChar,
                value,
                BluetoothGattCharacteristic.WRITE_TYPE_DEFAULT
            )
        } else {
            @Suppress("DEPRECATION")
            threshChar.value = value
            gatt.writeCharacteristic(threshChar)
        }
    }
}
```

### Notify の有効化（CCCD書き込み）

iOSと同様に、Notifyを有効にするには**CCCDデスクリプタへの書き込み**が必要です。

```kotlin
private fun enableNotify(gatt: BluetoothGatt, service: BluetoothGattService) {
    val notifyChar = service.getCharacteristic(
        UUID.fromString("12345678-1234-5678-1234-56789abcdef2")
    )
    if (notifyChar == null) return

    // ① ローカルのNotifyを有効化
    gatt.setCharacteristicNotification(notifyChar, true)

    // ② CCCD（Client Characteristic Configuration Descriptor）に書き込み
    val cccdUuid = UUID.fromString("00002902-0000-1000-8000-00805f9b34fb")
    val cccd = notifyChar.getDescriptor(cccdUuid)
    if (cccd != null) {
        val enableValue = BluetoothGattDescriptor.ENABLE_NOTIFICATION_VALUE
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
            gatt.writeDescriptor(cccd, enableValue)
        } else {
            @Suppress("DEPRECATION")
            cccd.value = enableValue
            gatt.writeDescriptor(cccd)
        }
    }
}
```

`setCharacteristicNotification` だけでは**ペリフェラルに通知が届かない**ことに注意してください。CCCDへの書き込みを忘れると、iOSでは機能するがAndroidでは動かないという現象が起きます。

## Android固有の既知問題

AndroidのBLEスタックはLinuxカーネルの BlueZ ではなくQualcommのソフトウェアスタックを基に構築されており、独自の問題が多く知られています。

### 問題1: GATT_ERROR 133

接続直後や操作中に `status=133` (`GATT_ERROR`) が `onConnectionStateChange` で返ることがあります。原因は複数ありますが、最も多いのは**接続直後にGATT操作を急ぎすぎること**です。

```kotlin
override fun onConnectionStateChange(gatt: BluetoothGatt, status: Int, newState: Int) {
    if (status == 133) {
        Log.e("BLE", "GATT_ERROR 133 — 接続を閉じて再試行")
        gatt.close()
        // 少し待ってから再接続
        Handler(Looper.getMainLooper()).postDelayed({ connect(device) }, 1000)
        return
    }
    if (newState == BluetoothProfile.STATE_CONNECTED) {
        // 接続後すぐに discoverServices() を呼ばず少し待つ（workaround）
        Handler(Looper.getMainLooper()).postDelayed({
            gatt.discoverServices()
        }, 600)
    }
}
```

`600ms` の遅延は経験則的なワークアラウンドです。デバイスによって調整が必要な場合があります。

### 問題2: サービスキャッシュが古い

Androidはペリフェラルのサービスをキャッシュします。ファームウェアをアップデートしてサービス構成が変わっても古い情報が使われる場合があります。`refreshDeviceCache()` はリフレクションで呼ぶ非公開APIです。

```kotlin
fun refreshDeviceCache(gatt: BluetoothGatt): Boolean {
    return try {
        val method = gatt.javaClass.getMethod("refresh")
        method.invoke(gatt) as Boolean
    } catch (e: Exception) {
        Log.e("BLE", "キャッシュリフレッシュ失敗: $e")
        false
    }
}

// 接続後・discoverServices前に呼ぶ
override fun onConnectionStateChange(...) {
    if (newState == BluetoothProfile.STATE_CONNECTED) {
        refreshDeviceCache(gatt)
        Handler(Looper.getMainLooper()).postDelayed({ gatt.discoverServices() }, 600)
    }
}
```

### 問題3: Bond（ペアリング）とGATT操作の競合

ペアリング済みデバイスに接続すると、GATT操作中に突然ボンディングダイアログが表示されることがあります。`ACTION_BOND_STATE_CHANGED` ブロードキャストを監視して、Bond完了後にGATT操作を行う方法が安全です。

```kotlin
private val bondReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val state = intent.getIntExtra(BluetoothDevice.EXTRA_BOND_STATE, -1)
        when (state) {
            BluetoothDevice.BOND_BONDED -> {
                Log.d("BLE", "ボンディング完了")
                bluetoothGatt?.discoverServices()
            }
            BluetoothDevice.BOND_NONE -> Log.w("BLE", "ボンディング解除")
        }
    }
}
```

### 問題4: GATT操作はシリアル実行が必要

AndroidのGATTスタックは操作が完了する前に次の操作を受け付けません。`readCharacteristic / writeCharacteristic / writeDescriptor` を連続して呼ぶとリクエストが無視されます。コールバックの受信後に次の操作を行うようにシリアル化します。

```
┌──────────────────────────────────────────────────────┐
│  リクエストキュー（手動実装 or ライブラリで自動化）      │
│                                                      │
│  readΩ → onCharacteristicRead → writeΩ              │
│       ↓ 完了後に次を Dequeue                          │
│  enableNotify → onDescriptorWrite → 完了              │
└──────────────────────────────────────────────────────┘
```

## Coroutineを使ったモダンな実装

NordicのKable・SweetBlue・PolarBLE SDKなどのライブラリはこれらのWorkaroundを隠蔽します。自前で実装する場合は `suspendCoroutine` でコールバックをサスペンド関数に変換するパターンが有効です。

```kotlin
suspend fun readTemperatureAsync(gatt: BluetoothGatt, char: BluetoothGattCharacteristic): ByteArray {
    return suspendCoroutine { cont ->
        val originalRead = object : BluetoothGattCallback() {
            override fun onCharacteristicRead(
                g: BluetoothGatt,
                c: BluetoothGattCharacteristic,
                value: ByteArray,
                status: Int
            ) {
                if (status == BluetoothGatt.GATT_SUCCESS) {
                    cont.resume(value)
                } else {
                    cont.resumeWithException(IOException("Read failed: $status"))
                }
            }
        }
        gatt.readCharacteristic(char)
    }
}

// 呼び出し側
viewModelScope.launch {
    try {
        val data = readTemperatureAsync(gatt, tempChar)
        val celsius = ByteBuffer.wrap(data).order(ByteOrder.LITTLE_ENDIAN).getShort() / 100.0
        _temperature.value = celsius
    } catch (e: IOException) {
        Log.e("BLE", "読み出し失敗: $e")
    }
}
```

**まとめ**

- Notifyには `setCharacteristicNotification` + **CCCD書き込み**の両方が必要
- GATT_ERROR 133 は接続後の遅延挿入で軽減できる
- サービスキャッシュは `refreshDeviceCache()` (リフレクション) で無効化する
- GATT操作は**逐次実行**が原則。コールバック後に次の操作を発行する
- Coroutineを使うとコールバック地獄を回避できる
