## 4プラットフォームの全体比較

本書ではこれまでにiOS (Core Bluetooth)、Web (Web Bluetooth API)、Android (Android BLE API)、Linux (BlueZ + Python bleak) の4つのプラットフォームでBLEアプリを実装してきました。それぞれの特性を整理します。

| 項目 | iOS | Web | Android | Linux/Python |
|---|---|---|---|---|
| **APIフレームワーク** | Core Bluetooth (Swift) | Web Bluetooth API (JS) | android.bluetooth | BlueZ + bleak |
| **言語** | Swift / ObjC | JavaScript / TypeScript | Kotlin / Java | Python |
| **セントラル実装** | CBCentralManager | navigator.bluetooth | BluetoothManager | BleakClient |
| **CCCD書き込み** | 自動 | 自動 | **手動** | 自動 |
| **バックグラウンド動作** | 可（Info.plist必要） | 不可 | 可（Service必要） | 常時可能 |
| **安定性** | 高 | 中（ブラウザ依存） | 中（機種依存多い） | 高 |
| **導入難易度** | 低〜中 | 低（HTTPS/Chrome必要） | 中〜高 | 低（スクリプト） |
| **プロダクション向き** | ◎ | △ | ◎ | ○（ローカル向け） |


## 主要な実装の差異

### スキャン

```
iOS:
  centralManager.scanForPeripherals(withServices: [CBUUID])

Web:
  navigator.bluetooth.requestDevice({ filters: [{ services: [uuid] }] })
  ※ユーザーが手動でデバイスを選択

Android:
  scanner.startScan(filters, settings, callback)

Python bleak:
  await BleakScanner.discover()
```

### Notify の有効化

iOSとbleakはCCCDを自動で書き込みますが、**Androidのみ手動でCCCDを書き込む** 必要があります。

```
# iOS / bleak
self.peripheral.setNotifyValue(true, for: char)   // CCCD自動
await client.start_notify(uuid, callback)          // CCCD自動

# Android: 2ステップ必須
gatt.setCharacteristicNotification(char, true)     // ローカルのみ
gatt.writeDescriptor(cccd, ENABLE_NOTIFICATION_VALUE)  // CCCDをペリフェラルへ
```

### 接続完了〜GATT操作の流れ

```
iOS:       didConnect → discoverServices → didDiscoverServices → ...操作
Web:       gatt.connect → getPrimaryService → getCharacteristic → ...操作
Android:   onConnectionStateChange(CONNECTED) → discoverServices
             → onServicesDiscovered → ...操作
Linux:     async with BleakClient(addr) as client: → client.services → ...操作
```

## 第11章まとめ

本章では以下を学びました。

1. **Android BLEの全体像**: API 18から31への変遷、Android 12+の権限モデル、主要クラス（BluetoothManager, BluetoothLeScanner, BluetoothGatt）
2. **スキャンと接続**: `ScanFilter` によるUUID絞り込み、`connectGatt()` → `BluetoothGattCallback` フロー
3. **GATT操作と既知問題**: CCCDの手動書き込み、GATT_ERROR 133、サービスキャッシュ、操作のシリアル化、Coroutineによる改善
4. **Linux BlueZ**: D-Busアーキテクチャ、`bluetoothctl`、`hcitool`、Raspberry Pi 4での設定
5. **Python bleak**: プラットフォーム非依存のBLEクライアント、スキャン・Read/Write/Notify・温度ロガー実装
