## まとめと第5章への橋渡し {#sec:ch4-summary}

<!-- topic: 本章の振り返り -->

この章では、BLE接続確立後のデータ操作を担う**ATT（Attribute Protocol）**と**GATT（Generic Attribute Profile）**を学びました。

[@sec:ch3]で、レイヤーとデータトランスポートの地図、基本経路を拡張する通信機能を学びました。この章でATTとGATTの内部構造を積み上げたことで、通信能力と製品のデータ設計を結び付けられるようになりました。

| 位置 | 第3章・第4章で得た見方 |
|---|---|
| アプリケーションとプロファイル | 製品の振る舞いと値の契約 |
| GATT | サービス、キャラクタリスティック、ディスクリプター |
| ATT | アトリビュートと操作PDU |
| L2CAP | ATTやSMPを振り分けるチャンネル |
| HCI | HostとControllerの責務の境界 |
| Link Layer | 接続、Advertising、受信確認、暗号化 |
| PHY | ビット列を無線信号として送受信する方法 |
| データトランスポート | physical link、logical transport、logical linkによる通信路の性質 |

: BLEのレイヤーと通信路の全体像 {#tbl:ch4-stack-and-transport-overview}

各節で学んだ内容を振り返ります。

**[@sec:att-gatt-overview]**——ATTとGATTの位置づけを確認しました。クラシックBluetoothから分離されたATTとGATTの設計思想と、HCI境界がControllerとHostの分業（半導体ベンダーとOSベンダー）を可能にしている構造を学びました。

**[@sec:att-structure]**——ATTの最小単位「アトリビュート」の4要素（ハンドル・タイプ・バリュー・パーミッション）と、1パケットで運べるサイズを決めるATT MTUの仕組みを学びました。

**[@sec:att-commands]**——ATTコマンドをRequest/Response、Command、Notification、Indicationの交換パターン別に整理しました。30秒タイムアウトのトランザクションルールと、Notify/Indicateの違いを理解しました。

**[@sec:gatt-hierarchy]**——GATTの4層階層（Profile / Service / Characteristic / Descriptor）を学びました。ATTテーブル上でハンドルの並び順によって区画が表現される仕組みと、Characteristic Propertiesの8ビットフラグの意味を整理しました。

**[@sec:descriptors]**——ディスクリプタの種類、特にCCCDの詳細な動作（ボンディングなし時のリセット、クライアント固有設定）を学びました。

**[@sec:profiles]**——サービスディスカバリのATTシーケンス、標準プロファイルの実例、キャラクタリスティック設計の3分類（センサー値・内部状態・コントロールポイント）を学びました。


## 重要用語一覧

<!-- topic: 用語一覧 -->

| 用語 | 説明 |
|---|---|
| ATT（Attribute Protocol） | ハンドルを指定してアトリビュートを読み書きするプロトコル |
| GATT（Generic Attribute Profile） | ATTを使ったデータ構造（サービス/キャラクタリスティック/ディスクリプタ）の定義 |
| アトリビュート | ATTが操作する最小単位。ハンドル・タイプ・バリュー・パーミッションの4要素 |
| ハンドル（Handle） | アトリビュートを識別する2バイトの番号（0x0001〜0xFFFF） |
| タイプ（Type） | アトリビュートの種類を示すUUID（128ビット、またはSIG標準16ビット） |
| ATT MTU | ATT PDUの最大サイズ（デフォルト23バイト、拡張可能） |
| ATTサーバ | アトリビュートテーブルを保持するデバイス（センサー・デバイス側が多い） |
| ATTクライアント | アトリビュートにアクセスするデバイス（スマートフォン・PC側が多い） |
| Request / Response | クライアント→サーバのトランザクション（1対1、30秒タイムアウト） |
| Notification | サーバ→クライアントへの応答なし通知（高頻度データに適する） |
| Indication | サーバ→クライアントへの確認応答あり通知（高信頼性が必要な場面に適する） |
| Command（Write Command） | クライアント→サーバへの応答なし書き込み |
| Primary Service | 外部に公開するサービス（UUID 0x2800） |
| Secondary Service | 他サービスから参照される共有サービス（UUID 0x2801） |
| Included Service | 別サービスを取り込む仕組み（UUID 0x2802） |
| Characteristic | サービスを構成するデータ単位。Declaration + Value + Descriptor の3アトリビュートの組 |
| Characteristic Declaration | キャラクタリスティックの宣言（UUID 0x2803）。Properties/ValueHandle/UUIDを含む |
| Characteristic Properties | そのキャラクタリスティックができる操作を示す8ビットフラグ |
| Descriptor | Characteristic Valueの補足情報や振る舞い設定を担うアトリビュート |
| CCCD（Client Characteristic Configuration Descriptor） | Notify/Indicateの購読設定。UUID 0x2902。接続ごとにクライアント固有 |
| SCCD（Server Characteristic Configuration Descriptor） | Broadcastの有効/無効設定。UUID 0x2903 |
| サービスディスカバリ | 接続後にATTコマンドでサービス・キャラクタリスティックを探索する手順 |
| HCI（Host Controller Interface） | ControllerとHostの分割境界。USB/UART等で物理的に分離可能 |
| Controller | リンク層・物理層（RF）を実装するハードウェア寄りのブロック |
| Host | L2CAP以上のソフトウェアスタック（ATT・GATT・GAP・SMP） |


## 第5章への橋渡し

<!-- topic: 次章の予告 -->

これまで第1〜4章でBLEの概念・使い方・プロトコルスタック・データ構造を学びました。[@sec:ch5]からはいよいよ実装に移ります。

[@sec:ch5]では**Nordic Semiconductor nRF52840**を使ったファームウェア開発環境のセットアップを行います。nRF Connect SDK（Zephyr RTOSベース）上で開発環境を整え、最初の「Hello World」としてBLEアドバタイジングを送信するところまでを実走します。

[@sec:ch6]では、この章で学んだGATTテーブルを実際にnRF Connect SDK上で実装します。`BT_GATT_SERVICE_DEFINE`マクロでサービスとキャラクタリスティックを定義し、Readコールバック・Writeコールバック・Notifyの送信を実装します。[@sec:profiles]で設計した「懐中電灯サービス」を実際のコードに落とし込みながら、BLEペリフェラルの実装を一通り完成させます。

ATT/GATTの座学はここまでです。次章からは手を動かしていきましょう。
