### 第1章の要点

**1.1 micro:bitで始めるBLE体験**

micro:bitとnRF Connectアプリを使い、BLEの動作フロー——アドバタイジング、デバイスの発見、接続、GATTへのアクセス——を実機で確認しました。BLEは特別な機材も秘密の情報も必要とせず、スマートホンと手頃なデバイスがあれば今すぐ試せます。プロが使うツールと原理は同じです。

**1.2 BLEとは何か**

BLEは2010年のBluetooth 4.0で登場した、Bluetooth Classicとは別のプロトコルスタックです。物理層から設計しなおされ、コイン電池1個で1年以上動き続けることを目的としています。その鍵は、コネクションインターバルの間だけ高周波回路をオフにする間欠動作と、必要最小限の短いパケット通信です。通信は簡単に途切れますが、ミリ秒単位で再接続しGATTキャッシュにより1〜2パケットで復旧するため、ユーザには通信が維持されているように見えます。Bluetooth 5以降も後方互換性を保ちながら、速度・距離・方向検知・オーディオへと進化し続けています。

**1.3 BLEのエコシステム**

ヘルスケア機器、スマートホームデバイス、HID周辺機器、位置情報タグ、LE Audioなど、BLEは日常のさまざまな場面に浸透しています。Bluetooth SIGが標準プロファイルを定義して異なるメーカー間の互換性を保証し、カスタムプロファイルで独自製品を作る自由も両立しています。技術仕様は誰でも無料でダウンロードでき、SDKやフォーラムも公開されていて、囲い込まれた技術ではありません。スマートホンの爆発的な普及が「セントラルが世界中にある」状態を生み出したことが、BLE普及の最大の背景です。

**1.4 BLE開発の進め方と役割分担**

BLE製品の開発には、個人・ホビスト、スタートアップ、既存事業者・企画型、研究発というパターンがあり、それぞれに固有の強みと落とし穴があります。ファームウェア担当・アプリケーション担当・企画PdMは必要なBLE知識の深さが異なります。技術のちょっとした聞き間違いが致命的な問題を引き起こすこともあり、最も多いトラブルは「実際に繋げてみたら仕様の解釈が違っていた」という結合確認の先送りです。早期に繋げて確かめることと、共通言語を持つことがプロジェクトを前進させます。

### 重要用語の整理

| 用語 | 意味 |
|---|---|
| アドバタイジング | ペリフェラルが自分の存在を周囲にブロードキャストすること |
| スキャン | セントラルが周囲のデバイスを探索すること |
| セントラル | 接続を開始する側（スマートホン、PCなど） |
| ペリフェラル | 接続を受け入れる側（センサー、デバイスなど） |
| GATT | データの構造と交換手順を規定するプロフィール基盤 |
| サービス | GATTにおける関連機能のグループ |
| キャラクタリスティック | GATTにおける実際のデータの単位 |
| コネクションインターバル | 接続中に通信パケットを交わす間隔 |
| ペアリング | 暗号化鍵を交換する手続き |
| ボンディング | ペアリングで交わした鍵を記憶し次回接続を省略すること |

### 読者層とこれからの歩み方

本書はさまざまな立場の読者を想定しています。技術は用途を制限しません——BLEの知識は、それを活かす立場の数だけ異なる風景を見せてくれます。自分の立場から、次のステップの見通しを確認してください。

**ホビスト・個人開発者**

1.1節の体験がそのままプロジェクトの出発点です。第2章で接続とGATTの概念を深め、Part 3（ファームウェア編）でnRF52840のSDKを使った実装に進むことで、自作デバイスの完成度が上がります。ファームもアプリも一人で担えることは大きな強みです、その強みを活かして早く動くものを作りましょう。

**ファームウェアエンジニア**

第2章・第3章でアドバタイジングとリンク層の仕組みを押さえ、第4章でGATTの構造を深掘りすることが最初の目標です。自分が実装するGATTが「アプリ側からどう見えるのか」を常に意識することが、連携トラブルを防ぐ基本姿勢です。

**アプリケーションエンジニア（iOS / Android）**

第2章でGATTのRead / Write / Notifyの違いとペアリングの流れを理解することが先決です。ファームウェア担当が定義したGATT仕様書を正確に読む力は、アプリエンジニアにとっての核心スキルです。

**企画・プロダクトマネージャー**

1.4節が特に重要です。「BLEで何ができて何ができないか」の感覚を磨き続けることが、技術担当と円滑に話すための土台になります。第2章のGATTとプロファイルの節を読み、用語の共通認識を持つことをお勧めします。

### 第2章へ

第1章では、BLEの全体像を「広く・浅く」把握しました。第2章「BLEの基本概念と用語」では、ここで登場した概念を「深く・正確に」理解します。

- セントラルとペリフェラルの詳細な役割の違い
- アドバタイジングパケットの中身と種類
- GATTの構造——UUID・サービス・キャラクタリスティック・プロパティ
- 接続パラメータ（コネクションインターバル・スレーブレイテンシ・タイムアウト）の意味と調整

1.1節でnRF Connectを使って眺めたGATTテーブルの「中身」が、第2章で読み解けるようになります。
