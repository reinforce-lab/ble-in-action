## 1.2 BLEとは何か

<!-- topic: 節の導入 — 1.1で体験したBLEが、どのような経緯で生まれたのかを歴史から解き明かす -->

1.1節では、micro:bitとスマートホンをつないでBLEの通信を体験しました。では、そもそもBLEとはどのような技術で、どのような経緯で登場したのでしょうか。この節では、Bluetooth技術の歴史を振り返り、BLEがどのような目的で設計された技術なのかを理解します。

### 歴史：Bluetoothのはじまりとlow energyの登場

無線通信には、通信相手が必要です。デジタル・データを電波でやりとりするためには、お互いが同じ規格に従っている必要があります。ちょうど同じ規格のネジとナットならどのメーカーの組み合わせでも使えるように、無線通信規格は通信を成り立たせるかなめです。

Bluetooth無線技術は、近接無線通信技術として、1999年にその最初の規格Bluetooth 1.0が公開されました。その仕様は通信の高速化などで Bluetooth 2.0、Bluetooth 3.0 と更新されていきました。この時代のBluetoothは今日「Bluetooth Classic」あるいは「Bluetooth BR/EDR（Basic Rate / Enhanced Data Rate）」と呼ばれています。ワイヤレスヘッドセット、PCと周辺機器の接続、ファイル転送、カーナビとスマートホンの連携など、常時接続を前提とした用途で広く使われていました。

2010年に公開されたBluetooth 4.0で、Bluetooth無線技術に初めて取り込まれた新たな技術が、**Bluetooth Low Energy（BLE）**です。BLEはBluetooth Classicの改良版ではなく、物理層やリンク層から設計しなおした、**まったく新しいプロトコルスタック**として設計されました。

Bluetooth 4.0の登場当初は、少し困ったことが起きました。Bluetooth 3.0以前の機器にはBLEがないため、Classicのスマートホンでは BLEアクセサリが使えません。そこで2011年に「Bluetooth SMART READY」と「Bluetooth SMART」という2つのロゴマークが発表されました。ClassicとBLEの両方を持つスマートホンなどには「SMART READY」を、BLEのみを搭載するアクセサリには「SMART」を付けて区別したのです。この2つのロゴマークは、5年後の2016年に廃止されました。続々と発売されるスマートホンがBluetooth 4.0を採用したことで、Classicのみの機器の割合が急激に減少し、区別する必要がなくなったからです。

Bluetooth 4.0以降のBluetooth規格には後方互換性があります。4.0を基本としつつ、通信の高速化・距離の長大化・方向検知・オーディオなど数々の技術が盛り込まれ、進化し続けています。

### Bluetooth ClassicとBLEの比較

Bluetooth ClassicとBLEは、同じ「Bluetooth」という名前を持ちながら、設計の目的がまったく異なります。

Bluetooth Classicは、携帯電話とヘッドセットのように常時接続が前提のケーブル置き換えを目指して設計されました。最大3 Mbpsの比較的高いデータレートを持ち、音声やオーディオのストリーミングに適しています。一方で、常時接続は消費電力が大きくなります。

BLEは、コイン型のボタン電池1つで数ヶ月〜1年動作し続けることを目標に設計されました。センサー値や状態通知といった少量のデータを、必要なときだけ短時間で送受信する間欠通信を前提としています。用途の違いから、技術の中身も根本的に異なります。

| | Bluetooth Classic | BLE |
|---|---|---|
| 登場 | 1999年（Bluetooth 1.0） | 2010年（Bluetooth 4.0） |
| データレート | 最大3 Mbps | 1〜2 Mbps（実効速度は低い） |
| 接続モデル | 常時接続を前提 | 間欠通信（必要時のみ接続） |
| 消費電力 | 比較的大きい（数十〜数百 mA） | 超低消費電力（平均10〜50 μA程度） |
| 主な用途 | ヘッドセット、音声通話、ファイル転送 | センサー、ウェアラブル、ビーコン |
| データ交換 | 用途ごとに異なるプロファイル群 | GATT基盤で統一 |

Bluetooth 4.0以降のチップは、用途に応じて2つの構成があります。BLEのみをサポートする**Single-mode**は低コストで消費電力が小さく、センサー機器やビーコン用途に向きます。ClassicとBLEの両方をサポートする**Dual-mode**はスマートホンやPCによく使われ、どちらのデバイスとも組み合わせられます。

### 低消費電力を実現する仕組み

BLEが「Low Energy」と呼ばれる理由は、無線通信回路をオンにする時間を可能な限り短くする、というシンプルな原則にあります。

**間欠動作（スリープ）**

BLEデバイスは、常に電波を送受信しているわけではありません。通信が不要な時間は電子回路をスリープ状態にして電力を節約し、決められたタイミングでだけウェイクアップして通信します。例えば温度センサーであれば、動作時間の99%以上をスリープに費やし、通信は0.1%以下の時間しか行わないケースもあります。

**短時間パケット通信**

BLEの通信は一度に数ミリ秒〜数百マイクロ秒で完了します。接続の確立も数ミリ秒、1パケットの送信は数十〜数百マイクロ秒と非常に速く、通信回路をオンにしている時間そのものを短くしています。

**小さなパケット**

BLEのパケットサイズは小さく設計されています。センサー値など少量のデータを伝えるには十分で、送信時間が短くなります。

**アドバタイジングモード（接続なしで情報発信）**

BLEには、接続を確立せずに情報を発信する「アドバタイジング」という動作モードがあります。ビーコンなどのデバイスは広告パケットを一定周期で発信するだけで、接続を確立しません。この方式では複数のスマートホンが同時に受信できる上に、発信側の消費電力を極めて低く抑えられます。

**接続インターバルの広い設定幅**

接続状態での通信周期（接続インターバル）は、7.5ミリ秒から4秒近くまで設定できます。キーボードやゲームコントローラのような応答速度が求められるものはミリ秒単位の短い間隔を、室温センサーのようにゆっくり変化するものは秒単位の長い間隔を選びます。用途に合った消費電力と遅延のバランスを取れるのです。

このような工夫の積み重ねで、直径20 mm・厚さ3.2 mmのコイン型電池（CR2032、容量220 mAh）1つで、1秒間隔の広告送信であれば2〜3年間動作します。

### なぜBLEが選ばれるのか

センサーやウェアラブルデバイスに使える無線通信技術はいくつかあります。Wi-FiはBLEより高速ですが消費電力が桁違いに大きく、コイン電池で動かすことはほぼ不可能です。ZigBeeはBLEに近い低消費電力ですが、通信相手となるゲートウェイが別途必要です。BLEが選ばれる理由は、大きく4つあります。

**コイン電池で長期動作できる**

BLEはボタン型電池1つで半年〜1年以上の動作が可能です。毎日充電は不要で、電池交換の頻度も少なくてすみます。これが、フィットネス機器・医療機器・環境センサーなど、電源確保が難しいデバイスで採用される最大の理由です。

**スマートホンという巨大なエコシステムが通信相手になる**

2011年のiPhone 4S以降、Bluetooth 4.0に対応したスマートホンが普及しました。現在出荷されるほぼすべてのiPhoneとAndroid端末がBLEの「セントラル」として動作します。つまり追加のハードウェアなしに、手元のスマートホンがアクセサリの通信相手になるのです。普及したスマートホンがセントラルになれることが、BLEを一気に普及させた最大の原動力でした。

**小型化・低コストに向いている**

センサーや小型デバイスに組み込む無線通信チップは安価でなければなりません。BLEチップはパッケージが数ミリ角程度のものも存在し、部品単価も低価格です。電池も小さくできるため、製品全体をコンパクトに設計できます。

**GATTによる標準プロファイルで互換性を確保できる**

BLEはGATT（Generic Attribute Profile）という共通基盤の上にデータ交換の仕組みを構築しています。さらにBluetooth SIGは、心拍センサー・体温計・血圧計・電池残量サービスなど多くの標準プロファイルを定義・公開しています。標準プロファイルに準拠していれば、特定のアプリを使わなくても、多くのフィットネスアプリや汎用ツールと即座に動作します。

### BLEの進化：Bluetooth 4.0〜5.4

BLEは登場以来、用途の拡大と技術的な改善を重ねてきました。以下に主要バージョンの変更点をまとめます。

| バージョン | 年 | 主な変更内容 |
|---|---|---|
| **4.0** | 2010年 | BLE仕様の初版。GATT基盤・標準プロファイルの整備 |
| **4.1** | 2013年 | 接続性の向上。ペリフェラル同士の通信、LTE共存改善 |
| **4.2** | 2014年 | データパケット拡大（最大251バイト）、プライバシー強化、IPv6対応 |
| **5.0** | 2016年 | 通信距離最大4倍・速度2倍（2 Mbps）・広告データ量8倍 |
| **5.1** | 2019年 | AoA/AoD方向検知機能。屋内位置測位の精度向上 |
| **5.2** | 2020年 | **LE Audio**登場。BLEで高音質オーディオを実現（LC3コーデック） |
| **5.3** | 2021年 | 接続品質・省電力化のさらなる改善 |
| **5.4** | 2023年 | PAwR（広告への応答機能）、電子棚札対応、セキュリティ強化 |

特に注目すべきは2020年のBluetooth 5.2で登場した「LE Audio」です。それまでオーディオのワイヤレス伝送はClassic専用でしたが、BLEでも高音質・低消費電力のオーディオストリーミングが実現しました。今後、ワイヤレスイヤホンやヘッドセットもLE Audioへ移行していくと見られています。Bluetooth技術は、**Classic中心からBLE中心へ**と完全に再定義されつつあります。

なお、BLEを使う際に必要な機能が使えるかどうかは、デバイスのスマートホン機種・OSバージョン・半導体・ソフトウェア開発環境がその機能に対応しているかに依存します。Bluetooth 4.0にはなかった技術要素を使う場合は、事前に対応状況を確認しておくことが重要です。

この節では、Bluetoothの歴史を振り返り、BLEがClassicとは根本的に異なる低消費電力の新技術として2010年に登場したことを見てきました。コイン電池で長期動作できること、スマートホンがセントラルとして機能すること、そしてGATTという共通基盤が互換性を支えていること――これら3つが、BLEが今日広く採用される理由です。

次節では、BLEのデータ交換の仕組みであるGATTをより詳しく見ていきます。サービス、キャラクタリスティク、アドバタイジングといった基本概念を整理することで、実際の開発に必要な基礎が揃います。
