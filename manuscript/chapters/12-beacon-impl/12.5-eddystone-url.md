## Eddystone-URL フレームの構造

Eddystone-URLはBLEのService Data（AD Type: 0x16）にURL情報を格納します。サービスUUIDは `0xFEAA` です。

```
Eddystone-URL フレーム (バイト構成)
┌────────────────────────────────────────────────────────────────┐
│  Frame Type (1B) │ TX Power (1B) │ URL Scheme (1B) │ URL (可変) │
│     0x10         │    0xED       │     0x03        │ "example"  │
└────────────────────────────────────────────────────────────────┘
```

**URL Scheme コード表**

| コード | スキーム |
|---|---|
| 0x00 | `http://www.` |
| 0x01 | `https://www.` |
| 0x02 | `http://` |
| 0x03 | `https://` |

**URL末尾短縮コード表**

| コード | 展開後 |
|---|---|
| 0x00 | `.com/` |
| 0x01 | `.org/` |
| 0x02 | `.edu/` |
| 0x03 | `.net/` |
| 0x04 | `.info/` |
| 0x05 | `.biz/` |
| 0x06 | `.gov/` |
| 0x07 | `.com` |
| 0x08 | `.org` |


## Eddystone-URL アドバタイズデータの作成

例として "https://bleaction.example.com" を送信する場合：

```c
/* Eddystone-URL: "https://bleaction.example.com" */
/* = 0x03 + "bleaction.example" + 0x07 (".com") */

#define EDDYSTONE_SVC_UUID  BT_UUID_16_ENCODE(0xFEAA)

static const uint8_t eddystone_url[] = {
    0x10,                           /* Frame Type: Eddystone-URL */
    0xED,                           /* TX Power: -19 dBm at 1m */
    0x03,                           /* URL Scheme: https:// */
    /* Encoded URL: "bleaction.example" + ".com" コード */
    'b', 'l', 'e', 'a', 'c', 't', 'i', 'o', 'n',
    '.', 'e', 'x', 'a', 'm', 'p', 'l', 'e',
    0x07,                           /* .com */
};

static const struct bt_data ad_eddystone[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS, BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA_BYTES(BT_DATA_UUID16_ALL, EDDYSTONE_SVC_UUID),
    BT_DATA(BT_DATA_SVC_DATA16, eddystone_url, sizeof(eddystone_url)),
};
```

> **制約**: Eddystone-URL の最大ペイロードは17バイト。アドバタイズペイロード合計(31バイト)から固定部分を引いた残りです。長いURLはURL短縮サービスを使います。


## iBeaconとEddystoneの同時送信（インターリーブ）

一部のデバイスでは iBeaconとEddystoneを交互に送信するインターリーブ方式を使います。nRF52840では `bt_le_adv_update_data()` で切り替えるか、アドバタイズセット（Extended Advertising）を使います。

```c
/* 500ms交互切り替えの簡易実装 */
static bool use_ibeacon = true;

while (1) {
    if (use_ibeacon) {
        bt_le_adv_update_data(ad_ibeacon, ARRAY_SIZE(ad_ibeacon), NULL, 0);
    } else {
        bt_le_adv_update_data(ad_eddystone, ARRAY_SIZE(ad_eddystone), NULL, 0);
    }
    use_ibeacon = !use_ibeacon;
    k_msleep(500);
}
```


## Androidでの Eddystone-URL 受信

```kotlin
fun parseEddystoneUrl(result: ScanResult): String? {
    val scanRecord = result.scanRecord ?: return null
    val svcData = scanRecord.getServiceData(
        ParcelUuid.fromString("0000feaa-0000-1000-8000-00805f9b34fb")
    ) ?: return null

    if (svcData.isEmpty() || svcData[0] != 0x10.toByte()) return null   // URL frame check

    val txPower = svcData[1].toInt()   // unused here but useful for distance
    val scheme = when (svcData[2].toInt()) {
        0x00 -> "http://www."
        0x01 -> "https://www."
        0x02 -> "http://"
        0x03 -> "https://"
        else -> return null
    }

    val sb = StringBuilder(scheme)
    for (i in 3 until svcData.size) {
        val b = svcData[i].toInt() and 0xFF
        sb.append(when (b) {
            0x00 -> ".com/"
            0x01 -> ".org/"
            0x07 -> ".com"
            0x08 -> ".org"
            else -> b.toChar()
        })
    }
    return sb.toString()
}
```


## Physical Web (Chrome)

Eddystone-URLはGoogleの **Physical Web** プロジェクト向けに設計されました。物理的な場所に情報URLを紐づける仕組みです。ただし2019年にGoogleはChrome Physical Web機能の提供を終了しました。現在は独自アプリやWeb Bluetooth経由での活用が主流です。


**まとめ**

- Eddystone-URLは `0xFEAA` サービスのService Dataにフレームタイプ0x10+URL
- URL短縮コードで17バイト制限を活用
- nRF52840では `bt_le_adv_update_data()` でiBeaconとのインターリーブが可能
- AndroidはService Data `getServiceData(UUID)` で解析
