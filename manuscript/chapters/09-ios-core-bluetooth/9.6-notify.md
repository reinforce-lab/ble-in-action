# 9.6 Notify の受信

<!-- topic: setNotifyValue, didUpdateValueFor, Notify vs Indicate, CCCD管理 -->

---

## Notifyとは何か

第4章で解説したように、GATTには値変更をセントラルに通知する仕組みとして **Notification** と **Indication** の2種類があります。

| 種類 | 確認応答 | 用途 |
|---|---|---|
| Notification | なし（Fire & Forget）| 高頻度センサーデータ、ログ |
| Indication | あり（確認応答あり）| 重要な状態変化、信頼性が必要なデータ |

Core Bluetoothでは、どちらも `setNotifyValue(_:for:)` で有効化し、`didUpdateValueFor` で受け取ります。アプリ側から2つを区別する方法はほとんどなく、ペリフェラルの仕様に従います。

## Notifyのサブスクリプション

第9.4節でキャラクタリスティクスを発見した後、`setNotifyValue(true, for:)` でNotify（またはIndicate）を有効化します。これは内部的に、ATTのClient Characteristic Configuration Descriptor（CCCD）に `0x0001`（Notification enabled）を書き込む操作です。

```swift
func peripheral(
    _ peripheral: CBPeripheral,
    didDiscoverCharacteristicsFor service: CBService,
    error: Error?
) {
    for characteristic in service.characteristics ?? [] {
        if characteristic.properties.contains(.notify) {
            // Notifyを有効化
            peripheral.setNotifyValue(true, for: characteristic)
            print("Notify有効化: \(characteristic.uuid)")
        }
    }
}
```

サブスクリプションの設定が完了すると `peripheral(_:didUpdateNotificationStateFor:error:)` が呼ばれます。

```swift
func peripheral(
    _ peripheral: CBPeripheral,
    didUpdateNotificationStateFor characteristic: CBCharacteristic,
    error: Error?
) {
    if let error = error {
        print("Notify設定エラー: \(error)")
        return
    }

    if characteristic.isNotifying {
        print("Notify有効: \(characteristic.uuid)")
    } else {
        print("Notify無効化: \(characteristic.uuid)")
    }
}
```

## 通知の受信

Notifyが有効化されると、ペリフェラルが値を更新するたびに `peripheral(_:didUpdateValueFor:error:)` が呼ばれます。これは9.5節で実装したReadの結果と **同じメソッド** です。

```swift
func peripheral(
    _ peripheral: CBPeripheral,
    didUpdateValueFor characteristic: CBCharacteristic,
    error: Error?
) {
    if let error = error {
        print("通知受信エラー: \(error)")
        return
    }

    guard let data = characteristic.value else { return }

    switch characteristic.uuid {
    case CBUUID(string: "12345678-1234-5678-1234-56789ABCDEF2"):
        // 環境センサーデータ（温度2バイト + 湿度2バイト）
        parseEnvironmentData(data)

    default:
        break
    }
}

private func parseEnvironmentData(_ data: Data) {
    guard data.count >= 4 else { return }

    // バイト0-1: 温度 (Int16 LE, 0.01°C 単位)
    let rawTemp  = Int16(littleEndian: data.withUnsafeBytes { $0.load(as: Int16.self) })
    let tempC    = Double(rawTemp) / 100.0

    // バイト2-3: 湿度 (UInt16 LE, 0.01% 単位)
    let rawHumid = data.withUnsafeBytes { $0.load(fromByteOffset: 2, as: UInt16.self) }
    let humidity = Double(rawHumid) / 100.0

    print("温度: \(String(format: "%.2f", tempC))°C  湿度: \(String(format: "%.2f", humidity))%")

    // UIの更新はメインスレッドで
    DispatchQueue.main.async {
        self.onSensorUpdate?(tempC, humidity)
    }
}
```

## 接続時の再サブスクリプション

**重要**: CCCDの設定は、接続が切断されると **ペリフェラル側でデフォルト値（無効）にリセットされます**。再接続後は必ず再度 `setNotifyValue(true, for:)` を呼ぶ必要があります。

```swift
func centralManager(_ central: CBCentralManager, didConnect peripheral: CBPeripheral) {
    peripheral.delegate = self
    peripheral.discoverServices([targetServiceUUID])
    // ↑ サービス → キャラクタリスティクス探索後に、
    //   didDiscoverCharacteristicsFor 内で setNotifyValue を呼ぶ
}

func centralManager(
    _ central: CBCentralManager,
    didDisconnectPeripheral peripheral: CBPeripheral,
    error: Error?
) {
    // 再接続
    centralManager.connect(peripheral, options: nil)
    // 再接続後はdidConnectから始まり、再度setNotifyValueが呼ばれる
}
```

## Notify受信頻度とバッファリング

nRF52840側でNotify間隔を設定すると（第7章の接続間隔設定を参照）、Core Bluetooth側では受信間隔に合わせてデリゲートが呼ばれます。

高頻度のNotifyを受け取る場合、UIの更新頻度を制限してパフォーマンスを保つ実装が必要です。

```swift
class BluetoothManager: NSObject, CBPeripheralDelegate {
    // UIに通知するためのコールバック
    var onSensorUpdate: ((Double, Double) -> Void)?

    // スロットリング: 最終更新から 100ms 以上経過した場合のみUIを更新
    private var lastUIUpdate = Date.distantPast
    private let uiUpdateInterval: TimeInterval = 0.1

    func peripheral(_ peripheral: CBPeripheral,
                    didUpdateValueFor characteristic: CBCharacteristic,
                    error: Error?) {
        guard error == nil, let data = characteristic.value else { return }

        let (temp, humidity) = parseData(data)

        // スロットリング
        let now = Date()
        if now.timeIntervalSince(lastUIUpdate) >= uiUpdateInterval {
            lastUIUpdate = now
            DispatchQueue.main.async {
                self.onSensorUpdate?(temp, humidity)
            }
        }
    }

    private func parseData(_ data: Data) -> (Double, Double) {
        // ... パース処理
        return (0.0, 0.0)
    }
}
```

## Notifyの無効化

ペリフェラルとの通信が不要になったとき、Notifyを明示的に無効化しておくとペリフェラル側の送信処理を止められます。

```swift
func disableNotifications() {
    guard let char = notifyCharacteristic,
          char.isNotifying else { return }
    peripheral?.setNotifyValue(false, for: char)
}
```

ただし、接続を切断する場合は切断時にCCCDがリセットされるため、切断直前に無効化を呼ぶ必要はありません。

## Indicateの確認応答フロー

ペリフェラルが Indication（`CBCharacteristicProperties.indicate`）を使う場合、Core Bluetoothは受信後に **自動的に確認応答（ATT Handle Value Confirmation）** をペリフェラルに返します。アプリ側での追加実装は不要です。

```swift
// Indicateのサブスクリプション（Notifyと同じコード）
if characteristic.properties.contains(.indicate) {
    peripheral.setNotifyValue(true, for: characteristic)
}
// 受信も didUpdateValueFor で受け取る（Notifyと同じ）
```

## nRF52840側との対応

第6章で作成したnRF52840のNotifyキャラクタリスティクス:

```c
// nRF52840: 通知送信
bt_gatt_notify(conn, &sensor_svc.attrs[SENSOR_NOTIFY_ATTR_IDX],
               &env_payload, sizeof(env_payload));
```

```swift
// iOS: 受信
func peripheral(_ peripheral: CBPeripheral,
                didUpdateValueFor characteristic: CBCharacteristic,
                error: Error?) {
    guard let data = characteristic.value, data.count >= 4 else { return }
    // env_payload 構造体に対応するパース
    let tempRaw  = Int16(littleEndian: data.withUnsafeBytes { $0.load(as: Int16.self) })
    let humidRaw = UInt16(littleEndian: data.withUnsafeBytes {
        $0.load(fromByteOffset: 2, as: UInt16.self)
    })
    let temp    = Double(tempRaw)  / 100.0
    let humidity = Double(humidRaw) / 100.0
    print("Notify受信: \(temp)°C, \(humidity)%RH")
}
```

---

**まとめ**

- `setNotifyValue(true, for:)` でCCCDを有効化し、 `didUpdateValueFor` で受け取る
- ReadとNotifyは同じ `didUpdateValueFor` で受け取るため、 UUIDで分岐する
- CCCDは切断でリセットされるため、**再接続後は必ず再サブスクリプション**
- Notifyの確認応答設定（`peripheral(_:didUpdateNotificationStateFor:error:)`)で有効化を確認できる
- Indicateの確認応答はCore Bluetoothが自動処理するため、追加実装は不要
