## バックグラウンドモードの必要性

デフォルトのiOSアプリは、バックグラウンドに移行するとわずかな実行時間の後にサスペンド状態になります。サスペンド中は **BLEイベントは通知されず、BTServerがキューに蓄積** します。アプリがフォアグラウンドに戻った時点でキューのイベントが届きます。

このデフォルト動作では、以下のユースケースを実現できません。

- バックグラウンドでセンサーデータを継続受信して記録する
- ペリフェラルとの接続が切れたらバックグラウンドで再接続する
- 特定のBLEデバイスが近づいたらバックグラウンドでアラートを出す

これらを実現するには **バックグラウンドモードの設定** が必要です。


## Info.plistの設定

Xcodeで対象ターゲットの「Signing & Capabilities」→「Background Modes」で設定するか、Info.plistに直接記載します。

```xml
<!-- Info.plist -->
<key>UIBackgroundModes</key>
<array>
    <string>bluetooth-central</string>
</array>
```

`bluetooth-central` を設定すると、セントラルロールのアプリがバックグラウンドでBLEイベントを受け取れます。ペリフェラルロールのアプリには `bluetooth-peripheral` を設定します。

設定後のバックグラウンド動作:

| イベント | バックグラウンド前提なし | bluetooth-central 設定済み |
|---|---|---|
| アドバタイズ受信（スキャン中）| サスペンドで停止 | 受信可能（制限あり） |
| 接続確立 | サスペンドで通知されない | `didConnect` コールバックあり |
| Notify受信 | サスペンドで通知されない | `didUpdateValueFor` コールバックあり |
| 切断検知 | サスペンドで通知されない | `didDisconnect` コールバックあり |


## バックグラウンドスキャンの制約

`bluetooth-central` を設定してバックグラウンドでスキャンを行うと、**12分に1回程度** の低頻度スキャンになります。ただし、同時にフォアグラウンドアプリがスキャンをしている場合は、フォアグラウンドアプリと同じ頻度のスキャンが行われます。

さらに、バックグラウンドスキャン時は `CBCentralManagerScanOptionAllowDuplicatesKey: true` が無視されます（重複除去が強制されます）。

```swift
// バックグラウンドスキャンの注意点
// withServices: nil はバックグラウンドで動作しない!
// 必ずサービスUUIDを指定する
centralManager.scanForPeripherals(
    withServices: [myServiceUUID],  // 必須
    options: nil
)
```

**重要**: `withServices: nil` でのスキャンはバックグラウンドでは機能しません。バックグラウンドスキャンには **必ずサービスUIDを指定** する必要があります。


## バックグラウンドでのNotify動作

接続済みのペリフェラルからのNotifyは、バックグラウンド中でも受信できます。Notify受信のたびにBTServerがアプリを一時的に起床させてデリゲートメソッドを呼び出します。

```swift
// バックグラウンドでもこのコールバックは呼ばれる
func peripheral(_ peripheral: CBPeripheral,
                didUpdateValueFor characteristic: CBCharacteristic,
                error: Error?) {
    guard let data = characteristic.value else { return }

    // データをCore Dataやファイルに保存（バックグラウンド処理）
    saveToDataStore(characteristic.uuid, data: data, timestamp: Date())

    // UIはフォアグラウンド復帰後に更新
    // バックグラウンドでUIを更新しても表示されないが、クラッシュはしない
}
```

バックグラウンドでの処理は **短時間で終わらせる** ことが重要です。iOSはバックグラウンドアプリの実行時間を厳しく管理しており、時間超過でプロセスが強制終了されることがあります。


## ユーザへの通知（Local Notification）

バックグラウンドでBLEイベントを受信して、ユーザにアラートを出す場合は **UserNotifications framework** を使います。

```swift
import UserNotifications

func sendLocalNotification(title: String, body: String) {
    let content = UNMutableNotificationContent()
    content.title = title
    content.body  = body
    content.sound = .default

    let request = UNNotificationRequest(
        identifier: UUID().uuidString,
        content: content,
        trigger: nil  // 即座に配信
    )

    UNUserNotificationCenter.current().add(request) { error in
        if let error = error {
            print("通知エラー: \(error)")
        }
    }
}

// 使用例: センサー閾値超過アラート
func peripheral(_ peripheral: CBPeripheral,
                didUpdateValueFor characteristic: CBCharacteristic,
                error: Error?) {
    guard let data = characteristic.value else { return }
    let temp = parseTemperature(data)

    if temp > 35.0 {
        sendLocalNotification(
            title: "高温アラート",
            body: "温度が\(String(format: "%.1f", temp))°Cを超えました"
        )
    }
}
```

ユーザー許可が必要なため、アプリ起動時に通知許可を申請します。

```swift
UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .sound]) { granted, _ in
    print("通知許可: \(granted)")
}
```


## State Restoration（状態復元）

アプリがバックグラウンドでメモリ不足によりOSに終了させられた場合でも、BLE接続状態を復元できる仕組みが **State Restoration** です。

### 設定方法

```swift
// 初期化時にRestoreIdentifierを指定
centralManager = CBCentralManager(
    delegate: self,
    queue: nil,
    options: [
        CBCentralManagerOptionRestoreIdentifierKey: "com.example.myBLEManager"
    ]
)
```

### 復元コールバックの実装

```swift
func centralManager(
    _ central: CBCentralManager,
    willRestoreState dict: [String: Any]
) {
    // 復元されたぺリフェラル一覧
    if let peripherals = dict[CBCentralManagerRestoredStatePeripheralsKey] as? [CBPeripheral] {
        for peripheral in peripherals {
            peripheral.delegate = self
            self.peripheral = peripheral
            print("保存済みペリフェラル復元: \(peripheral.name ?? "不明")")
        }
    }

    // 復元されたスキャンサービス一覧
    if let services = dict[CBCentralManagerRestoredStateScanServicesKey] as? [CBUUID] {
        print("保存済みスキャン対象サービス: \(services)")
    }
}
```

`willRestoreState` が呼ばれた後、通常どおり `centralManagerDidUpdateState` で `.poweredOn` を確認してから通信を再開します。

### State Restorationが必要なケース

- 健康管理アプリ（長時間バックグラウンド動作）
- プロセスが終了されても再起動後に自動再接続が必要な場合
- App Storeのレビューで要求されるバックグラウンド動作の信頼性確保


## 電力消費への影響

バックグラウンドモードを有効にすると、電力消費が増加します。

| 動作 | 電力への影響 |
|---|---|
| 接続維持（Notify待ち）| 低い（接続間隔に依存）|
| バックグラウンドスキャン | 中程度（12分制限で抑制）|
| 高頻度Notifyのバックグラウンド受信 | 中〜高（データ処理の都度起床）|

**接続間隔と電力のトレードオフ** は[@sec:ch7]で解説したとおりです。バックグラウンド動作が必要なアプリでは、ペリフェラル側の接続間隔を適切に設定することが重要です。

```
接続間隔 100ms → 高頻度Notify → iPhone電池消耗が早い（フィットネスアプリ向け）
接続間隔 1000ms → 低頻度Notify → iPhone電池消耗が少ない（環境センサー向け）
```


## バックグラウンドモードのベストプラクティス

1. **必要なときだけバックグラウンドモードを有効にする**: App Store審査で用途に合わない場合はリジェクトされることがある
2. **バックグラウンドでの処理は短く**: 長時間の処理はバックグラウンドタスク（BGTaskScheduler）と組み合わせる
3. **State Restorationを実装する**: メモリ不足でプロセスが終了されても再起動時に接続を復元できるようにする
4. **スキャンにはサービスUIDを必ず指定**: `nil` ではバックグラウンドスキャンが機能しない
5. **Local Notificationでユーザーに通知する**: バックグラウンドイベントをユーザーに伝える唯一の手段


**まとめ**

- `UIBackgroundModes: bluetooth-central` を設定するとバックグラウンドでBLEイベントを受信できる
- バックグラウンドスキャンは **12分に1回程度** に制限される。サービスUUID指定が必須
- 接続済みペリフェラルからのNotifyはバックグラウンドでも受信可能
- State Restorationでアプリがシステムに終了させられても接続状態を復元できる
- バックグラウンドでの処理は短く終えるよう設計する
