## CBCentralManagerを作る前に設計を考える

`CBCentralManager` のインスタンスをアプリに **1つだけ** もつのが原則です。複数インスタンスを作成しても動作するかもしれませんが、iOSのバージョンによって予期しない挙動が発生することがあります。

また、BLE通信を行っている間はインスタンスを解放してはいけません。接続が完了したからといって解放すると、BTServerとの接続が切断され、ペリフェラルとの通信も終了します。

一般的には `UIViewController` か専用の `BluetoothManager` クラスをシングルトンとして持ち、アプリのライフサイクル全体で保持します。

---

## 初期化コード

```swift
import CoreBluetooth
import UIKit

class BluetoothManager: NSObject, CBCentralManagerDelegate {

    // アプリ全体で1つのインスタンスを保持
    var centralManager: CBCentralManager!

    override init() {
        super.init()
        // delegate: イベントを受け取るオブジェクト（自分自身）
        // queue: nilでメインキュー（UIと同スレッド）
        centralManager = CBCentralManager(delegate: self, queue: nil)
    }
}
```

`initWithDelegate:queue:` の引数 `queue` に `nil` を渡すとメインキューが使われます。BLE処理が重い場合や、メインスレッドをブロックしたくない場合はDispatchQueueを指定します。

```swift
// バックグラウンドキューを指定する場合
let bleQueue = DispatchQueue(label: "com.example.bleQueue", qos: .background)
centralManager = CBCentralManager(delegate: self, queue: bleQueue)
```

> **注意**: バックグラウンドキューを使う場合、デリゲートメソッド内でUIを更新するコードは `DispatchQueue.main.async` でメインスレッドに戻す必要があります。

## 状態管理: centralManagerDidUpdateState

CBCentralManagerの初期化が完了すると、**即座に** `centralManagerDidUpdateState(_:)` が呼ばれます。このメソッドは `CBCentralManagerDelegate` で **唯一の必須（required）** メソッドです。

```swift
func centralManagerDidUpdateState(_ central: CBCentralManager) {
    switch central.state {
    case .poweredOn:
        print("Bluetooth ON: スキャン開始可能")
        startScanning()
    case .poweredOff:
        print("Bluetooth OFF: ユーザーに有効化を促す")
        // UIでユーザーに通知する
    case .unauthorized:
        print("BLE使用の権限がありません")
        // Info.plistの設定を確認
    case .unsupported:
        print("このデバイスはBLE非対応")
    case .resetting:
        print("BTServerリセット中: 再接続処理を行う")
        handleDisconnection()
    case .unknown:
        // インスタンス生成直後の一時的な状態
        break
    @unknown default:
        break
    }
}
```

### 各状態の意味と対処

| 状態 | 意味 | 対処 |
|---|---|---|
| `.unknown` | 初期値。すぐに更新される | 何もしない |
| `.resetting` | BTServerが一時的に接続断 | 接続を切断し再接続準備 |
| `.unsupported` | BLE非対応デバイス（シミュレーター等） | BLEなしで動作するフォールバック |
| `.unauthorized` | アプリにBLE権限がない | Info.plistの目的文言を確認 |
| `.poweredOff` | Bluetoothがオフ | ユーザーにCore Bluetooth設定を案内 |
| `.poweredOn` | 正常。スキャン可能 | スキャン開始 |

`.poweredOn` になるまでは **スキャンも接続もできません**。`centralManagerDidUpdateState` で `.poweredOn` を確認してから次のステップに進む設計が基本です。

## 状態遷移図

```
インスタンス生成
      │
      ▼
 .unknown ─────────────→ .unsupported（非BLEデバイス）
      │
      ├──→ .unauthorized（権限なし）
      │
      ▼
 .poweredOff
      │ ユーザーがBluetoothをON
      ▼
 .poweredOn  ←─────────────────────────────┐
      │                                     │
      │ ユーザーがOFF / BTServerクラッシュ  │
      ▼                                     │
 .poweredOff / .resetting ─────────────────┘
```

`.resetting` は BTServer が異常終了してリセットされたときに通知されます。この状態になったら、進行中の接続は切断されたものとして扱い、`.poweredOn` に戻ったときに再スキャン・再接続を試みます。

## CBCentralManagerのオプション初期化

iOS 7以降では初期化オプション辞書を渡せます。

```swift
let options: [String: Any] = [
    CBCentralManagerOptionShowPowerAlertKey: true,       // BT OFFのときダイアログを表示
    CBCentralManagerOptionRestoreIdentifierKey: "com.example.myBLEManager"  // State Restoration用
]
centralManager = CBCentralManager(delegate: self, queue: nil, options: options)
```

`CBCentralManagerOptionShowPowerAlertKey` を `true` にすると、Bluetoothがオフのときにシステムダイアログ（「Bluetoothをオンにしますか？」）が自動表示されます。デフォルトは `false` です。

`CBCentralManagerOptionRestoreIdentifierKey` はバックグラウンドでのState Restoration（アプリが終了後に再起動されても接続状態を復元する機能）に使います。詳細は9.7節で解説します。

## スキャン開始タイミングの実装例

状態変化を受け取るUIとBluetooth処理を分離した実装例です。

```swift
class BluetoothManager: NSObject, CBCentralManagerDelegate {
    var centralManager: CBCentralManager!
    var onStateUpdate: ((CBManagerState) -> Void)?         // UIへのコールバック
    var peripheral: CBPeripheral?                          // 接続先を保持

    override init() {
        super.init()
        centralManager = CBCentralManager(
            delegate: self,
            queue: DispatchQueue(label: "com.example.ble"),
            options: [CBCentralManagerOptionShowPowerAlertKey: true]
        )
    }

    func centralManagerDidUpdateState(_ central: CBCentralManager) {
        // UIコールバックはメインスレッドで呼ぶ
        DispatchQueue.main.async {
            self.onStateUpdate?(central.state)
        }

        if central.state == .poweredOn {
            startScanning()
        }
    }

    private func startScanning() {
        // 次節で实装
    }
}
```

このように **UIへの通知とBLE制御を分離** するパターンにしておくと、テストしやすくViewControllerも薄く保てます。

## よくあるミス

**`centralManagerDidUpdateState` の前にスキャンを開始する**

```swift
// ❌ 間違い: init内で即座にスキャンしようとするコード
override init() {
    super.init()
    centralManager = CBCentralManager(delegate: self, queue: nil)
    centralManager.scanForPeripherals(withServices: nil, options: nil) // 🚫 まだpoweredOnでない
}
```

CBCentralMangerを初期化した直後の状態は `.unknown` であり、スキャンを開始できません。必ず `centralManagerDidUpdateState` で `.poweredOn` を確認してからスキャンを始めます。

**メソッド名のタイポ**

`CBCentralManagerDelegate` のメソッドはほとんどがオプショナル（`@objc optional`）です。メソッド名をタイポしてもコンパイルエラーにはなりません。Xcodeの補完（Ctrl+Space）とドキュメントを活用してタイポを防ぎます。

---

**まとめ**

- `CBCentralManager` はアプリで1インスタンス、アプリライフサイクル全体で保持
- `centralManagerDidUpdateState` は **唯一の必須デリゲートメソッド**
- `.poweredOn` になるまでスキャン・接続は実行不可
- `.resetting` は再接続のトリガー; `.unauthorized` は権限設定の見直しが必要
- UIコールバックとBLE処理を分離する設計がメンテナブル

次節では `.poweredOn` 確認後に呼ぶ `scanForPeripherals(withServices:options:)` の詳細を解説します。
