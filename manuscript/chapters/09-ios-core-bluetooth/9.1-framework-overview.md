## iOSのBluetooth LEアーキテクチャ

iOS上でBluetooth LEを扱うアプリケーションを書く前に、iOSがBLEを内部でどのように実装しているかを把握しておくと、予期せぬ挙動に遭遇したときに原因を特定しやすくなります。

iOSのBluetooth LEホスト実装は **BTServer** というシステムデーモンが担っています。Bluetooth LE コントローラ（ハードウェア）との HCI 通信、Link Layer 管理、L2CAP/ATT/GATT スタックはすべてこのデーモン内で動作します。

```
┌─────────────────────────────────────┐
│         iOS アプリケーション          │
│  ┌──────────────────────────────┐   │
│  │    Core Bluetooth framework  │   │
│  └────────────┬─────────────────┘   │
└───────────────│─────────────────────┘
                │ IPC (XPC)
┌───────────────▼─────────────────────┐
│            BTServer daemon           │
│  GATT layer / ATT layer / L2CAP     │
│  Link Layer management               │
└───────────────┬─────────────────────┘
                │ HCI
┌───────────────▼─────────────────────┐
│  Bluetooth LE Controller (Hardware) │
└─────────────────────────────────────┘
```

アプリケーションとBTServerの間は **XPCベースのプロセス間通信（IPC）** で接続されています。Core Bluetoothフレームワークは、このIPCをラップして使いやすいSwift/Objective-CのAPIとして提供します。

この設計から導かれる重要な含意が2つあります。

1. **アプリが複数動作しても問題ない**: BLE通信の実体はBTServer側にあるため、複数のアプリが同時にCBCentralManagerを生成しても、ハードウェアリソースの仲裁はシステム側が行います。ただし意図しない競合は避けるべきです。
2. **アプリがサスペンドされてもBTServerは動き続ける**: バックグラウンドモードを設定しておけば、アプリがサスペンド中でもBTServerが通知を受信し、アプリを起床させてデリゲートを呼び出せます。


## Core Bluetoothフレームワークの主要クラス

第4章で解説したATT/GATTの概念が、Core Bluetoothではクラスとして表現されています。

| GATT/ATTの概念 | Core Bluetoothのクラス | 役割 |
|---|---|---|
| セントラル（クライアント）| `CBCentralManager` | スキャン・接続・切断の制御 |
| ペリフェラル（サーバ）| `CBPeripheral` | 接続済みペリフェラルの表現 |
| サービス | `CBService` | キャラクタリスティクスの論理グループ |
| キャラクタリスティクス | `CBCharacteristic` | 値の読み書き・通知の単位 |
| ペリフェラルマネージャ | `CBPeripheralManager` | iOS側をペリフェラルとして動作させる |

本章では主に **セントラルロール**（iPhoneからnRF52840に接続する方向）を扱います。ペリフェラルロール（`CBPeripheralManager`）については概要のみ触れます。


## UUIDとCBUUID

BLEのサービスやキャラクタリスティクスは **UUID（Universally Unique Identifier）** で識別されます。UUIDは128ビットの値で、次の2種類があります。

### Bluetooth SIG標準UUID（16bit短縮形）

Bluetooth SIGが規定したサービス・キャラクタリスティクスには16bit短縮形UUIDが割り当てられています。たとえば心拍数サービスは `0x180D`、バッテリーサービスは `0x180F` です。

16bit短縮形は `0000XXXX-0000-1000-8000-00805F9B34FB` という128bitベースUUIDの `XXXX` 部分です。

```swift
// 16bit短縮形（SIG標準サービス）
let heartRateServiceUUID = CBUUID(string: "180D")

// 内部では128bitに展開される
// 0000180D-0000-1000-8000-00805F9B34FB
```

### カスタムUUID（128bit）

独自に定義したサービスやキャラクタリスティクスには、128bitのカスタムUUIDを使います。macOSの `uuidgen` コマンドで生成できます。

```bash
$ uuidgen
71DA3FD1-7E10-41C1-B16F-4430B506CDE7
```

```swift
// カスタム128bit UUID
let customServiceUUID = CBUUID(string: "71DA3FD1-7E10-41C1-B16F-4430B506CDE7")
```

> **注意**: 16bit短縮形UUIDはBluetooth SIGが管理しており、独自定義に使ってはいけません。カスタムサービスには必ず128bitのUUIDを使用します。


## フレームワークで実現できること

Core Bluetoothフレームワークが提供するセントラルロールの機能は次のとおりです。

**スキャン（广告パケットの受信）**
- サービスUUIDによるフィルタリングスキャン
- アドバタイズメントデータ（ローカル名・サービスUUID・製造者データ等）の取得
- RSSI（受信信号強度）の取得による距離推定

**接続管理**
- ペリフェラルへの接続・切断
- 接続オプション（バックグラウンド通知設定等）

**GATT通信**
- サービス・キャラクタリスティクスの探索
- キャラクタリスティクス値の読み出しと書き込み
- Notify/Indicateのサブスクリプション管理

**対応できないこと（重要な制約）**
- クラシックBluetoothのSPP（シリアルポートプロファイル）へのアクセス → MFi認証が必要
- L2CAPのATT_MTU交換の細かい制御（iOS/OSがハンドリング）
- アドバタイズメント間隔の明示的な設定（BTServerが決定）


## 開発に必要な準備

### Xcodeプロジェクトの設定

Core Bluetoothフレームワークは **iOS 5以降**（セントラルロール）でサポートされています。現在の開発では iOS 13+ をターゲットとするのが一般的です。

フレームワークは自動的にリンクされるため、手動での追加は不要です。Swiftコードでは `import CoreBluetooth` と記述するだけで使えます。

### Info.plistへの目的の記載（iOS 13以降必須）

iOS 13以降、BLEを使うアプリはInfo.plistに使用目的を記載する必要があります。記載がない場合、アプリがBLEにアクセスしようとした時点でクラッシュします。

```xml
<key>NSBluetoothAlwaysUsageDescription</key>
<string>BLEデバイスのセンサーデータを受信するためにBluetoothを使用します。</string>
```

バックグラウンド動作も必要な場合は、「Required Background Modes」も追加します（9.7節で詳述）。


## デリゲートパターン

Core Bluetoothの操作はすべて **非同期** です。スキャン、接続、読み書きの結果はデリゲートメソッドを通じて通知されます。

```
アプリ                           Core Bluetooth
 │                                    │
 │ centralManager.scanForPeripherals()│
 │──────────────────────────────────→│
 │                                    │ (非同期でアドバタイズ受信)
 │ didDiscoverPeripheral(...)         │
 │←──────────────────────────────────│
 │                                    │
 │ centralManager.connect(peripheral) │
 │──────────────────────────────────→│
 │                                    │ (接続手続き)
 │ didConnect(peripheral)             │
 │←──────────────────────────────────│
```

必須の実装デリゲートは2つです。

- `CBCentralManagerDelegate`: CBCentralManagerの状態変化・スキャン結果・接続イベント
- `CBPeripheralDelegate`: 発見したペリフェラルのサービス探索・読み書き・Notify受信

次節からは、この2つのデリゲートを実装しながら、スキャンから通信完了までの一連のフローを説明します。


**まとめ**

- Core Bluetoothは **BTServer（デーモン）** とのIPCをラップしたフレームワーク
- 主要クラスはCBCentralManager / CBPeripheral / CBService / CBCharacteristic
- UUIDには16bit短縮形（SIG標準）と128bitカスタムの2種類がある
- すべての操作は非同期＋デリゲートパターンで実装する
- iOS 13以降はInfo.plistへの目的記載が必須
