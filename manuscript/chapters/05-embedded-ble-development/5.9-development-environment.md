## 5.9 BLE内蔵マイコンの開発環境 {#sec:ch5-development-environment}

BLE内蔵マイコンの開発環境には、コードを入力するエディター以外にも多くの要素があります。メーカーやSDKが違っても、基本的な流れは共通しています。

```text
ソースコードと設定
        ↓
コンパイラー／リンカー
        ↓
ファームウェアイメージ
        ↓
書き込み・デバッグツール
        ↓
MCU上で実行
        ↓
ログ／デバッガー／測定器で観測
```

### 5.9.1 SDKとBluetoothスタック

SDKは、ヘッダーファイルとライブラリーだけを指すとは限りません。BLE内蔵マイコン向けSDKには、Bluetoothスタック、RTOS、デバイスドライバー、ビルドシステム、サンプル、書き込みツールが含まれます。

Bluetoothスタックの提供方法もメーカーによって異なります。

- バイナリーとして提供され、所定のAPIから呼び出す
- RTOSの一部としてソースコードからビルドする
- HostとControllerを別々の実装から選ぶ
- 無線コア向けファームウェアを別イメージとして書き込む

どの形式でも、アプリケーションからはGAP／GATT APIが見えます。しかし、メモリーの割り当て、更新方法、ログ、脆弱性対応、ライセンスは異なります。

### 5.9.2 RTOSと実行モデル

小さなマイコンは、リセット後に初期化を行い、メインループと割り込みで動かすことができます。RTOSを使うと、複数のスレッド、タイマー、キュー、同期機構を利用できます。

BLE処理は非同期です。アドバタイジング開始を要求した後、接続、書き込み、切断は将来のイベントとして届きます。SDKはコールバック、イベントキュー、スレッドなどの形で通知します。

コールバックの実行コンテキストを確認せず、長い計算、ブロッキングI/O、待ち合わせを行うと、Bluetoothスタックやほかの処理を止める可能性があります。時間のかかる処理はワークキューや製品ロジックのスレッドへ渡します。

### 5.9.3 プロジェクトを構成するファイル

一般的なファームウェアプロジェクトには、次があります。

- C／C++などのソースコード
- 対象マイコンと開発ボードの定義
- 機能を選択するビルド設定
- 周辺回路とピン割り当て
- リンカースクリプトとメモリーマップ
- Bootloader、署名、更新イメージの設定

nRF Connect SDKはZephyrを基盤とし、主に次の仕組みを使います。

| 仕組み | 主な役割 |
|---|---|
| CMake | アプリケーションとソースファイルをビルドへ登録する |
| Kconfig／`prj.conf` | Bluetooth、ログ、ドライバーなどの機能を選ぶ |
| Devicetree | SoC、ボード、GPIO、I2C、SPIなどのハードウェアを記述する |
| west | ワークスペース管理、ビルド、書き込みなどの入口 |
| Zephyr API | カーネル、ドライバー、Bluetooth Hostをアプリケーションから使う |

KconfigとDevicetreeは役割が異なります。Kconfigは「この機能をビルドへ含めるか」を選び、Devicetreeは「どのハードウェアが、どのアドレスやピンにあるか」を表します。

### 5.9.4 nRF Connect SDK 3.0を準備する

本書ではnRF Connect SDK 3.0の安定版を使います。SDKと対応ツールチェーンの組み合わせを固定し、章をまたいで同じ環境を使います。

Nordicは、Visual Studio CodeのnRF Connect拡張機能からSDKとツールチェーンをまとめてインストールする方法を案内しています。拡張機能のWelcome画面から`Install SDK`を選び、nRF Connect SDK 3.0の安定版とインストール先を指定します。拡張機能は対応するツールチェーンも導入します。

GUIはインストールと操作の入口ですが、ビルドの仕組みそのものではありません。インストール後は、nRF Connect用のターミナルを開き、次を確認します。

```bash
west --version
cmake --version
ninja --version
```

実際のバージョン番号はSDK 3.0のツールチェーンに従います。本書では出力例の細かな番号ではなく、選択したSDKとツールチェーンが対応していることを確認します。

SDKの`main`ブランチは開発中の状態です。本書の手順では、再現性を優先してリリース済みのタグを使います。

インストール方法は更新されるため、実行時にはNordicの[Installing SDK and toolchain for the first time](https://docs.nordicsemi.com/r/bundle/nrf-connect-vscode/page/get_started/quick_setup.html/installing-sdk-and-toolchain-for-the-first-time)も確認してください。

### 5.9.5 開発ボードを接続する

nRF52840 DKの開発用USBコネクターとPCを、データ通信に対応したUSBケーブルで接続します。充電専用ケーブルでは認識されません。

Visual Studio CodeのnRF Connect拡張機能またはnRF Terminalから、接続されたボードのシリアルポートやデバッガーを確認します。複数の開発ボードを接続する場合は、シリアル番号を指定して書き込み先を選びます。

古い資料では`nrfjprog`を直接使う手順が多く見つかります。nRF Connect SDK 3.0では、通常のビルドと書き込みは`west`やnRF Connect拡張機能を入口にします。問題を切り分けるときには、その下で使われるnRF Util、J-Link、デバイスドライバーまで確認します。
