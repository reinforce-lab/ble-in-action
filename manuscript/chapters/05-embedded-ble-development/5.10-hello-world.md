## 5.10 nRF52840でHello Worldを動かす {#sec:ch5-hello-world}

最初はBluetoothを使いません。短いプログラムをビルドし、nRF52840 DKへ書き込み、ログを確認します。これによって、一般的なマイコン開発の一周を先に成立させます。

### 5.10.1 最小プロジェクト

次のファイルを用意します。

```text
hello_world/
├── CMakeLists.txt
├── prj.conf
└── src/
    └── main.c
```

`CMakeLists.txt`は、Zephyrのビルドシステムを読み込み、アプリケーションのソースを登録します。

```cmake
cmake_minimum_required(VERSION 3.20.0)

find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
project(hello_world)

target_sources(app PRIVATE src/main.c)
```

`prj.conf`ではコンソール出力を有効にします。開発ボードとSDKの標準設定でUARTコンソールが有効になる場合でも、サンプルがログを必要とすることを明示します。

```kconfig
CONFIG_CONSOLE=y
CONFIG_PRINTK=y
```

`main.c`は文字列を出力して終了します。

```c
#include <zephyr/kernel.h>

int main(void)
{
    printk("Hello from nRF52840\n");
    return 0;
}
```

### 5.10.2 ボードを指定してビルドする

nRF Connect SDK 3.0では、nRF52840 DK上のnRF52840を`nrf52840dk/nrf52840`として指定します。

```bash
west build -b nrf52840dk/nrf52840
```

ビルドは、おおむね次の順で進みます。

1. CMakeがアプリケーションとZephyrを構成します。
2. Kconfigが`prj.conf`と依存関係から有効な機能を決めます。
3. Devicetreeが対象ボードのハードウェア記述を生成します。
4. コンパイラーがソースをオブジェクトへ変換します。
5. リンカーがZephyr、ドライバー、アプリケーションを一つのイメージへ配置します。

`build/zephyr/`には、用途の異なる成果物が生成されます。

| ファイル | 用途 |
|---|---|
| `zephyr.elf` | シンボルとデバッグ情報を含む。デバッガーや解析に使う |
| `zephyr.hex` | Flashへ書き込むIntel HEX形式 |
| `zephyr.bin` | 生のバイナリーイメージ |
| `zephyr.map` | 関数やデータの配置、Flash／RAM使用量を確認する |

ビルドの最後にはFlashとRAMの使用量が表示されます。Hello Worldの値そのものより、以後の機能追加によって使用量がどう増えるかを観測できることが重要です。

### 5.10.3 書き込みとログ確認

nRF52840 DKを接続し、次を実行します。

```bash
west flash
```

書き込み後にボードがリセットされ、プログラムが起動します。nRF Terminalなどで対応するシリアルポートを開くと、次の文字列を確認できます。

```text
Hello from nRF52840
```

文字列が表示されない場合は、次の順で切り分けます。

1. ビルドは成功したか
2. 書き込み先のボードは正しいか
3. 書き込み後にリセットされたか
4. 選択したシリアルポートは正しいか
5. コンソールの方式と通信設定は一致しているか

ソースコードの誤りと、PCがログを受け取れない問題を混ぜないことが大切です。

### 5.10.4 変更を一周させる

出力する文字列を変更し、再度ビルド、書き込み、ログ確認を行います。

```text
ソースを変更
    ↓
west build
    ↓
west flash
    ↓
リセット後のログを確認
```

この一周が、以後の章で繰り返す開発ループです。Bluetoothを有効にしても、センサーを追加しても、問題を「設定」「コンパイル」「リンク」「書き込み」「実行」「外部からの観測」に分けて考えます。
