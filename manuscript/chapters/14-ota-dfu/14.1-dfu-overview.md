# DFUの仕組みとBootloader

<!-- topic: OTA DFU, Bootloader, イメージスロット, MCUboot, Swap, Nordic DFU -->


## なぜOTA DFUが必要か

製品を出荷した後でもバグ修正や機能追加が必要になります。OTA DFU（Over-The-Air Device Firmware Update）を使えば、ユーザーはスマートフォンアプリでボタンを押すだけでファームウェアを更新できます。JAGタグやUSB接続は不要です。


## Bootloaderの役割

DFUを実現するために、マイコンには **Bootloader** が必要です。Bootloaderは通常のアプリケーションより先に起動する特殊なプログラムで、以下の役割を持ちます。

1. **新ファームウェアの受信・保存**: DFU転送中のデータを二次スロットに書き込む
2. **整合性チェック**: CRCまたは署名を検証する
3. **イメージの書き換え**: 検証が通ったら一次スロットと二次スロットを入れ替える（Swap）
4. **障害時のロールバック**: 起動失敗が続く場合は旧ファームウェアに戻す

```
Flash 領域の分割
┌─────────────────────────────────────────────────────────────────┐
│ 0x00000                                                         │
│  Bootloader  (MCUboot)                                          │
│  ～48KB                                                         │
├─────────────────────────────────────────────────────────────────┤
│ Bootloader情報 (MCUBOOT_HEADER等)                                │
├─────────────────────────────────────────────────────────────────┤
│ Primary Slot (アクティブなアプリケーション)                        │
│  ～440KB                                                        │
├─────────────────────────────────────────────────────────────────┤
│ Secondary Slot (DFU受信エリア)                                   │
│  ～440KB                                                        │
├─────────────────────────────────────────────────────────────────┤
│ Scratch Area (Swap中の一時退避)                                   │
│  ～4KB                                                          │
└─────────────────────────────────────────────────────────────────┘
  0xFFFFF
```

nRF52840の総フラッシュ領域は **1MB** です。

## Nordic DFUプロトコルの種類

| プロトコル | Bootloader | 特徴 |
|---|---|---|
| Legacy DFU | nRF5 SDK Bootloader | 旧来（SDK v11以前） |
| Secure DFU | nRF5 SDK Bootloader | 署名付き。SDK v12〜 |
| **SMP (MCUmgr)** | **MCUboot** | **nRF Connect SDK 標準。本書で使用** |

本書ではnRF Connect SDK + **MCUboot + SMP** の組み合わせを使います。iOSライブラリにはNordicの [nRF Connect Device Manager (iOS)](https://github.com/NordicSemiconductor/IOS-nRF-Connect-Device-Manager) を使います。


**まとめ**

- Bootloaderは Primary / Secondary スロットを管理し、DFU後にSwapを行う
- nRF52840(1MB)は Bootloader(48KB) + Primary(440KB) + Secondary(440KB) + Scratch(4KB) に分割
- nRF Connect SDK環境では MCUboot + SMP が標準構成
- iOSからはSMPプロトコルで BLE経由でファームウェアを転送する

次節ではMCUbootをnRF52840に設定します。
