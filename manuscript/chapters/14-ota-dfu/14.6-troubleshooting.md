## よくある問題と解決法

### 問題1: 「Image hash does not match」

**原因**: 転送中にパケット損失が発生し、受信側のCRCが合わない。

**解決策**:
```swift
// FirmwareUpgradeConfiguration でパイプライン深度を下げる
let config = FirmwareUpgradeConfiguration(
    pipelineDepth: 1   // デフォルト3 → 1に下げてシリアル転送に
)
```

また、Connection Interval を短くすると再送機会が増えます。

```kconfig
# prj.conf: Connection Interval の最小値を下げる
CONFIG_BT_PERIPHERAL_PREF_MIN_INT=6   # 7.5ms
CONFIG_BT_PERIPHERAL_PREF_MAX_INT=12  # 15ms
```


### 問題2: 転送が50〜60%で止まる

**原因**: iPhone側のバッファが溢れてフロー制御が働いている。

**解決策**:
```kconfig
# Bufferサイズを増やす
CONFIG_BT_L2CAP_TX_BUF_COUNT=8
CONFIG_BT_BUF_ACL_TX_COUNT=10
CONFIG_BT_BUF_ACL_RX_SIZE=502
```


### 問題3: DFU後に古いファームウェアで起動する（ロールバック）

**原因**: アプリが `boot_write_img_confirmed()` を呼んでいない。または呼ぶ前に `watchdog` がタイムアウトした。

**解決策**:
```c
#include <zephyr/dfu/mcuboot.h>

int main(void)
{
    // 起動直後（WDTリセット前）にコンファームする
    if (!boot_is_img_confirmed()) {
        boot_write_img_confirmed();
        printk("イメージ確認済み\n");
    }
    // ... 残りの初期化
}
```


### 問題4: Bootloaderで止まる（アプリが起動しない）

**原因**: イメージ署名の検証失敗（鍵が違う）か、パーティションサイズの不一致。

**解決法**: シリアルログで確認します。

```
# 正常ケース
[00:00:00.001] I: Primary image: version=1.1.0
[00:00:00.002] I: Jumping to first image slot

# 異常ケース: 署名失敗
[00:00:00.001] E: bootutil_img_validate: Verification failed!
[00:00:00.002] W: Failed attempt to boot image 0 (3)
```

署名鍵が一致していることを確認します。

```bash
# ビルド時と同じ鍵で再署名
imgtool verify --key root-ec-p256.pem build/zephyr/zephyr.signed.bin
# Verified OK!  ← この出力が必要
```


### 問題5: リカバリーモードへの入り方

署名鍵を紛失した、または不正なイメージを書き込んだ場合でも、nRF52840DKは **UART/USB経由での書き込み** が常に可能です（`west flash` でオーバーライドできる）。

プロダクション基板でリカバリが困難な場合は、**デバッグポートを塞ぐ前**にリカバリUART（GPIOブートピン）を設計段階で組み込んでおくことを推奨します。


## DFU開発チェックリスト

```
□ MCUboot が正しく設定されている (CONFIG_BOOTLOADER_MCUBOOT=y)
□ プライマリ・セカンダリスロットのサイズが pm_static.yml と一致している
□ アプリが boot_write_img_confirmed() を起動直後に呼んでいる
□ FirmwareUpgradeConfiguration の pipelineDepth を適切に設定している
□ DFUパッケージの manifest.json のフォーマットが正しい
□ 署名鍵が正しい (imgtool verify で確認)
□ MTU が十分大きい (244+ バイト推奨)
□ Connection Interval が短い (15ms 以下推奨)
```


**まとめ**

| 症状 | 原因 | 対処 |
|---|---|---|
| CRCミスマッチ | パケット損失 | pipelineDepth=1、Connection Intervalを短く |
| 転送中断 | バッファ溢れ | BT_L2CAP_TX_BUF_COUNT増加 |
| 旧バージョン起動 | コンファーム未実施 | `boot_write_img_confirmed()` 追加 |
| Bootloaderで停止 | 署名不一致 | `imgtool verify` で鍵確認 |
