## MCUbootの有効化

`prj.conf` に以下を追加するとMCUbootが自動的にリンクされます。

```kconfig
# MCUboot Bootloader
CONFIG_BOOTLOADER_MCUBOOT=y

# SMPサーバー (DFU受信エンドポイント)
CONFIG_MCUMGR=y
CONFIG_MCUMGR_TRANSPORT_BT=y
CONFIG_MCUMGR_GRP_IMG=y       # Imageグループ (DFU本体)
CONFIG_MCUMGR_GRP_OS=y         # OSグループ (リセット等)

# BLE SMP最大転送サイズ (MTU - ATTオーバーヘッド)
CONFIG_MCUMGR_TRANSPORT_BT_REASSEMBLY=y
CONFIG_BT_L2CAP_TX_MTU=498
CONFIG_BT_BUF_ACL_RX_SIZE=502

# 既存のBLE設定
CONFIG_BT=y
CONFIG_BT_PERIPHERAL=y
CONFIG_BT_DEVICE_NAME="BLEInAction_DFU"
```

## パーティションテーブル

`pm_static.yml`（Permanent Memory Partitions）でフラッシュ領域を明示的に定義します。

```yaml
# pm_static.yml (nRF52840: 1MB Flash)
mcuboot:
  address: 0x0
  size: 0xC000          # 48KB

mcuboot_primary:
  address: 0xC000
  size: 0x6E000         # 440KB

mcuboot_secondary:
  address: 0x7A000
  size: 0x6E000         # 440KB

mcuboot_scratch:
  address: 0xE8000
  size: 0x4000          # 16KB (Scratch: ページサイズの倍数)

settings_storage:
  address: 0xEC000
  size: 0x8000          # 32KB: Zephyr Settings等
```

`prj.conf` にパーティションファイルを指定します。

```kconfig
CONFIG_PM_PARTITION_REGION_MCUBOOT_SECONDARY_EXTERNAL_FLASH=n
# pm_static.yml はビルドシステムが自動で検出
```

## 署名鍵の準備

MCUbootはファームウェアイメージに **ECDSAまたはRSA署名** を要求します。開発中は`imgtool`でテスト鍵を生成します。

```bash
# imgtool のインストール (nRF Connect SDK に含まれる)
pip install imgtool

# EC256 (ECDSA-P256) テスト秘密鍵の生成
imgtool keygen -k root-ec-p256.pem -t ecdsa-p256

# 公開鍵をC配列に変換（MCUbootビルドに使用）
imgtool getpub -k root-ec-p256.pem

# 出力例:
# const unsigned char rsa_pub_key[] = {
#     0x04, 0x3b, ...
# };
```

**注意**: 本番製品では秘密鍵を安全なキー管理システム（HSM等）で保護してください。GitHubにコミットしないよう必ず `.gitignore` に追加します。

```bash
echo "*.pem" >> .gitignore
```

## ビルドと確認

```bash
# MCUboot付きビルド
west build -b nrf52840dk/nrf52840 -- \
    -DCONFIG_BOOTLOADER_MCUBOOT=y \
    -DCONF_FILE="prj.conf"

# フラッシュ（MCUboot + アプリ両方を書き込む）
west flash

# シリアルモニタでBootloaderの起動を確認
west espterm --dev /dev/ttyACM0 --speed 115200
# [00:00:00.000] I: Starting bootloader
# [00:00:00.001] I: Primary image: magic=good, swap_type=0x1, copy_done=0x3, image_ok=0x3
# [00:00:00.002] I: Bootloader chainload address offset: 0xc000
# [00:00:00.003] I: Jumping to the first image slot
```

## アプリケーションの確認フローを追加

DFU後の起動でアプリが「動作確認完了（confirm）」フラグを立てる必要があります。立てないと次回リセット時にBootloaderが旧バージョンへロールバックします。

```c
#include <zephyr/dfu/mcuboot.h>

int main(void)
{
    /* DFUで更新されたイメージをconfirmする */
    if (!boot_is_img_confirmed()) {
        int ret = boot_write_img_confirmed();
        if (ret) {
            printk("イメージ確認失敗: %d\n", ret);
            /* 意図的にコンファームしない → 次回ロールバック */
        } else {
            printk("新ファームウェアのイメージを確認しました\n");
        }
    }

    /* 通常の初期化 ... */
}
```

**まとめ**

- `CONFIG_BOOTLOADER_MCUBOOT=y` + `CONFIG_MCUMGR_TRANSPORT_BT=y` でDFU有効化
- `pm_static.yml` でPrimary(440KB) / Secondary(440KB) / Scratch(16KB) を定義
- `imgtool keygen` でECDSA-P256鍵を生成し、秘密鍵は安全に管理
- 起動後に `boot_write_img_confirmed()` を呼ぶことでロールバックを防ぐ
