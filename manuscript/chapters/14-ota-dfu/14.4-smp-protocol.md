## SMP（Simple Management Protocol）の概要

nRF Connect SDK の DFU は **SMP（Simple Management Protocol）** を使います。SMPはMCUmgrフレームワークの通信プロトコルで、Image管理・OS管理・FileSystem管理などのコマンドグループを持ちます。

```
┌──────────────────────────────────────────────────────────┐
│  SMP フレーム構造                                          │
│                                                          │
│  ┌─────┬──────┬──────┬────┬────┬─────────────────────┐  │
│  │OP(1)│FLAGS │LEN(2)│GRP │SEQ │ CBOR Payload        │  │
│  │0=R  │      │      │(2) │(1) │  コマンドデータ       │  │
│  │2=W  │      │      │    │    │                     │  │
│  └─────┴──────┴──────┴────┴────┴─────────────────────┘  │
│                                                          │
│  GRP=1: Image管理 (DFU)                                  │
│  GRP=0: OS管理 (reset等)                                  │
└──────────────────────────────────────────────────────────┘
```

## DFUのコマンドシーケンス詳細

```
iOS  →  nRF52840                           説明
─────────────────────────────────────────────────────────────
[1] Image List (Read)                   現在のイメージ情報確認
    GRP=1, CMD=0, OP=Read

[2] Image Upload (Write, chunk 0..N)    ファームウェア転送（分割）
    GRP=1, CMD=1, OP=Write
    CBOR: { "off": 0, "data": <bytes> }
    CBOR: { "off": 512, "data": <bytes> }  ← MTU分割
    ...
    最後のチャンク: { "off": N, "data": <bytes>, "len": total_size }

[3] Image Test (Write)                  新イメージをtest flagで設定
    GRP=1, CMD=0, OP=Write
    CBOR: { "confirm": false, "hash": <image_hash> }

[4] Reset (Write)                       デバイスリセット → Bootloader起動 → Swap
    GRP=0, CMD=5, OP=Write
    CBOR: {}
```

## MTUとチャンク転送

BLE ATTのMTUはデフォルト23バイト（ペイロード20バイト）ですが、MTU交換ネゴシエーションで最大507バイトまで拡張できます。MTUが大きいほどDFU転送速度が向上します。

```
転送速度の計算例:
  イメージサイズ: 200KB = 204800 bytes
  MTU: 244 bytes → ペイロード: 244 - 3(ATTヘッダ) - 8(SMPヘッダ) ≈ 233 bytes
  チャンク数: 204800 / 233 ≈ 879 チャンク

  Connection Interval: 15ms（nRF52840デフォルト）
  1チャンクあたり 1〜2 Connectionインターバル
  転送時間 ≈ 879 × 2 × 15ms ≈ 26秒

  MTU=498 の場合:
  ペイロード ≈ 487 bytes → チャンク数 ≈ 420
  転送時間 ≈ 420 × 2 × 15ms ≈ 13秒（約2倍速）
```

## BLE SMPサービス

SMPはBLE上で専用のGATTサービスとして動作します。

| 項目 | 値 |
|---|---|
| SMP Service UUID | `8D53DC1D-1DB7-4CD3-868B-8A527460AA84` |
| SMP Characteristic UUID | `DA2E7828-FBCE-4E01-AE9E-261174997C48` |
| プロパティ | Write Without Response + Notify |

送信：Writeでデータを送る
受信：Notifyで応答を受け取る

SMPはATTペイロードに直接CBORエンコードされたフレームを乗せます。

## ファームウェア側の実装確認

`prj.conf` に以下が設定されていればSMPサービスは自動で有効化されます。

```kconfig
CONFIG_MCUMGR=y
CONFIG_MCUMGR_TRANSPORT_BT=y
CONFIG_MCUMGR_GRP_IMG=y
CONFIG_MCUMGR_GRP_OS=y
CONFIG_BT_SMP=n              # DFU専用: ペアリング不要
CONFIG_MCUMGR_TRANSPORT_BT_CONN_PARAM_CONTROL=y
```

iOSライブラリが接続してSMPフレームを送ると、Zephyrのmcumgrスタックが自動処理します。アプリ側でDFUコードを書く必要はありません。

---

**まとめ**

- SMPはCBORエンコードされたコマンドをBLE Write/Notifyで送受信するプロトコル
- DFU手順: Image List → Upload（分割）→ Image Test → Reset → Bootloader Swap
- MTUを大きくすると転送速度が向上（244→498 で約2倍）
- `CONFIG_MCUMGR_TRANSPORT_BT=y` だけでSMPサービスが有効になる
