## 6.4 ServiceとCharacteristicを定義する {#sec:ch6-custom-service}

接続できるだけでは、製品の状態を読んだり設定を変更したりできません。本節では、第4章で設計したGATTインターフェースを、ZephyrのAttributeテーブルとして定義します。

本章では、センサー付きライトを簡略化したDevice Control Serviceを使います。物理センサーとLEDは第7章で接続するため、値はまだソフトウェア上に保持します。

### 6.4.1 実装するGATTインターフェース

Device Control Serviceには、次のCharacteristicを置きます。

| Characteristic | 意味 | Properties | Value |
|---|---|---|---|
| LED State | 現在のLED状態 | Read、Notify | 1 byte、`0`: OFF、`1`: ON |
| Measurement Value | 現在の測定値 | Read、Notify | 符号付き16 bit、0.01単位 |
| Measurement Interval | 測定間隔 | Read、Write | 符号なし16 bit、ms |
| Command Request | 処理の依頼 | Write | Opcode、Request ID、Argument |
| Command Response | コマンドの完了結果 | Read、Notify | Opcode、Request ID、Status、Result |
| Device Event | 製品で発生した事実 | Notify | Event ID、Detail、Value |

: Device Control ServiceのCharacteristic {#tbl:ch6-device-control-characteristics}

状態と設定を分け、Command RequestとCommand Responseも分けます。Command RequestへのWrite Responseは、Valueを受け付けたというATT上の結果です。製品処理の完了は、後からCommand Responseで通知します。

### 6.4.2 128 bit UUIDを定義する

製品固有のServiceとCharacteristicには、独自の128 bit UUIDを使います。次の値は本書のサンプル用です。実製品では、プロジェクトで生成・管理するUUIDへ置き換えます。

`src/device_service.h`を作ります。

```c
#ifndef DEVICE_SERVICE_H_
#define DEVICE_SERVICE_H_

#include <stdint.h>
#include <zephyr/bluetooth/uuid.h>

#define BT_UUID_DEVICE_SERVICE_VAL \
    BT_UUID_128_ENCODE(0x7e57a000, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)
#define BT_UUID_LED_STATE_VAL \
    BT_UUID_128_ENCODE(0x7e57a001, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)
#define BT_UUID_MEASUREMENT_VAL \
    BT_UUID_128_ENCODE(0x7e57a002, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)
#define BT_UUID_MEASUREMENT_INTERVAL_VAL \
    BT_UUID_128_ENCODE(0x7e57a003, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)
#define BT_UUID_COMMAND_REQUEST_VAL \
    BT_UUID_128_ENCODE(0x7e57a004, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)
#define BT_UUID_COMMAND_RESPONSE_VAL \
    BT_UUID_128_ENCODE(0x7e57a005, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)
#define BT_UUID_DEVICE_EVENT_VAL \
    BT_UUID_128_ENCODE(0x7e57a006, 0x4c7a, 0x4f8a, 0x9f2c, 0x1d2e3f4a5b60)

#define BT_UUID_DEVICE_SERVICE \
    BT_UUID_DECLARE_128(BT_UUID_DEVICE_SERVICE_VAL)
#define BT_UUID_LED_STATE \
    BT_UUID_DECLARE_128(BT_UUID_LED_STATE_VAL)
#define BT_UUID_MEASUREMENT \
    BT_UUID_DECLARE_128(BT_UUID_MEASUREMENT_VAL)
#define BT_UUID_MEASUREMENT_INTERVAL \
    BT_UUID_DECLARE_128(BT_UUID_MEASUREMENT_INTERVAL_VAL)
#define BT_UUID_COMMAND_REQUEST \
    BT_UUID_DECLARE_128(BT_UUID_COMMAND_REQUEST_VAL)
#define BT_UUID_COMMAND_RESPONSE \
    BT_UUID_DECLARE_128(BT_UUID_COMMAND_RESPONSE_VAL)
#define BT_UUID_DEVICE_EVENT \
    BT_UUID_DECLARE_128(BT_UUID_DEVICE_EVENT_VAL)

int device_service_set_measurement(int16_t value);
int device_service_set_led_state(uint8_t value);

#endif
```

`BT_UUID_128_ENCODE()`には、人が読むUUIDの各フィールドを指定します。マクロは、BluetoothのValueへ格納するときに必要なバイト順へ変換します。UUIDの文字列表記を手で逆順に並べ替えないようにします。

### 6.4.3 ServiceをAttributeテーブルへ登録する

`src/device_service.c`では、`BT_GATT_SERVICE_DEFINE()`を使ってServiceを静的に登録します。まず、ServiceとLED Stateだけを定義した形を示します。

```c
#include <zephyr/bluetooth/gatt.h>
#include <zephyr/sys/byteorder.h>

#include "device_service.h"

static uint8_t led_state;

static ssize_t read_led_state(struct bt_conn *conn,
                              const struct bt_gatt_attr *attr,
                              void *buf, uint16_t len,
                              uint16_t offset)
{
    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             &led_state, sizeof(led_state));
}

static void led_state_ccc_changed(const struct bt_gatt_attr *attr,
                                  uint16_t value)
{
    /* 購読状態の変化は6.7節で扱う */
}

BT_GATT_SERVICE_DEFINE(device_service,
    BT_GATT_PRIMARY_SERVICE(BT_UUID_DEVICE_SERVICE),

    BT_GATT_CHARACTERISTIC(BT_UUID_LED_STATE,
        BT_GATT_CHRC_READ | BT_GATT_CHRC_NOTIFY,
        BT_GATT_PERM_READ,
        read_led_state, NULL, NULL),
    BT_GATT_CCC(led_state_ccc_changed,
                BT_GATT_PERM_READ | BT_GATT_PERM_WRITE)
);
```

このマクロから、少なくとも次のAttributeが作られます。

```text
Primary Service Declaration
└─ LED State Characteristic Declaration
   ├─ LED State Characteristic Value
   └─ Client Characteristic Configuration Descriptor
```

`BT_GATT_CHARACTERISTIC()`のPropertiesとPermissionは別の役割です。`BT_GATT_CHRC_READ`は、Characteristic Declarationを探索したクライアントへ「Readできる」と示します。`BT_GATT_PERM_READ`は、Value AttributeへのReadを実際に許可します。片方だけを設定しても、正しいGATTインターフェースにはなりません。

### 6.4.4 Service UUIDをアドバタイジングへ追加する

接続前に対象Serviceを持つPeripheralを絞り込めるよう、128 bit Service UUIDをAdvertising Dataへ追加します。

```c
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA_BYTES(BT_DATA_UUID128_ALL,
                  BT_UUID_DEVICE_SERVICE_VAL),
};
```

128 bit UUIDはAD Structureの多くを使います。Legacy Advertisingの31 byteには、Flags、128 bit UUID、完全な名前をすべて収められないことがあります。そのため、本書では名前をScan Response Dataへ置いています。

ビルド対象へ`device_service.c`を追加するため、`CMakeLists.txt`も変更します。

```cmake
target_sources(app PRIVATE
    src/main.c
    src/device_service.c
)
```

書き込み後、BLE汎用ツールから接続し、Device Control ServiceとLED Stateを探索します。Serviceが見つからない場合は、アドバタイジングではなく、接続後のService Discovery結果を確認します。Advertising DataへUUIDがあることと、ATTデータベースへServiceが登録されていることは別の事実です。
