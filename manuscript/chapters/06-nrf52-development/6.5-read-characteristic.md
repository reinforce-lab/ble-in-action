## 6.5 状態と設定をReadで公開する {#sec:ch6-read-characteristic}

GATT Clientが現在状態を取得する基本操作はReadです。Read Requestを受け取ると、ZephyrはCharacteristic Valueに登録したReadコールバックを呼びます。

コールバックは、製品内部の値をそのままCのメモリーから返す場所ではありません。GATTインターフェース仕様で決めた長さ、符号、単位、バイトオーダーへ変換し、要求された範囲を返します。

### 6.5.1 Readコールバックの引数を確認する

Readコールバックは次の形です。

```c
static ssize_t read_value(struct bt_conn *conn,
                          const struct bt_gatt_attr *attr,
                          void *buf, uint16_t len,
                          uint16_t offset);
```

| 引数 | 意味 |
|---|---|
| `conn` | Readを要求した接続 |
| `attr` | 対象のAttribute |
| `buf` | Valueを書き込むZephyr側のバッファー |
| `len` | 今回返せる最大長 |
| `offset` | Valueのどの位置から読むか |

戻り値は、`buf`へ書いたバイト数またはATT Errorです。Value全体が2 byteでも、`len`と`offset`を無視して`memcpy()`すると、Read Blobや小さな応答バッファーへ正しく対応できません。

`bt_gatt_attr_read()`は、Value全体の長さと`offset`を使い、今回返せる範囲を計算します。固定長Valueでも、このヘルパーを使うとReadの境界処理を共通化できます。

### 6.5.2 LED Stateを1 byteで返す

LED Stateは`0`または`1`の1 byteです。6.4節の`read_led_state()`では、内部値と通信上のValueが同じ形式なので、そのアドレスを渡せます。

```c
static ssize_t read_led_state(struct bt_conn *conn,
                              const struct bt_gatt_attr *attr,
                              void *buf, uint16_t len,
                              uint16_t offset)
{
    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             &led_state, sizeof(led_state));
}
```

第7章で実際のLEDを接続した後も、このValueはGPIOレジスターを直接読んだ値ではなく、製品が管理する現在状態として扱います。ハードウェア操作に失敗した場合に、要求値と実際の状態を区別できるためです。

### 6.5.3 16 bit Valueをリトルエンディアンへ変換する

Measurement Valueは、0.01単位の符号付き16 bit整数とします。たとえば`2356`は`23.56`を表します。Measurement Intervalは、ms単位の符号なし16 bit整数です。

```c
static int16_t measurement_value = 2356;
static uint16_t measurement_interval_ms = 1000;

static ssize_t read_measurement(struct bt_conn *conn,
                                const struct bt_gatt_attr *attr,
                                void *buf, uint16_t len,
                                uint16_t offset)
{
    uint8_t value[2];

    sys_put_le16((uint16_t)measurement_value, value);
    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             value, sizeof(value));
}

static ssize_t read_measurement_interval(struct bt_conn *conn,
                                         const struct bt_gatt_attr *attr,
                                         void *buf, uint16_t len,
                                         uint16_t offset)
{
    uint8_t value[2];

    sys_put_le16(measurement_interval_ms, value);
    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             value, sizeof(value));
}
```

`sys_put_le16()`を使い、CPU内部の表現から通信上のリトルエンディアンへ明示的に変換します。nRF52840もリトルエンディアンですが、Cの変数をそのまま送るコードでは、Value形式を実装していることが読み取りにくくなります。変換処理を置くことで、通信仕様との対応が明確になります。

### 6.5.4 CharacteristicをServiceへ追加する

6.4節の`BT_GATT_SERVICE_DEFINE()`へ、Measurement ValueとMeasurement Intervalを追加します。

```c
BT_GATT_CHARACTERISTIC(BT_UUID_MEASUREMENT,
    BT_GATT_CHRC_READ | BT_GATT_CHRC_NOTIFY,
    BT_GATT_PERM_READ,
    read_measurement, NULL, NULL),
BT_GATT_CCC(measurement_ccc_changed,
            BT_GATT_PERM_READ | BT_GATT_PERM_WRITE),

BT_GATT_CHARACTERISTIC(BT_UUID_MEASUREMENT_INTERVAL,
    BT_GATT_CHRC_READ | BT_GATT_CHRC_WRITE,
    BT_GATT_PERM_READ | BT_GATT_PERM_WRITE,
    read_measurement_interval,
    write_measurement_interval, NULL),
```

この時点では、`measurement_ccc_changed()`と`write_measurement_interval()`を後続節で定義します。コードを節ごとに入力する場合は、関数プロトタイプをService定義より前へ置くか、6.6節・6.7節まで進んでからビルドします。

### 6.5.5 BLE汎用ツールでValueを読む

接続してService Discoveryを行い、次を確認します。

- LED Stateは1 byteの`00`として読める
- Measurement Valueは`34 09`として読める
- `0x0934`を10進数にすると`2356`になり、0.01単位では`23.56`になる
- Measurement Intervalは`E8 03`として読める
- `0x03E8`は`1000 ms`です

BLE汎用ツールは、カスタムCharacteristicの意味を知りません。多くの場合、Valueは16進数のバイト列として表示されます。ファームウェアとクライアントが同じ仕様を使って、符号、バイトオーダー、単位を解釈する必要があります。

Readで取得できるのは、要求を処理した時点のValueです。値が変わるたびにクライアントへ知らせるにはNotifyを使います。その前に次節で、設定変更とコマンド要求をWriteで受け取ります。
