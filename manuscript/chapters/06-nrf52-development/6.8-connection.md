## 6.8 接続、切断、CCCDを管理する {#sec:ch6-connection-management}

GATTのValueだけでなく、接続の開始と終了も製品の状態です。接続中だけ必要な処理を開始し、切断時に止め、次のCentralが接続できるようアドバタイジングを再開します。

本節では接続コールバックを登録し、章内で作ったGATTインターフェースをBLE汎用ツールから一周させます。

### 6.8.1 アドバタイジング開始を関数に分ける

起動時と切断時の両方から呼べるよう、アドバタイジング開始処理を関数にします。

```c
static int start_advertising(void)
{
    int err;

    err = bt_le_adv_start(BT_LE_ADV_CONN_FAST_1,
                          ad, ARRAY_SIZE(ad),
                          sd, ARRAY_SIZE(sd));
    if (err) {
        LOG_ERR("Advertising start failed: %d", err);
        return err;
    }

    LOG_INF("Advertising started");
    return 0;
}
```

一つの接続を受け付けると、接続に使ったLegacy Advertisingは停止します。切断しただけでは、アプリケーションが開始したAdvertising Setが自動的に元へ戻るとは限りません。本書のサンプルでは、切断コールバックから明示的に再開します。

### 6.8.2 接続コールバックを登録する

`BT_CONN_CB_DEFINE()`を使うと、接続コールバックを静的に登録できます。

```c
#include <zephyr/bluetooth/conn.h>

static void connected(struct bt_conn *conn, uint8_t err)
{
    char address[BT_ADDR_LE_STR_LEN];

    bt_addr_le_to_str(bt_conn_get_dst(conn),
                      address, sizeof(address));

    if (err) {
        LOG_WRN("Connection to %s failed: 0x%02x",
                address, err);
        start_advertising();
        return;
    }

    LOG_INF("Connected: %s", address);
}

static void disconnected(struct bt_conn *conn, uint8_t reason)
{
    char address[BT_ADDR_LE_STR_LEN];

    bt_addr_le_to_str(bt_conn_get_dst(conn),
                      address, sizeof(address));
    LOG_INF("Disconnected: %s, reason 0x%02x",
            address, reason);

    start_advertising();
}

BT_CONN_CB_DEFINE(connection_callbacks) = {
    .connected = connected,
    .disconnected = disconnected,
};
```

接続失敗時の`err`と、切断時の`reason`はBluetoothのStatus／Reason Codeです。アプリケーション独自のエラー番号として解釈しません。第7章では、ログの時刻と接続パケットを対応づけて原因を調べます。

コールバック内ではログと短い状態更新だけを行います。接続時にService探索を待つ、センサーを同期的に初期化する、Flashへ大量に書くなどの処理は、Work Queueまたは製品ロジックのスレッドへ渡します。

### 6.8.3 main()でBluetoothを起動する

`main.c`の初期化経路は次のようになります。

```c
int main(void)
{
    int err;

    err = bt_enable(NULL);
    if (err) {
        LOG_ERR("Bluetooth initialization failed: %d", err);
        return 0;
    }

    LOG_INF("Bluetooth initialized");

    err = start_advertising();
    if (err) {
        return 0;
    }

    k_sleep(K_FOREVER);
    return 0;
}
```

`BT_GATT_SERVICE_DEFINE()`で作ったServiceは静的に登録されるため、`main()`から登録関数を呼んでいません。動的にServiceを追加・削除する設計では、登録時期、接続中の変更、クライアント側のキャッシュを別に考える必要があります。

### 6.8.4 CCCDの有効期間を理解する

Notifyを購読すると、Zephyrは接続ごとのCCCD状態を保持します。Bondingを使わない本章の構成では、切断後の新しい接続でクライアントが改めて購読します。

```text
接続
  ↓
Service Discovery
  ↓
CCCDへNotify有効を書き込む
  ↓
Notificationを受信
  ↓
切断
  ↓
次の接続で再び探索・購読
```

Bonded DeviceについてCCCDを永続化する構成もありますが、セキュリティ、Settings Subsystem、GATTキャッシュを含む設計になります。本章では暗号化やBondingを必須にせず、接続ごとのGATT操作を先に確認します。所有権とセキュリティは第10章で扱います。

### 6.8.5 一連の操作を確認する

ファームウェアを書き込み、BLE汎用ツールから次の順で操作します。

1. `BLE In Action`をスキャンする
2. Advertising DataにDevice Control ServiceのUUIDがあることを確認する
3. 接続する
4. Device Control Serviceを探索する
5. LED State、Measurement Value、Measurement IntervalをReadする
6. LED State、Measurement Value、Command Response、Device EventのNotifyを有効にする
7. Measurement Intervalへ`D0 07`を書き、`2000 ms`に変更する
8. Command Requestへ`01 2A 01 00`を書き、LED状態変更を要求する
9. LED Stateの`01`と、Request ID `2A`を持つCommand Responseを受信する
10. 切断する
11. 再びスキャンでき、再接続できることを確認する

不具合がある場合は、最後まで一度に追いません。

| 症状 | 最初に確認する境界 |
|---|---|
| スキャンに表示されない | Advertising開始ログ、Advertising Data |
| 接続できない | 接続可能Parameters、接続失敗Status |
| Serviceが見えない | Service登録、Service Discovery、キャッシュ |
| Readできない | Properties、Permission、Readコールバック |
| Writeが失敗する | 長さ、offset、値範囲、ATT Error |
| Notifyが来ない | CCCD、Value Attribute、購読後の状態変化 |
| 再接続できない | 切断コールバック、Advertising再開結果 |

: GATTペリフェラルの切り分け入口 {#tbl:ch6-peripheral-troubleshooting}

この確認によって、ログ上の関数呼び出しだけでなく、別の機器からGATTインターフェースを操作できるところまで到達します。
