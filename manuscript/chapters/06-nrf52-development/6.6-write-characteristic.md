## 6.6 設定とコマンドをWriteで受け取る {#sec:ch6-write-characteristic}

Writeは、クライアントからサーバーへValueを渡す操作です。ただし、Measurement Intervalのような設定と、測定開始のようなコマンドでは、Write後の意味が異なります。

設定は、妥当なValueを受け付けた時点で現在値を更新できます。コマンドは、Writeを受け付けた後に時間のかかる処理が続く場合があります。Writeコールバックの中で処理を完了させようとせず、受付と完了を分けます。

### 6.6.1 Writeコールバックで境界を検査する

Writeコールバックは次の形です。

```c
static ssize_t write_value(struct bt_conn *conn,
                           const struct bt_gatt_attr *attr,
                           const void *buf, uint16_t len,
                           uint16_t offset, uint8_t flags);
```

コールバックへ渡された`buf`を読む前に、少なくとも次を確認します。

- この実装が対応しない`offset`ではないか
- `len`が仕様どおりか
- 値が許容範囲内か
- 現在の製品状態で受け付けられるか
- Write RequestとWrite Commandのどちらを許すか

不正な入力は、内部状態を変更する前にATT Errorとして返します。

### 6.6.2 Measurement Intervalを更新する

Measurement Intervalは2 byteのリトルエンディアンで、100〜60,000 msを許可します。

```c
static ssize_t write_measurement_interval(
    struct bt_conn *conn,
    const struct bt_gatt_attr *attr,
    const void *buf, uint16_t len,
    uint16_t offset, uint8_t flags)
{
    uint16_t value;

    if (offset != 0U) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_OFFSET);
    }

    if (len != sizeof(uint16_t)) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_ATTRIBUTE_LEN);
    }

    value = sys_get_le16(buf);
    if (value < 100U || value > 60000U) {
        return BT_GATT_ERR(BT_ATT_ERR_VALUE_NOT_ALLOWED);
    }

    measurement_interval_ms = value;
    LOG_INF("Measurement interval: %u ms", value);
    return len;
}
```

`sys_get_le16()`は、通信上の2 byteからCPU内部の`uint16_t`へ変換します。長さを確認する前に呼び出してはいけません。

Characteristicには`BT_GATT_CHRC_WRITE`を指定しているため、本書のクライアントはWrite Requestを使います。Write RequestへのWrite Responseは、設定値を受け付けて反映したことを示せます。

Write Without Responseを許可する場合は、Propertiesへ`BT_GATT_CHRC_WRITE_WITHOUT_RESP`を追加します。しかし、クライアントにはATT上の受付結果が返りません。設定やコマンドの再送、順序、エラー通知を製品仕様で補う必要があります。

### 6.6.3 Command RequestのValue形式を決める

本章のCommand Requestは4 byteとします。

| Offset | 長さ | フィールド | 意味 |
|---:|---:|---|---|
| 0 | 1 byte | Opcode | `1`: LED状態変更、`2`: 即時測定 |
| 1 | 1 byte | Request ID | RequestとResponseを対応づける番号 |
| 2 | 2 byte | Argument | Opcodeごとの引数、リトルエンディアン |

: Command RequestのValue形式 {#tbl:ch6-command-request-value}

LED状態変更ではArgumentの`0`をOFF、`1`をONとします。即時測定ではArgumentを予約値`0`とします。

### 6.6.4 コマンドをWork Queueへ渡す

WriteコールバックではValueを検査し、処理要求を保存してWork Queueへ渡します。

```c
#include <zephyr/kernel.h>
#include <zephyr/sys/atomic.h>

struct command_request {
    uint8_t opcode;
    uint8_t request_id;
    uint16_t argument;
};

static struct command_request pending_command;
static atomic_t command_pending;

static void command_work_handler(struct k_work *work);
K_WORK_DEFINE(command_work, command_work_handler);

static ssize_t write_command_request(
    struct bt_conn *conn,
    const struct bt_gatt_attr *attr,
    const void *buf, uint16_t len,
    uint16_t offset, uint8_t flags)
{
    const uint8_t *value = buf;
    struct command_request request;

    if (offset != 0U) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_OFFSET);
    }

    if (len != 4U) {
        return BT_GATT_ERR(BT_ATT_ERR_INVALID_ATTRIBUTE_LEN);
    }

    request.opcode = value[0];
    request.request_id = value[1];
    request.argument = sys_get_le16(&value[2]);

    if (request.opcode < 1U || request.opcode > 2U) {
        return BT_GATT_ERR(BT_ATT_ERR_VALUE_NOT_ALLOWED);
    }

    if (request.opcode == 1U && request.argument > 1U) {
        return BT_GATT_ERR(BT_ATT_ERR_VALUE_NOT_ALLOWED);
    }

    if (!atomic_cas(&command_pending, 0, 1)) {
        return BT_GATT_ERR(BT_ATT_ERR_UNLIKELY);
    }

    pending_command = request;
    k_work_submit(&command_work);
    return len;
}
```

`atomic_cas()`によって、未処理のコマンドがある間は次の要求を受け付けない簡単な実装にしています。実製品ではキューへ複数要求を積む、同じRequest IDの再送を検出する、優先度を設けるなどの方針が必要です。

`return len`の時点では、コマンド処理は完了していません。Write Responseが示すのは、Value形式と現在状態を確認し、処理キューへ受け付けたことです。

### 6.6.5 Command RequestをServiceへ追加する

CharacteristicをService定義へ追加します。

```c
BT_GATT_CHARACTERISTIC(BT_UUID_COMMAND_REQUEST,
    BT_GATT_CHRC_WRITE,
    BT_GATT_PERM_WRITE,
    NULL, write_command_request, NULL),
```

BLE汎用ツールから、次のValueを書き込みます。

```text
01 2A 01 00
```

これはOpcode `1`、Request ID `0x2A`、Argument `1`です。コールバックが受け付ければWrite Requestは成功します。ただし、LED StateとCommand Responseはまだ通知されません。次節で、製品側から状態変化と完了結果を送ります。
