## 6.2 最初のアドバタイジング {#sec:ch6-first-advertising}

Hello Worldでは、ファームウェアの実行をログから確認しました。次はBluetoothスタックを有効にし、外部のスマートフォンから電波上の結果を確認します。

本節では接続とGATT Serviceをまだ実装しません。非接続のアドバタイジングを送信し、SDKの設定、Bluetooth API、Advertising Dataが第2章・第3章の内容へどう対応するかを確認します。

### 6.2.1 Bluetoothを有効にする

プロジェクトの`prj.conf`を次のようにします。

```kconfig
CONFIG_BT=y
CONFIG_BT_BROADCASTER=y
CONFIG_BT_DEVICE_NAME="BLE In Action"

CONFIG_LOG=y
```

`CONFIG_BT=y`はZephyrのBluetooth機能を有効にします。`CONFIG_BT_BROADCASTER=y`は、Broadcasterとしてアドバタイジングを送信する機能を選びます。

接続可能なPeripheralは次節以降で作るため、ここでは`CONFIG_BT_PERIPHERAL`を使いません。設定名からも、アドバタイジングを送ることと、接続を受け付けることが別の機能だと分かります。

### 6.2.2 Advertising Dataを定義する

`main.c`を次のようにします。

```c
#include <zephyr/bluetooth/bluetooth.h>
#include <zephyr/bluetooth/hci.h>
#include <zephyr/kernel.h>
#include <zephyr/logging/log.h>
#include <zephyr/sys/util.h>

LOG_MODULE_REGISTER(main, LOG_LEVEL_INF);

static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA(BT_DATA_NAME_COMPLETE,
            CONFIG_BT_DEVICE_NAME,
            sizeof(CONFIG_BT_DEVICE_NAME) - 1),
};

int main(void)
{
    int err;

    err = bt_enable(NULL);
    if (err) {
        LOG_ERR("Bluetooth initialization failed: %d", err);
        return 0;
    }

    err = bt_le_adv_start(BT_LE_ADV_NCONN,
                          ad, ARRAY_SIZE(ad),
                          NULL, 0);
    if (err) {
        LOG_ERR("Advertising start failed: %d", err);
        return 0;
    }

    LOG_INF("Advertising started");
    k_sleep(K_FOREVER);
    return 0;
}
```

`bt_enable()`はBluetoothサブシステムを初期化します。成功後に`bt_le_adv_start()`を呼び、アドバタイジングを開始します。

`BT_LE_ADV_NCONN`は、接続を受け付けないAdvertising Parametersを選びます。スマートフォンから名前は見えますが、接続はできません。

### 6.2.3 SDKの構造体と電波上のデータを対応づける

`struct bt_data`は、Advertising DataのAD Structureを表します。`BT_DATA_BYTES`と`BT_DATA`は、AD TypeとValueを組み合わせます。

```text
AD Structure
┌─────────────┬───────────┬──────────────┐
│ Length      │ AD Type   │ AD Data      │
└─────────────┴───────────┴──────────────┘
```

最初の要素はFlagsです。

```c
BT_DATA_BYTES(BT_DATA_FLAGS,
              BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR)
```

`BT_LE_AD_GENERAL`はGeneral Discoverable Mode、`BT_LE_AD_NO_BREDR`はBR/EDRをサポートしないことを表します。

二つ目の要素はComplete Local Nameです。

```c
BT_DATA(BT_DATA_NAME_COMPLETE,
        CONFIG_BT_DEVICE_NAME,
        sizeof(CONFIG_BT_DEVICE_NAME) - 1)
```

`CONFIG_BT_DEVICE_NAME`の文字列がAdvertising Dataへ入ります。Kconfigの設定、Cの構造体、電波上のAD Structureが一つにつながります。

### 6.2.4 ビルドして観測する

Hello Worldと同じボードを指定してビルドし、書き込みます。

```bash
west build -b nrf52840dk/nrf52840 --pristine
west flash
```

Bluetoothを新たに有効にしたため、ここでは`--pristine`を付け、以前のCMakeとKconfigの生成結果を作り直します。

ログに次が表示されることを確認します。

```text
Advertising started
```

次に、スマートフォンのBLE汎用ツールでスキャンします。`BLE In Action`という名前とRSSIが表示されれば、アドバタイジングを受信できています。

確認できる経路は次のようになります。

```text
prj.conf
  CONFIG_BT_DEVICE_NAME
        ↓
main.c
  struct bt_data
        ↓
Zephyr Bluetooth Host／Controller
        ↓
nRF52840の無線回路
        ↓
Advertising PDU
        ↓
スマートフォンのスキャン結果
```

ログに`Advertising started`と出ても、スマートフォンから見えるとは限りません。Advertising Dataが期待どおりでない、アンテナや電源に問題がある、スマートフォン側でスキャンしていないなど、無線上の観測までに別の段階があります。ログと外部観測の両方を確認します。

開発ループと最小の電波送信を確認できました。次節では、このアドバタイジングを接続可能にし、第4章で設計したGATT Service、Characteristic、Read、Write、Notifyの実装へ進みます。
