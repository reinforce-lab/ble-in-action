## スキャンの実行

Bluetoothが `.poweredOn` になったら、`scanForPeripherals(withServices:options:)` を呼んでスキャンを開始します。

```swift
private func startScanning() {
    // 第6章で定義したカスタムサービスUUID
    let targetServiceUUID = CBUUID(string: "12345678-1234-5678-1234-56789ABCDEF0")

    centralManager.scanForPeripherals(
        withServices: [targetServiceUUID],   // サービスでフィルタリング
        options: [
            CBCentralManagerScanOptionAllowDuplicatesKey: false
        ]
    )
    print("スキャン開始: \(targetServiceUUID)")
}
```

### withServices: 引数の重要性

`withServices` に `nil` を渡すと、周囲の **すべての** BLEデバイスが発見されます。実装中のデバッグには便利ですが、本番コードでは **必ず対象サービスのUUIDを指定** します。

理由は2つあります。

1. **消費電力**: 不要なデバイスを発見するたびにデリゲートが呼ばれ、処理コストがかかる
2. **バックグラウンド動作**: `withServices: nil` ではバックグラウンドスキャンが動作しない（[@sec:background]参照）

```swift
// ❌ 開発時のみ。本番では使わない
centralManager.scanForPeripherals(withServices: nil, options: nil)

// ✅ 本番コード
centralManager.scanForPeripherals(withServices: [myServiceUUID], options: nil)
```

### AllowDuplicatesKey オプション

| 値 | 動作 |
|---|---|
| `false`（デフォルト）| 同一デバイスの最初のアドバタイズを1回だけ通知 |
| `true` | アドバタイズを受信するたびに通知（RSSI監視・変化するアドバタイズデータの取得に使う） |

`true` にするとデリゲートが高頻度で呼ばれるため、CPU・電力消費が増えます。位置ビーコンの距離推定など特定の用途以外では `false` を使います。


## 発見イベント: didDiscoverPeripheral

スキャン中にフィルタ条件に合うデバイスを発見すると `centralManager(_:didDiscover:advertisementData:rssi:)` が呼ばれます。

```swift
func centralManager(
    _ central: CBCentralManager,
    didDiscover peripheral: CBPeripheral,
    advertisementData: [String: Any],
    rssi RSSI: NSNumber
) {
    // ローカル名を取得
    let localName = advertisementData[CBAdvertisementDataLocalNameKey] as? String ?? "不明"
    print("発見: \(localName) RSSI: \(RSSI) dBm")

    // 接続対象かを判定して接続
    if localName == "BLEInAction_Sensor" {
        self.peripheral = peripheral  // 必ずインスタンス変数で保持
        centralManager.stopScan()     // 発見したらスキャン停止
        centralManager.connect(peripheral, options: nil)
    }
}
```

**ポイント**: 発見した `CBPeripheral` は **インスタンス変数で保持** しなければなりません。`CBCentralManager` はペリフェラルへの参照を保持しないため、インスタンス変数で保持しないとARC（自動参照カウント）によって解放され、接続が即座に切断されます。


## アドバタイズメントデータの解析

`advertisementData` 辞書のキーと内容は次のとおりです。

| キー定数 | 型 | 内容 |
|---|---|---|
| `CBAdvertisementDataLocalNameKey` | `String` | デバイスのローカル名 |
| `CBAdvertisementDataServiceUUIDsKey` | `[CBUUID]` | アドバタイズされたサービスUUID |
| `CBAdvertisementDataManufacturerDataKey` | `Data` | メーカー固有データ（先头2バイトがCompany ID）|
| `CBAdvertisementDataTxPowerLevelKey` | `NSNumber` | 送信電力 dBm |
| `CBAdvertisementDataServiceDataKey` | `[CBUUID: Data]` | サービス別のdata |
| `CBAdvertisementDataIsConnectable` | `NSNumber` (Bool) | 接続可否フラグ |

### アドバタイズデータの解析例（メーカー固有データ）

```swift
if let manufacturerData = advertisementData[CBAdvertisementDataManufacturerDataKey] as? Data {
    // 先頭2バイト: Company ID (little-endian)
    let companyID = UInt16(manufacturerData[0]) | (UInt16(manufacturerData[1]) << 8)
    // 残りがペイロード
    let payload = manufacturerData.dropFirst(2)
    print("Company ID: 0x\(String(companyID, radix: 16)) payload: \(payload.hex)")
}
```


## RSSIによる距離推定

`RSSI` はアドバタイズパケットの受信信号強度（dBm）です。値はマイナスで、絶対値が小さいほど強い信号（近距離）を示します。

```
-30 dBm  : 非常に近い（数十 cm 以内）
-60 dBm  : 近い（1-2 m）
-80 dBm  : 中程度（3-5 m）
-100 dBm : 遠い（5 m 以上 / 壁や障害物あり）
```

距離の推定式（Appleの推奨モデル）:

$$d = 10^{\frac{TxPower - RSSI}{10n}}$$

- $TxPower$: 1m地点での基準RSSI（ペリフェラルの送信電力アドバタイズから取得）
- $RSSI$: 計測された受信信号強度
- $n$: 環境係数（自由空間 = 2、建屋内 = 2〜4）

**注意**: RSSIは電波の多重反射・遮蔽物・ペリフェラルの向きなどで大きく変動します。距離推定の精度は高くなく、おおよその近遠の判断にとどめます。


## スキャンのライフサイクル管理

スキャンの開始と停止はアプリのライフサイクルに合わせて管理します。

```swift
// アプリがフォアグラウンドになったとき
func applicationDidBecomeActive() {
    if centralManager.state == .poweredOn {
        startScanning()
    }
}

// 接続成功したとき（既出）
func centralManager(_ central: CBCentralManager, didConnect peripheral: CBPeripheral) {
    central.stopScan()  // 接続済みなのでスキャン停止
}

// アプリがバックグラウンドになるとき
func applicationDidEnterBackground() {
    // バックグラウンドモード未設定の場合、スキャンは自動停止する
    // バックグラウンドモード設定済みの場合はスキャン継続（9.7節）
}
```

`stopScan()` を呼ぶまでスキャンは継続します。不要なスキャンは電力を消費するため、接続が確立したら速やかに停止してください。


## 複数デバイスのスキャン

複数のペリフェラルを同時に管理する場合は、発見したペリフェラルを配列や辞書で管理します。

```swift
var discoveredPeripherals: [UUID: CBPeripheral] = [:]

func centralManager(
    _ central: CBCentralManager,
    didDiscover peripheral: CBPeripheral,
    advertisementData: [String: Any],
    rssi RSSI: NSNumber
) {
    let uuid = peripheral.identifier
    if discoveredPeripherals[uuid] == nil {
        discoveredPeripherals[uuid] = peripheral
        print("新規デバイス発見: \(peripheral.name ?? uuid.uuidString)")
    }
}
```

`CBPeripheral.identifier` はiOSがデバイスに割り当てる UUID（UUIDType）で、実際のBLEアドレスとは異なります。同じデバイスでも異なるiOSデバイスからは異なる `identifier` が割り当てられることがあります。ただし、同一iOSデバイスからは再接続時も同じ `identifier` が維持されます（ペリフェラルの再接続に活用できます）。


**まとめ**

- `scanForPeripherals(withServices:options:)` は **対象サービスUUIDを指定** して呼ぶ
- `AllowDuplicatesKey: true` はRSSI監視や変化するアドバタイズデータの取得に使う
- 発見した `CBPeripheral` は必ずインスタンス変数で保持する（解放されると接続断）
- RSSIは目安程度の距離推定。環境ノイズに敏感なため精度は低い
- 接続成功後は `stopScan()` を忘れずに呼ぶ
