## アドバタイズパケットの解析

Wiresharkでアドバタイズパケットをクリックすると詳細が表示されます。

```
Bluetooth Low Energy Link Layer
├─ Access Address: 0x8e89bed6 (Advertising)
├─ Packet Header
│   ├─ PDU Type: ADV_IND (0x0)     ← コネクタブル・無指向アドバタイズ
│   └─ Length: 26
├─ Advertising Address: c0:26:da:xx:xx:xx (random)
└─ Advertising Data
    ├─ Length: 2, Type: Flags (0x01)
    │   └─ LE General Discoverable Mode
    ├─ Length: 17, Type: Complete UUID-128 bit (0x07)
    │   └─ UUID128: 12345678-1234-5678-1234-56789abcdef0
    └─ Length: 5, Type: Complete Local Name (0x09)
        └─ BLEInAction_Sensor
```

確認ポイント：
- `PDU Type` が `ADV_IND` または `ADV_NONCONN_IND` か
- アドバタイズしているサービスUUIDが正しいか
- デバイス名が正しいか

## ATT PDU の読み方

パケット一つを展開すると以下のように見えます。

### Write Request（しきい値の書き込み）

```
Bluetooth Attribute Protocol
├─ Opcode: Write Request (0x12)
├─ Handle: 0x0017 (Threshold Characteristic Value)
└─ Value: dc 09
            ^^ ^^
            0x09DC = 2524 → 25.24°C (little-endian)
```

### Handle Value Notification（Notify受信）

```
Bluetooth Attribute Protocol
├─ Opcode: Handle Value Notification (0x1b)
├─ Handle: 0x0014 (Temp/Hum Characteristic Value)
└─ Value: 9c 09 8c 1b
            ^^^^^ ^^^^^
            0x099C = 2460 → 24.60°C
                   0x1B8C = 7052 → 70.52%
```


## 接続パラメータの確認

```
LL Control Opcode: LL_CONNECTION_UPDATE_IND
├─ Win Size: 1 (1.25ms)
├─ Win Offset: 3 (3.75ms)
├─ Interval: 24 (30ms)
├─ Latency: 0
└─ Timeout: 400 (4000ms = 4s)
```

`Interval=24` → 24 × 1.25ms = 30ms のConnection Intervalです。消費電力とレスポンスのバランスを確認できます。


## 有用なWiresharkフィルタ集

```
# ATT WriteのCCCDのみ（Notify有効化の確認）
btatt.opcode == 0x12 && btatt.handle == 0x001b

# Notifyパケットのみ
btatt.opcode == 0x1b

# LL層のコントロールパケット（接続パラメータ更新など）
btle.data_header.llid == 0x3

# エラーレスポンス
btatt.opcode == 0x01

# MTU交換
btatt.opcode == 0x02 || btatt.opcode == 0x03
```


**まとめ**

- アドバタイズパケットでUUID・デバイス名・PDUタイプを確認する
- 接続フロー: CONNECT_IND → MTU交換 → サービス発見 → CCCD書き込み → Notify
- ATT PDUのOpcodeでRead/Write/Notifyを識別できる
- フィルタ `btatt.opcode == 0x1b` でNotifyパケットだけ絞り込める
