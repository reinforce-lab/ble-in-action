## HCI Snoop ログとは

AndroidはBluetooth HCIレベルのログを `.log` ファイルに記録できます。このログをWiresharkで開くことで、iOSのPacketLoggerと同等の解析が可能です。

---

## 有効化手順

```
1. 設定 → 端末情報 → ビルド番号を7回タップ → 開発者オプションが有効化

2. 設定 → 開発者向けオプション:
   [Bluetooth HCIスヌープログを有効にする] → ON

3. Bluetoothをオフ → オンに切り替えて、ログ記録を再開させる

4. デバッグしたいBLE操作を実行

5. ログファイルを取り出す:
   adb pull /data/misc/bluetooth/logs/btsnoop_hci.log ./btsnoop_hci.log
   # または
   adb bugreport bugreport.zip  # ログが含まれるバグレポート
```

---

## Wiresharkでの解析

```
1. Wireshark を起動
2. File → Open → btsnoop_hci.log を選択
3. Wiresharkが自動でBTSNOOP形式として認識

表示フィルタの例:
  btatt                          → ATTプロトコル全般
  btatt.opcode == 0x1b           → Notify パケット
  btsmp                          → Security Manager (ペアリング)
  btlcp                          → リンク制御
```

## Logcat でのBLEデバッグ

HCI Snoopに加え、Androidの `Logcat` で `BluetoothGattCallback` のコールバックをリアルタイムに確認します。

```bash
# BLEタグのみのログをリアルタイム表示
adb logcat -s BLE:D BluetoothGattCallback:D

# アプリのBLEログ全体（タグに "BLE" を含む）
adb logcat | grep -i bluetooth

# Androidシステムのbluetoothログ
adb logcat -s bt_btif:D bt_hci:D
```

## よくあるAndroid BLE問題と診断

### 問題: GATT_ERROR 133 の原因調査

```
Logcatで確認:
D BluetoothGatt: onClientConnectionState() - status=133 clientIf=5 comm=true addr=C0:26:DA:xx

HCI Snoopで確認:
  HCI Event: LE Meta → LE Connection Complete
    Status: 0x08 (Connection Timeout)  ← 133の原因の一つ
```

`Status: 0x08` はRF環境の問題か、接続試行タイムアウトです。デバイスを近づけて再試行してください。

### 問題: CCCD書き込みが失敗する

```
Wiresharkで確認:
  ATT Write Request:  Handle=0x001B Value=0100 (Notify ON)
  ATT Error Response: Opcode=0x12 Handle=0x001B Error=0x02 (Read Not Permitted)

原因: ファームウェアの CCCD 属性に PERM_WRITE が設定されていない
修正: BT_GATT_PERM_READ | BT_GATT_PERM_WRITE を確認
```

## ログサイズと管理

HCI Snoop ログはBluetooth操作が多いと数十MBになります。

```bash
# 現在のログサイズ確認
adb shell ls -lh /data/misc/bluetooth/logs/

# ログのクリア（Bluetoothを再起動）
adb shell am broadcast -a android.bluetooth.adapter.action.REQUEST_DISABLE
adb shell am broadcast -a android.bluetooth.adapter.action.REQUEST_ENABLE
```

**まとめ**

- 開発者オプションの「Bluetooth HCIスヌープログ」で HCI ログを記録
- `adb pull` でPC に取り出し、Wireshark で開いて解析
- `btatt.opcode == 0x1b` でNotifyのみを絞り込める
- GATT_ERROR 133はHCIレベルの `LE Connection Complete Status` で原因を特定
