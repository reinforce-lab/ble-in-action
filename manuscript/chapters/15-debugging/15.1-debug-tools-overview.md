## BLEデバッグのレイヤー

BLEの問題は複数のレイヤーで発生します。どのレイヤーで問題が起きているかを特定することがデバッグの第一歩です。

```
┌─────────────────────────────────────────────────────────────────┐
│  アプリ層    │ デバッグ: Xcode logs, Android Logcat              │
│  GATTサービス │ デバッグ: Wireshark (ATT PDU)                    │
│  ATT/L2CAP  │ デバッグ: Wireshark, iOS PacketLogger             │
│  HCI         │ デバッグ: Android HCI Snoop, iOS PacketLogger    │
│  リンク層    │ デバッグ: nRF Sniffer + Wireshark                 │
│  物理層      │ デバッグ: スペクトルアナライザ（高コスト）           │
└─────────────────────────────────────────────────────────────────┘
```

## ツール比較

| ツール | プラットフォーム | 見えるもの | 難易度 | 費用 |
|---|---|---|---|---|
| **nRF Sniffer + Wireshark** | PC | 全レイヤー | 中 | nRF52840 DK必要 |
| **iOS PacketLogger** | macOS + iPhone | HCI以上 | 低 | 無料（Apple Developer） |
| **Android HCI Snoop Log** | Android | HCI以上 | 低 | 無料（開発者オプション） |
| **Wireshark (Bluetooth)** | PC | HCI/ATT | 中 | 無料 |
| **nRF Connect App** | iOS/Android | GATT | 低 | 無料 |
| **BTLEJuice / BTLE-Sniffer** | macOS | ATT | 中 | 無料 |

開発フローでは「まず **nRF Connect App** で接続・操作を確認 → 問題があれば **Wireshark** でパケット解析」が効率的です。

## nRF Connect モバイルアプリ

**nRF Connect for Mobile**（iOS/Android、無料）はGATTサービスを視覚的に操作できる強力なデバッグツールです。

- アドバタイジングパケットのデコード表示
- サービス・キャラクタリスティクス・デスクリプタの一覧
- Read/Write/Notify の手動操作
- RSSI・接続パラメータのリアルタイム表示

ファームウェアを書いたら最初にnRF Connectで接続して動作確認することを強くお勧めします。

## パケットキャプチャが必要なとき

以下の症状が出た場合はパケットレベルの確認が必要です。

| 症状 | 確認すべきレイヤー |
|---|---|
| そもそも接続できない | リンク層・アドバタイズ |
| 接続してもサービスが見つからない | GATT（ATT PDU） |
| Notifyが届かない | ATT（CCCD書き込みの有無） |
| 接続が頻繁に切れる | LL（Connection Event, Supervision Timeout） |
| DFU転送が途中で失敗 | ATT・HCI（MTU、フロー制御） |

- BLEデバッグはレイヤー別のツールを使い分ける
- まず nRF Connect App でGATT操作を確認
- 接続・ATTレベルの問題は nRF Sniffer + Wireshark
- iOS/Android 内部ログは PacketLogger / HCI Snoop で取得
