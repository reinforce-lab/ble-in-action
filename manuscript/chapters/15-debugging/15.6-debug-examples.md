## 実例1: 「接続できない」

### 症状
iOSアプリでスキャンしてもデバイスが見つからない。

### デバッグ手順

```
Step 1: nRF Connect アプリでスキャン
→ デバイスが表示されない

Step 2: Wireshark + nRF Sniffer でアドバタイズ確認
→ パケット一覧に "BLEInAction_Sensor" が現れない

Step 3: nRF52840のシリアルログ確認
[00:00:00.001] I: Advertising started
→ アドバタイズ開始ログが出ていない

Step 4: main.c のbt_le_adv_start() 戻り値確認
→ err = -12 (ENOMEM) が出ていた

原因: prj.conf に CONFIG_BT_MAX_CONN=1 のみ設定し、
      CONFIG_BT_PERIPHERAL=y を忘れていた

修正: prj.conf に CONFIG_BT_PERIPHERAL=y を追加
```

## 実例2: 「Notifyが届かない」

### 症状
iOSアプリで `setNotifyValue(true, for:)` を呼んでいるが、Notifyが1件も届かない。

### デバッグ手順

```
Step 1: PacketLogger でATTログ確認
→ Write Request: Handle=0x001B, Value=0100 はある
→ Write Response もある（CCCD書き込みは成功）
→ Handle Value Notification がゼロ件

Step 2: Zephyrファームウェアのログ確認
printk("Notify送信: %d\n", ret);
→ ret = -11 (EAGAIN)

-EAGAIN: GATTキューが満杯。接続後すぐに
         bt_gatt_notify() を呼んでいた

修正: temp_ccc_changed コールバック内で
      notify_enabled フラグを true にセットしてから送る
```

```c
static bool notify_enabled = false;

static void temp_ccc_changed(const struct bt_gatt_attr *attr, uint16_t value)
{
    notify_enabled = (value == BT_GATT_CCC_NOTIFY);
}

void ble_notify_sensor_data(...)
{
    if (!notify_enabled) return;   // ← 追加
    int ret = bt_gatt_notify(NULL, attr, &payload, sizeof(payload));
    ...
}
```

## 実例3: 「DFUが10%で止まる」

### 症状
iOSのDFU進捗バーが10%で止まり、最終的にタイムアウトエラーになる。

### デバッグ手順

```
Step 1: Wireshark でDFU転送パケット確認
→ ATT Write Without Response が連続で送られている
→ 途中から Connection Event が増えるが Return Value がない
→ Notification (MCUmgr response) が返っていない

Step 2: nRF52840シリアルログ確認
→ "mcumgr: Upload" ログが止まっている
→ Secondary slot へのflash書き込みページ境界(0x1000)で遅延

Step 3: FirmwareUpgradeConfiguration を確認
→ pipelineDepth=5 になっていた（デフォルト値）
→ Flash書き込み中にキューが溢れている

修正:
  let config = FirmwareUpgradeConfiguration(
      pipelineDepth: 2,              // 下げる
      estimatedSwapTime: 15          // Swap待機時間を増やす
  )
```
