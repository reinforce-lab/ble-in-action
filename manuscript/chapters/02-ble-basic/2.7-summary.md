## まとめと次章への橋渡し {#sec:ch2-summary}

本章では、スマートフォンからmicro:bitのLEDへ値を書き込む体験を、二つの流れに分けて追いました。

一つ目は、通信路を作る流れです。

```text
アドバタイジング
    ↓
スキャンと発見
    ↓
接続
    ↓
必要に応じたペアリングと暗号化
    ↓
サービスとキャラクタリスティックの探索
```

接続前はアドバタイザーとスキャナーとして相手を見つけます。接続が成立すると、セントラルとペリフェラルとして接続イベントごとにパケットを交換します。保護が必要な場合は、ペアリングで準備した鍵を使って接続を暗号化します。鍵を次回にも使うために保存することがボンディングです。接続後は、サービスとキャラクタリスティックをUUIDで探索し、ReadやWriteの操作対象を見つけます。

二つ目は、接続後にデータを運ぶ流れです。

```text
アプリケーション
  → GATT → ATT → L2CAP → HCI → Link Layer → PHY
  → 電波
  → 相手側のPHY → Link Layer → HCI → L2CAP → ATT → GATT
  → ファームウェア
```

GATTはサービスとキャラクタリスティックとして製品の値を見せます。ATTはその値を読み書きする要求にします。L2CAPは上位プロトコルの論理チャンネルを区別し、HCIはHostとControllerの間でデータを渡します。Link Layerは接続イベントのパケット交換を管理し、PHYはビット列を電波として送受信します。

Read、Write Request、Write Without Response、Notify、Indicateは、同じ基本経路を使います。異なるのは、クライアントとサーバーのどちらからデータを送り始めるか、ATTのResponseまたはConfirmationを待つかです。

本章で区別した役割と境界は、ログを読むための共通言語になります。

- セントラル／ペリフェラルは、接続中のLink Layerの役割です。
- GATTクライアント／GATTサーバーは、データを操作する役割です。
- Host／Controllerは、一つの機器内部の責務を分けます。
- Link Layerの受信確認、ATTの応答、製品機能の完了は、異なる位置の完了です。
- 接続断、ATTの応答待ち、HCIのバッファー待ち、ファームウェアの処理待ちは、異なる停止位置です。

[@sec:ch3]では、この基本経路の通信能力を拡大します。LE 2M PHY、LE Coded PHY、Data Length Extension、Extended Advertising、Channel Soundingなどが、基本経路のどこを変え、どの制約を解決するのかを扱います。

[@sec:ch4]では、GATTとATTを製品設計の側から拡大します。サービス、キャラクタリスティック、UUID、ハンドル、Properties、Permission、CCCD、データ形式を使い、ファームウェアとアプリケーションの間に共有する仕様を作ります。

後続章で細かな仕様へ進んだときも、機能名だけを覚えるのではなく、本章の二つの流れへ戻ります。その機能が通信路を作る側にあるのか、データを運ぶ側にあるのかを確かめることで、現在のBLE仕様に追加された多くの技術を整理できます。
