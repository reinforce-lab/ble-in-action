## まとめと次章への橋渡し

<!-- topic: この章で学んだことを通信フローに沿って再確認する -->

この章では、BLE通信の全体フローを「発見 → 接続 → データ交換」という流れに沿って学びました。各フェーズを通信シーケンス図に対応させると次の通りです。

```
ペリフェラル: [アドバタイズ] ──────────────────────────────────→
セントラル:           [スキャン] → [接続確立] → [サービス探索] → [データ交換] → [切断]
                                        ↑
                                  （任意）ペアリング・ボンディング
```

| フェーズ | 節 | 学んだこと |
|---|---|---|
| アドバタイズ / スキャン | 2.2 | 37・38・39番チャンネルへの間欠ブロードキャスト、ADパケットの構造、パッシブ/アクティブスキャン |
| 接続確立 | 2.3 | CONNECT\_IND、コネクションインターバル、スレーブレイテンシ、スーパービジョンタイムアウト |
| サービス探索 / データ交換 | 2.4 / 2.5 | UUID・GATT階層、Read / Write / Notify / Indicate、CCCDへの書き込み |
| ペアリング / ボンディング | 2.6 | 鍵交換によって通信を暗号化する手続き、鍵の永続保存と再接続の高速化 |


## 重要用語一覧

<!-- topic: 本章で登場した用語の簡潔な一覧 -->

| 用語 | 説明 |
|---|---|
| **セントラル** | 接続を開始する側（スマートフォンなど）。GATTクライアント |
| **ペリフェラル** | 接続を受け入れる側（センサーなど）。GATTサーバ |
| **アドバタイジング** | ペリフェラルが自分の存在を周囲に発信するブロードキャスト |
| **スキャン** | セントラルがアドバタイジングパケットを受信してデバイスを発見すること |
| **アドバタイジング間隔** | アドバタイジングの送出周期（20 ms〜10.24 s） |
| **コネクションインターバル** | 接続中の通信周期（7.5 ms〜4 s） |
| **スレーブレイテンシ** | ペリフェラルが連続してスキップできる通信スロットの回数 |
| **スーパービジョンタイムアウト** | 通信が途絶えてから切断とみなすまでの時間（100 ms〜32 s） |
| **UUID** | 128ビットの識別子。GATTのサービス・キャラクタリスティックに付く |
| **GATT** | BLEのデータ構造（Profile / Service / Characteristic / Descriptor）を定義するプロファイル |
| **サービス** | GATT上の機能グループ。UUIDで識別（例：Heart Rate Service 0x180D） |
| **キャラクタリスティック** | GATTの実際のデータ。値・UUID・プロパティの3要素で構成 |
| **プロパティ** | キャラクタリスティックで使える操作の種類（Read / Write / Notify / Indicate など） |
| **CCCD** | Notify/Indicateの購読を有効にするディスクリプタ（UUID: 0x2902） |
| **Read** | セントラルがペリフェラルの値を問い合わせて取得する操作 |
| **Write** | セントラルがペリフェラルに値を書き込む操作（応答あり） |
| **Write Without Response** | ペリフェラルからの応答を待たない書き込み（高速・低オーバーヘッド） |
| **Notify** | ペリフェラルが値の変化をセントラルへ自動送信する操作（応答なし） |
| **Indicate** | 確認応答（Confirmation）を伴うNotify（信頼性重視） |
| **ペアリング** | セントラルとペリフェラルが暗号鍵を交換して通信を保護する手続き |
| **ボンディング** | ペアリングで交換した鍵をフラッシュに保存し、再接続時の鍵交換を省略する仕組み |


## 次章へ

<!-- topic: 第3章の予告——「裏側」に降りる -->

この章で学んだフローと用語は、BLE開発の共通言語です。チームでやり取りするとき、ログを読むとき、仕様書を参照するとき、すべてこれらの概念が出てきます。

第3章では、この章で扱った「概念の裏側」に一段降りていきます。

- アドバタイジングチャンネルの3本はなぜこの周波数に配置されているのか
- コネクションインターバルの「スロット」は物理的にどう確保されているのか
- GATTのハンドル番号とUUIDはどのように紐付いているのか

物理層・リンク層・GAPという、この章が「使い方」として扱ってきた仕組みの実装を見ていきます。設計の細部を知ることで、「なぜ動かないのか」を調査するときの手がかりが増えます。
