## まとめと次章への橋渡し {#sec:ch2-summary}

BLEで値をやり取りするまでには、発見、接続、必要に応じた保護、GATTによるデータ交換という段階があります。

接続前は、周辺機器がアドバタイザーとして短いパケットを繰り返し送り、スマートフォンがスキャナーとして受信します。発見結果は、デバイスが存在し続けていることを直接表す状態ではありません。アドバタイジングパケットを受信したイベントを、OSやアプリケーションが機器の存在へ対応づけたものです。

接続すると、二台はセントラルとペリフェラルとして、接続イベントごとにパケットを交換します。Connection Interval、Peripheral Latency、Supervision Timeoutは、応答性、消費電力、通信途絶を切断と判断するまでの時間に影響します。

接続を作ることと、その通信路を保護することは別の段階です。保護が必要な場合は、ペアリングで鍵を準備し、その鍵を使って接続を暗号化します。鍵を次回の接続にも使えるよう保存することがボンディングです。

接続後は、GATTクライアントがサービスとキャラクタリスティックを探索し、UUIDで操作対象を選びます。Read、Write Request、Write Without Response、Notify、Indicateは同じ通信路を使いますが、送信を始める側と、ATTのResponseまたはConfirmationを待つかどうかが異なります。

一つのGATT操作は、GATTから直接電波へ出るわけではありません。ATT、L2CAP、HCI、Link Layer、PHYを順に通り、電波を渡った後、相手側のスタックを逆の順序で上がります。この経路は[@fig:gatt-write-packet-path]で確認できます。

### 画面に見える現象を通信の段階へ戻す

章で見てきた仕組みは、通信できない原因を調べるときの地図になります。

| 画面や製品に見える現象 | 最初に確認する段階 |
|---|---|
| 機器が一覧に現れない | Advertisingの開始、電波での送信、スキャン、OSのフィルター |
| 機器は現れるが接続できない | 接続可能なAdvertising、接続要求、最初の接続イベント |
| 接続後に切れる | 接続イベントのパケット交換、電波環境、Supervision Timeout |
| 接続中だが保護された値を操作できない | ペアリング、暗号化、GATTのアクセス条件 |
| 目的の値が見つからない | サービス探索、キャラクタリスティック探索、UUID |
| Writeしたが製品が動かない | ATT操作、各層の通信経路、ファームウェアの処理 |

: 通信の現象と確認する段階 {#tbl:ch2-troubleshooting-map}

「接続した」「送った」「届いた」という言葉だけでは、確認した位置が分かりません。セントラル／ペリフェラルは接続中のLink Layerの役割、GATTクライアント／GATTサーバーは値を操作する役割です。Link Layerの受信確認、ATTの応答、ファームウェアの処理、製品動作の完了も、それぞれ異なる位置にあります。

[@sec:ch3]では、PHY、Link Layer、アドバタイジング、接続の仕組みを拡大します。LE 2M PHY、LE Coded PHY、Extended Advertisingなどが、基本経路のどこを変えるかを見ていきます。

[@sec:ch4]では、ATTとGATTを拡大します。サービス、キャラクタリスティック、UUID、ハンドル、Properties、Permission、CCCD、データ形式を使い、周辺機器が公開する機能と値を設計します。
