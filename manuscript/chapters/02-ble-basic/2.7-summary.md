## まとめと次章への橋渡し {#sec:ch2-summary}

この章では、BLE通信を「通信路を作る流れ」と「接続後にデータを運ぶ流れ」に分けました。

```text
アドバタイジング → スキャンと発見 → 接続
    → 必要に応じたペアリングと暗号化
```

ペリフェラルはアドバタイジングで存在を知らせ、セントラルはスキャンによって相手を見つけます。接続後は、コネクションインターバルなどで決まるタイミングに従ってパケットを交換します。保護が必要な通信では、ペアリングによって得た鍵を使って接続を暗号化します。

```text
アプリケーション → GATT → ATT → L2CAP → HCI
    → Link Layer → PHY → 電波
    → 周辺機器側で逆の順序を上がる → ファームウェア
```

Read、Write、Notify、Indicateは、データを運ぶ向きとATTの応答の有無が異なります。どの操作も同じ経路の上を通るため、問題を調べるときは、接続が失われたのか、ATTの応答を待っているのか、次の層へデータを渡せないのかを分けて考えます。

### 次章へ

この章で作った二つの流れは、BLE開発で問題の位置を共有するための地図になります。第3章と第4章では、この地図の異なる部分を拡大します。

[@sec:ch3]では、PHY、Link Layer、アドバタイジング、接続、GAP、SMPを扱い、通信路がどのように作られ、維持され、保護されるかを説明します。

[@sec:ch4]では、L2CAP上を流れるATTとGATTを扱い、接続後のデータがどのように表現、探索、操作されるかを説明します。
