# BLE通信の全体像——通信フローと登場人物 {#sec:ch2}

[@sec:ch1]では、スマートフォンからmicro:bitへ値を書き込み、LEDを点灯させました。アプリケーションから見ると、目的のキャラクタリスティックを選んで値を書き込むだけです。ファームウェアから見ても、書き込まれた値を受け取るコールバックからLEDを制御するだけでした。

このとき、アプリケーションとファームウェアは、それぞれのSDKを通じて同じGATT基盤を利用していました。アプリケーションはサービスとキャラクタリスティックを探索して値を書き込み、ファームウェアはキャラクタリスティックへの書き込みを受け取ります。どちらの側から見ても、BLEはGATTの値を読み書きする仕組みとして見えていました。

ここからは、この構成を一般的なスマートフォンと周辺機器の通信として捉え、その中身を見ていきます。GATTへ渡した値が、そのまま相手のGATTへ移るわけではありません。値を届けるには、まずスマートフォンが周囲から周辺機器を見つけ、接続して通信路を作る必要があります。接続後も、値はGATTからいくつもの層を通って無線のパケットになり、電波を渡った後、周辺機器側で逆の順序を上がってファームウェアへ届きます。SDKから見えていたGATTの下では、BLEの複数の仕組みが一つの通信を支えています。

本章では、スマートフォンがLEDの値を書き込み、周辺機器のファームウェアが受け取るまでを、一続きのデータの流れとして追います。最初に、アドバタイジングとスキャンから接続へ進み、必要に応じて通信を保護し、GATTの操作対象を見つけるまでを見ます。次に、見つけたキャラクタリスティックへ書き込んだ値が、GATT、ATT、L2CAP、HCI、Link Layer、PHYを通って運ばれる経路をたどります。BLEの役割や用語は、この流れの中で必要になる位置に結び付けて整理します。

本章のゴールは、SDKの向こう側をブラックボックスとして扱うのではなく、GATTへ渡した値がどの層を通り、どのように相手のファームウェアへ届くのかを、BLEの知識をもとに頭の中でたどれるようになることです。すべての処理を直接見ることはできなくても、アプリケーションのログ、無線のパケット、ファームウェアのログなど、観測できる断片をデータの流れに置くことで、通信がどこまで進んでいるのかを考えられるようになります。
