# BLE通信の全体像——通信フローと登場人物 {#sec:ch2}

[@sec:ch1]では、スマートフォンからmicro:bitへ値を書き込み、LEDを点灯させました。アプリケーションから見ると、目的のキャラクタリスティックを選んで値を書き込むだけです。ファームウェアから見ても、書き込まれた値を受け取るコールバックからLEDを制御するだけでした。

しかし、アプリケーションが渡した値が、そのままmicro:bitへ届くわけではありません。スマートフォンは、最初に周囲の機器からmicro:bitを見つけ、接続して通信路を作ります。接続後の値はBLEの複数の層を下り、無線のパケットとして送信されます。micro:bitでは、受信したパケットが逆の順序で層を上がり、ファームウェアへ渡されます。

現在のBluetoothコア仕様には、BLEの登場後に追加された機能も一緒に収められています。そこで本章では、Bluetooth 4.2までに成立していた接続型の通信を題材に、現在のBluetooth Core Specification v6.3の用語で基本経路だけを取り出します。後から追加された高速化、長距離化、ブロードキャスト、測距、音声などは、この経路の位置がわかってから[@sec:ch3]で扱います。

本章では、次の二つの流れを追います。

1. アドバタイジング、スキャン、接続によって通信路を作り、必要なら暗号化する流れ
2. 接続後に操作対象を探索し、スマートフォンがGATTへ書き込んだ値を周辺機器のファームウェアまで運ぶ流れ

細かなフィールドやOpcodeを覚えることが目的ではありません。アプリケーションとファームウェアの間で問題が起きたときに、通信がどの位置まで進み、どこで止まったのかを同じ地図の上で話せることが、本章の到達点です。
