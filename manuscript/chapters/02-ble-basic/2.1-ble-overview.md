# BLE通信の全体像——通信フローと登場人物

<!-- topic: 導入——地図を先に見せる -->

第1章では、micro:bitとスマートフォンをつないでBLEを「動かして感じる」体験をしました。この章では、その裏側で何が起きていたのかを、仕組みの側から理解していきます。

多くの無線通信技術は、途切れない安定した高速な通信を目指しています。移動体通信でもWi-Fiでも、まるで目に見えない電線でつながっているかのような安定した通信であれば、使っている技術の違いに気づくこともありません。では、BLEで使う通信を別の無線規格で置き換えられるでしょうか。GATTと呼ばれるデータ表現の仕組みや、電波の伝わり方を利用するビーコンなど、目に見えない電線以上の工夫が盛り込まれたこの技術は、簡単に置き換えはできません。置換できない技術というのは、それだけの独自性があるということです。この章では、その独自性を形作る仕組みを1つずつ見ていきます。

仕組みを学ぶとき、細かい用語が次々と登場すると、いまどこにいるのかわからなくなりがちです。そこでこの節では最初に「地図」を示します。BLE通信がどのようなフェーズを経てデータに届くかを一枚のシーケンス図として俯瞰しておけば、以降の節でそれぞれの仕組みを学ぶときに「いまどのフェーズの話か」が常にわかります。


## 2つの役割：セントラルとペリフェラル

<!-- topic: BLEの役割の非対称性——接続を始める側と受け入れる側 -->

BLEの通信には、**セントラル（Central）**と**ペリフェラル（Peripheral）**という2つの役割があります。

セントラルは「接続を開始する側」です。周囲をスキャンして接続相手を探し、接続要求を送ります。スマートフォンやPCがこの役割を担うことがほとんどです。電力に余裕があり、処理能力も高い機器が向いています。

ペリフェラルは「接続を受け入れる側」です。自分の存在を周囲に知らせる信号を発信し、接続要求を待ちます。センサー、ウェアラブル、ビーコンなどがこの役割を担います。コイン電池で動く小型機器でも担えるように、最小限の消費電力で動作できます。

もう一つ、データのやり取りに関わる役割の対があります。ペリフェラルは**GATTサーバ**としてデータを持ち、セントラルは**GATTクライアント**としてそのデータを読み書きします。ネットワーク・サービスの開発経験があると、サーバといえば強力な処理能力がある計算機を想像しがちです。しかしBLEでは、気温や心拍値などセンサーからの値を持つのは周辺機器の側です。値を持つ側がサーバになりますから、コイン電池で動く小さなデバイスがサーバ、強力なスマートフォンがクライアントという、直感に反する構成になります。GATTについては2.4節で詳しく扱います。


## 通信の全体フロー

<!-- topic: 全体シーケンス——5フェーズの流れを一枚で -->

BLE通信は、次の5つのフェーズを順番に進みます。

```
ペリフェラル: [アドバタイズ] ─────────────────────────────────→
セントラル:           [スキャン] → [接続確立] → [サービス探索] → [データ交換] → [切断]
                                        ↑
                                  （任意）ペアリング・ボンディング
```

### フェーズ①：アドバタイジングとスキャン

ペリフェラルは電源が入ると、自分の存在を知らせる短いデータをブロードキャストし続けます。これを**アドバタイジング（Advertising）**と呼びます。このデータには、デバイスの名前や提供するサービスの識別子などが含まれます。

セントラルはこのブロードキャストを受信してデバイスを発見します。これを**スキャン（Scanning）**と呼びます。接続する前の「デバイスを見つける」フェーズです。このフェーズの仕組みを2.2節で詳しく説明します。

### フェーズ②：接続の確立

スキャンで目的のデバイスを見つけたセントラルは、接続要求を送ります。ペリフェラルが受け入れると、両者の間に通信路が確立されます。接続が確立すると、ペリフェラルはアドバタイジングをやめます。以降の通信は、両者だけの専用チャンネルで行われます。

接続時には**接続パラメータ**の設定もなされます。通信の周期（コネクションインターバル）や切断判定の時間（スーパービジョンタイムアウト）など、通信の「ペース」を決める値です。2.3節でこれらを詳しく扱います。

### フェーズ③：サービス探索とデータ交換

接続が確立したら、セントラルはペリフェラルが持つデータの構造を探索します。このデータ構造を**GATTテーブル**と呼び、サービスとキャラクタリスティックという入れ子の階層で整理されています。「このデバイスに何が読み書きできるか」という目次を見るフェーズです。

探索が終わると、いよいよデータのやり取りができます。値を読み出す（Read）、書き込む（Write）、変化を自動通知してもらう（Notify）など、いくつかの方法があります。2.4・2.5節でGATTの構造とデータ交換の手順を詳しく解説します。

### 任意フェーズ：ペアリングとボンディング

データ交換の前後、または接続と同時に、**ペアリング（Pairing）**が行われることがあります。ペアリングとは、暗号鍵を交換して通信を保護する手続きです。一度交換した鍵をデバイスに保存して、次回の接続で再利用することを**ボンディング（Bonding）**と呼びます。すべての製品でペアリングが必要なわけではなく、セキュリティ要件に応じて使います。2.6節で詳しく扱います。

### 切断

データのやり取りが終わればどちらからでも切断できます。ペリフェラルが省電力のために自発的に切断することも、スマートフォンがアプリを閉じたときに自動で切断されることもあります。ボンディング済みであれば、再接続時の鍵交換は省略されます。

音声や動画転送に用いる無線通信技術が、途切れず安定した、まるで目に見えない電線のような通信だとすれば、BLEの通信は、必要な少しのパケットを素早く伝える、**イベントを伝える通信**です。GATTの読み書きのコマンドは、だいたい1つのパケットに収まります。ですからBLEの通信は、通信相手とぱっとつながり、いくつかのパケットを素早くやり取りできればよいのです。この特性が、BLEの通信フロー全体を貫く設計思想です。
