## 通信の地図と役割 {#sec:ble-overview}

BLEの通信には、**セントラル（Central）**と**ペリフェラル（Peripheral）**という2つの役割があります。

セントラルは「接続を開始する側」です。周囲をスキャンして接続相手を探し、接続要求を送ります。スマートフォンやPCがこの役割を担うことがほとんどです。電力に余裕があり、処理能力も高い機器が向いています。

ペリフェラルは「接続を受け入れる側」です。自分の存在を周囲に知らせる信号を発信し、接続要求を待ちます。センサー、ウェアラブル、ビーコンなどがこの役割を担います。コイン電池で動く小型機器でも担えるように、最小限の消費電力で動作できます。

もう一つ、データのやり取りに関わる役割の対があります。ペリフェラルは**GATTサーバー**としてデータを持ち、セントラルは**GATTクライアント**としてそのデータを読み書きします。ネットワークサービスの開発経験があると、サーバーといえば強力な処理能力がある計算機を想像しがちです。しかしBLEでは、気温や心拍値などセンサーからの値を持つのは周辺機器の側です。値を持つ側がサーバーになりますから、コイン電池で動く小さなデバイスがサーバー、強力なスマートフォンがクライアントという、直感に反する構成になります。GATTについては[@sec:packet-path]で、データの経路と結びつけて扱います。

### 通信路を作る流れ

通信相手を見つけ、データを交換できる状態になるまでの流れは次のように整理できます。

```text
アドバタイジング
    ↓
スキャンと発見
    ↓
接続
    ↓
必要に応じたペアリングと暗号化
```

ペリフェラルは電源が入ると、自分の存在を知らせる短いデータをブロードキャストし続けます。これを**アドバタイジング（Advertising）**と呼びます。このデータには、デバイスの名前や提供するサービスの識別子などが含まれます。

セントラルはこのブロードキャストを受信してデバイスを発見します。これを**スキャン（Scanning）**と呼びます。接続する前の「デバイスを見つける」フェーズです。このフェーズの仕組みを[@sec:adv-scan]で詳しく説明します。

スキャンで目的のデバイスを見つけたセントラルは、接続要求を送ります。ペリフェラルが受け入れると、両者の間に通信路が確立されます。接続が確立すると、ペリフェラルはアドバタイジングをやめます。以降の通信は、両者だけの専用チャンネルで行われます。

接続時には**接続パラメータ**の設定もなされます。通信の周期（コネクションインターバル）や切断判定の時間（スーパービジョンタイムアウト）など、通信の「ペース」を決める値です。[@sec:connection]でこれらを詳しく扱います。

データ交換の前後、または接続と同時に、**ペアリング（Pairing）**が行われることがあります。ペアリングとは、暗号鍵を交換して通信を保護する手続きです。一度交換した鍵をデバイスに保存して、次回の接続で再利用することを**ボンディング（Bonding）**と呼びます。すべての製品でペアリングが必要なわけではなく、セキュリティ要件に応じて使います。[@sec:pairing]で詳しく扱います。

### 接続後にデータを運ぶ流れ

接続が確立したら、セントラルはペリフェラルが持つデータの構造を探索します。このデータ構造を**GATTテーブル**と呼び、サービスとキャラクタリスティックという入れ子の階層で整理されています。「このデバイスに何が読み書きできるか」という目次を見るフェーズです。

探索が終わると、値を読み出す（Read）、書き込む（Write）、変化を自動通知してもらう（Notify）などの操作ができます。ただし、アプリケーションがGATTへ渡した値が、そのまま電波へ出るわけではありません。値は複数の層を通り、周辺機器側で逆の経路を上がってファームウェアへ届きます。

```text
アプリケーション → GATT → ATT → L2CAP → HCI
    → Link Layer → PHY → 電波
    → 周辺機器側で逆の順序を上がる → ファームウェア
```

この経路を[@sec:packet-path]で追い、Read、Write、Notify、Indicateによる向きと応答の違いを[@sec:data-exchange]で整理します。

### 通信が終わるとき

データのやり取りが終われば、どちらからでも切断できます。ペリフェラルが省電力のために自発的に切断することもあります。ボンディング済みであれば、再接続時には保存した鍵を利用できます。
