## GATTの値を運ぶ {#sec:gatt-data-path}

接続ができ、必要な保護を満たしても、スマートフォンは周辺機器のどの値を操作すればよいか、まだ知りません。GATTは、接続した通信路の上に、製品が外部へ見せる機能と値の構造を作ります。

GATTサーバーは、外部へ公開する機能と値を、サービスとキャラクタリスティックとして表します。たとえば、温度センサーは次のような構造を公開できます。

| サービス | キャラクタリスティック |
|---|---|
| 温度サービス | 現在の温度、測定間隔 |
| 電池サービス | 電池残量 |

: 温度センサーが公開するGATTの構造例 {#tbl:gatt-temperature-structure}

サービスは機能のまとまりです。キャラクタリスティックは、読み書きする値と、その値に許された操作を表します。GATTクライアントは、接続後にこの構造を探索し、UUIDで目的のサービスとキャラクタリスティックを選びます。

キャラクタリスティックが表すものは、次の三つに分けて考えると設計しやすくなります。

| キャラクタリスティックが表すもの | 例 | 主に使う操作 |
|---|---|---|
| センサーなどから得た値 | 温度、加速度 | Read、Notify |
| 機器の内部状態 | 動作モード、電池残量 | Read、Notify |
| 機器への設定や操作 | 測定間隔、動作開始 | Write |

: キャラクタリスティックが表す値の例 {#tbl:gatt-characteristic-roles}

これは固定的な分類ではありません。一つのキャラクタリスティックで、現在値のReadと変更のWriteの両方を許すこともできます。重要なのは、製品のメモリー配置をそのまま公開するのではなく、外部から利用する値や操作として構成することです。

GATTには、クライアントとサーバーという役割があります。一般的な周辺機器ではスマートフォンがクライアント、周辺機器がサーバーになりますが、この役割は接続時のセントラルとペリフェラルから自動的に決まるものではありません。リンク層の役割とGATTの役割は、異なる層の役割として分けて考えます。

値を見つけた後は、目的に応じて操作を選びます。

| 行いたいこと | GATTで使う操作 |
|---|---|
| 現在の値を必要なときに取得する | Read |
| 設定値や操作値を書き込む | Write |
| 値が変化したときに知らせる | NotifyまたはIndicate |

: 利用目的とGATT操作 {#tbl:gatt-operation-purpose}

同じ接続を使っても、Read、Write、Notify、Indicateでは、送信を始める側と応答の有無が異なります。その違いは、一つの値がスマートフォンからファームウェアへ届く経路をたどると、パケット上の位置として見えるようになります。
