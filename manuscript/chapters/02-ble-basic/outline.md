# 第2章「BLEの基本概念と用語」執筆方針

## この章の役割

第2章では、BLEの仕様を機能ごとに列挙するのではなく、一つの通信が始まり、パケットが相手へ届くまでの流れを示します。BLEは機能の追加を重ねてきたため、現在のコア仕様を目次どおりに読むと、基本的な通信と後から追加された拡張機能とが入り交じります。この章では、複雑な仕様から基本となる経路だけを取り出し、BLE通信の全体像を作ります。

題材とするのは、Bluetooth 4.2までに成立していた基本的な利用場面です。周辺機器がLegacy Advertisingで存在を知らせ、スマートフォンが発見して接続し、必要に応じて通信を暗号化して、ATTとGATTでデータをやり取りする構成を扱います。ただし、古い仕様書の記述を再現するのではなく、技術用語と仕組みの説明はBluetooth Core Specification v6.3を基準にします。

この章を読み終えた読者が、スマートフォンのアプリケーションから書き込んだ値が、どの層を通り、どこでパケットになり、どのように周辺機器のファームウェアへ届くのかを、一続きの流れとして説明できることを目標にします。

## 説明の中心となる問い

> スマートフォンのアプリケーションがGATTへ書き込んだ値は、どのような経路を通って周辺機器のファームウェアへ届くのでしょうか。

この問いに答えるため、最初にPHYがビット列を電波で運ぶ関係を確認します。続いて、通信相手を見つけて通信路を作る流れを見ます。最後に、接続後のデータがBLEプロトコルスタックを下り、電波を渡り、相手側のスタックを上がる流れを追います。

## 第2章で追う四つの段階

### アドバタイジングで相手を見つける

1. 周辺機器がアドバタイジングを行う
2. スマートフォンがスキャンして発見する

周辺機器がアドバタイザーとしてどのように存在を知らせ、スマートフォンがスキャナーとしてどのように発見するかを説明します。接続前のアドバタイジングと、接続後のGATT通信が別の経路であることを最初に分けます。

### 接続して通信路を作る

1. スマートフォンが接続要求を送る
2. 接続イベントでパケット交換を始める

接続要求を境に、アドバタイザーとスキャナーから、セントラルとペリフェラルへ役割が変わります。接続後は共有した時刻とチャンネルで接続イベントを開き、双方向にパケットを交換します。接続開始、接続イベント、接続パラメーター、接続の維持と切断を順に扱います。

### 接続した通信路を保護する

1. 接続する
2. 必要ならペアリングで鍵を準備する
3. 鍵を使って接続を暗号化する

接続、ペアリング、暗号化、ボンディングを別の状態として整理します。セキュリティは接続を作る説明へ混ぜず、できあがった通信路を必要に応じて保護する段階として扱います。

### GATTの値を運ぶ

1. スマートフォンのアプリケーションからGATTへ値を渡す
2. ATT、L2CAP、HCI、Link Layer、PHYの順に値を運ぶ
3. 電波で相手へ送る
4. 周辺機器側のスタックを逆の順序で上がる
5. ファームウェアへ値を渡す

各層について、この章ではパケットの経路上で果たす役割だけを説明します。アプリケーションから渡されたデータがすぐに電波へ出るわけではなく、各層でヘッダーが加わり、必要に応じて分割され、HostとControllerのバッファーやフロー制御を経て送信されることを示します。

送信側だけでなく、受信側でPHYからLink Layer、HCI、L2CAP、ATT、GATTへと情報が上がり、最終的にファームウェアの処理へ届くところまでを一つの往復として扱います。

## 本文の流れ

本文は、BLE通信の俯瞰、電波によるビット列の転送、アドバタイジングによる発見、接続、通信路の保護、GATTの値の転送という順に進めます。接続前と接続後の通信を目次から判別できるように、次の階層で構成します。

1. 2.1「BLE通信を一つの流れとして見る」で、発見、接続、必要に応じた保護、GATTによるデータ交換という章全体の順序を示します。
2. 2.2「電波で0と1を伝える」で、LE 1M PHYを例に、パケットが届く条件、2.4 GHz帯、通信距離、RSSI、RFチャンネル、衝突、変調、パケットの関係を示します。
3. 2.3「アドバタイジングで相手を見つける」の下で、最初にアドバタイザーとスキャナー、Advertising DataとScan Response Data、受信時間と消費電力の関係を説明します。次に実際のバイト列へ当てはめ、最後にOSやアプリケーションから見える振る舞い、実際の発見時間、混雑時の衝突、見つからない場合の切り分けを扱います。
4. 2.4「接続して通信路を作る」の下で、接続要求、接続イベント、接続パラメーター、接続の維持と切断を扱います。
5. 2.5「接続した通信路を保護する」で、ペアリング、暗号化、ボンディングを扱います。
6. 2.6「GATTの値を運ぶ」の下で、アプリケーションからファームウェアまでの経路と、Read、Write、Notify、Indicateの違いを扱います。
7. 2.7「まとめと次章への橋渡し」で通信全体の地図を振り返り、第3章と第4章で詳しく扱う範囲を示します。

## 現在の技術で説明する

説明対象は単純なBLE通信に絞りますが、説明そのものはCore v6.3の構造に合わせます。たとえば、HostとControllerは同じ速度でデータを処理するとは限らず、Controllerへ無制限にパケットを渡すことはできません。HCIのフロー制御や利用可能なバッファーを通じて、次に渡せるデータ量を管理するという現在の整理を使います。

「パケットのウィンドウ」という表現が、接続開始時のTransmit Window、Link LayerのAcknowledgment and Flow Control、HCIのフロー制御、L2CAPのCredit Based Flow Controlなどのどれを指すかは、本文へ入れる前にCore v6.3の該当箇所で特定します。異なる層にあるウィンドウ、バッファー、クレジットの仕組みを同じものとして説明しません。

## この章では詳しく扱わないもの

第2章では、パケットの経路を理解するために必要な情報だけを残します。次の内容は名前や位置づけを示すに留め、詳細を後続章へ送ります。

- Advertising PDUの全種類とフィールド構造
- GFSK変調回路、I/Q復調回路、受信判定の詳細
- Link Layerの状態機械と接続確立手順
- チャンネル選択、周波数ホッピング、再送の詳細
- SMPの鍵生成とペアリング手順
- ATT Opcodeとエラーコードの一覧
- ATT MTU、分割、再構成の詳細
- GATTのハンドル、アトリビュート、ディスクリプターの内部構造
- CCCDへ書き込む値や永続化の詳細
- HCIコマンドとイベントの一覧
- Extended Advertising、Periodic Advertising、LE 2M PHY、LE Coded PHY
- Direction Finding、Isochronous Channels、LE Audio、PAwR、Channel Sounding

後から追加された機能は、第2章の基本経路を置き換えるものとして一括して混ぜません。基本経路のどこを拡張し、どの制約を解決する技術なのかを、必要な章で説明します。

## 第3章・第4章との境界

第2章は「何が、どの順番で、どこを通るか」を示します。第3章と第4章は、その地図の各部分を拡大します。

- 第3章では、PHY、Link Layer、アドバタイジング、接続、GAP、SMPを扱い、通信路がどのように作られ、維持され、保護されるかを説明します。
- 第4章では、L2CAP上を流れるATTとGATTを扱い、接続後のデータがどのように表現、探索、操作されるかを説明します。

第2章では、第3章や第4章で説明する仕様詳細を先取りしません。同じエピソードや同じトラブルを複数の章へ置く場合も、第2章では現象と切り分けの入口、第3章・第4章では原因となる仕様、というように段階を分けます。

## 執筆時の判断基準

- 用語を並べる前に、パケットの経路上で何をしているものかを示します。
- 一つの節では、通信全体のどの位置を説明しているかを明確にします。
- 数値やフィールド名は、その値が流れの理解や設計判断を変える場合だけ本文へ出します。
- 基本機能、後から追加された拡張機能、実装依存のバッファー制約を区別します。
- Core v6.3の仕様上の動作、OSやSDKによる抽象化、製品側の設計判断を混同しません。
- ファームウェア担当とアプリケーション担当が、同じ図と用語を使って問題の位置を話せる説明を優先します。
