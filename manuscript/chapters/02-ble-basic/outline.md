## 節構成

#### 2.1 セントラルとペリフェラル
**ファイル**: `2.1-central-peripheral.md`  
**概要**:
- 2つの役割の定義と責務の違い（接続を開始する側・受け入れる側）
- ペリフェラルの特徴：アドバタイジング、GATTサーバ、電池制約
- セントラルの特徴：スキャン、接続開始、GATTクライアント、電力余裕
- スマートホンが「セントラル」として機能する仕組みとその意義
- 1つのペリフェラルが複数セントラルと同時接続できるか（接続数の制約）

**ファイル**: `2.2-advertising-scanning.md`

- スキャンレスポンス：追加情報を返す仕組み
- iBeacon・Eddystoneなどビーコン形式との関係

#### 2.4 GATTの構造——サービスとキャラクタリスティック
**ファイル**: `2.4-gatt-structure.md`  
**概要**:
- GATTの全体像：階層構造（Profile → Service → Characteristic → Descriptor）
- サービス：機能グループの単位（例：Heart Rate Service、Battery Service）
- キャラクタリスティック：実際のデータの単位、値・UUID・プロパティの3要素
- プロパティ（Read / Write / Write Without Response / Notify / Indicate）の違いと使い分け
- Descriptor：Client Characteristic Configuration Descriptor（CCCD）の役割
- 標準プロファイルの読み方：Bluetooth SIG仕様書の対応する記述を辿る練習

**想定ページ数**: 5〜6ページ

#### 2.5 接続パラメータ
**ファイル**: `2.5-connection-parameters.md`  
**概要**:
- コネクションインターバル：通信周期（7.5ms〜4s）と省電力の関係
- スレーブレイテンシ：ペリフェラルが応答をスキップできる回数
- スーパービジョンタイムアウト：接続切断を判定する時間
- 3つのパラメータの組み合わせが電力消費と応答速度に与える影響
- iOSとAndroidによるパラメータ制約の違い
- パラメータ更新のネゴシエーション手順

**想定ページ数**: 3〜4ページ

#### 2.6 ペアリングとボンディング
**ファイル**: `2.6-pairing-bonding.md`  
**概要**:
- ペアリングとは：暗号化鍵を交換して通信を保護する手続き
- ボンディングとは：鍵をフラッシュに保存し、再接続時の手続きを省略する仕組み
- ペアリングモード：Just Works / Passkey Entry / Numeric Comparison の違いと用途
- セキュリティレベル（LE SecurityMode 1 / 2）の概念
- ボンディング済みデバイスの管理（iOS・Androidでの削除方法）
- なぜBLE製品でペアリングが必要か・不要かの判断基準

**想定ページ数**: 3〜4ページ
