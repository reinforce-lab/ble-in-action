## 8.6 Read／Writeで状態、設定、コマンドを扱う {#sec:ch8-read-write}

第4章では、GATTにコマンドとデータという標準分類がないことを確認しました。本章のアプリは、製品仕様で決めた意味に従い、現在状態、設定、コマンドを扱います。

### Readで初期状態を同期する

接続後の初期同期では、LED StateとMeasurement IntervalをReadします。Measurement ValueはNotifyを購読しますが、購読後に値がすぐ変化するとは限りません。初期表示が必要ならReadも行います。

```swift
private func beginInitialSynchronization() {
    state = .synchronizing

    read(DeviceUUID.ledState)
    read(DeviceUUID.measurement)
    read(DeviceUUID.interval)
    subscribe(DeviceUUID.measurement)
    subscribe(DeviceUUID.commandResponse)
    subscribe(DeviceUUID.deviceEvent)
}

private func read(_ uuid: CBUUID) {
    guard let characteristic = characteristics[uuid],
          characteristic.properties.contains(.read) else {
        fail("ReadできないCharacteristicです: \(uuid)")
        return
    }
    peripheral?.readValue(for: characteristic)
}
```

Readの結果は`didUpdateValueFor`へ届きます。Notify／Indicateも同じCallbackを使うため、UUIDとアプリが管理する操作状態から処理します。

```swift
func peripheral(
    _ peripheral: CBPeripheral,
    didUpdateValueFor characteristic: CBCharacteristic,
    error: Error?
) {
    if let error {
        recordFailure(operation: "value", uuid: characteristic.uuid, error: error)
        return
    }
    guard let data = characteristic.value else { return }

    do {
        let update = try decodeValue(for: characteristic, data: data)
        apply(update)
    } catch {
        recordDataError(uuid: characteristic.uuid, error: error)
    }
}
```

### 設定値は要求と現在値を分ける

Measurement Intervalへ`30 s`を書き込む例を考えます。送信前に範囲を確認し、Value Formatへ変換します。

```swift
func setMeasurementInterval(seconds: UInt16) {
    guard (1...3600).contains(seconds) else {
        state = .failed("測定周期が範囲外です")
        return
    }

    let data = Data([
        UInt8(seconds & 0xff),
        UInt8((seconds >> 8) & 0xff)
    ])
    write(data, to: DeviceUUID.interval, type: .withResponse)
}
```

`didWriteValueFor`でErrorがなければ、ATT Write Requestは成功しました。しかし、製品が要求値を丸める、後から反映する、センサー設定に失敗する可能性があります。アプリは要求値を一時的に保持し、Write後にMeasurement IntervalをReadするか、状態ValueのNotifyで現在値を確認します。

### コマンドはRequest IDで追跡する

Command Requestは、処理の依頼です。ここでは、Version、Request ID、Command ID、Payloadという形式を使います。

```swift
func sendCommand(id commandID: UInt8, payload: Data) {
    let requestID = nextRequestID()
    var data = Data([1])
    data.append(UInt8(requestID & 0xff))
    data.append(UInt8((requestID >> 8) & 0xff))
    data.append(commandID)
    data.append(payload)

    pendingCommands[requestID] = PendingCommand(
        commandID: commandID,
        startedAt: Date()
    )
    write(data, to: DeviceUUID.commandRequest, type: .withResponse)
}
```

`didWriteValueFor`は受付経路の結果です。処理完了は、同じRequest IDを持つCommand Responseで判断します。切断やTimeoutが起きた場合、再送によって同じ処理が二重に実行されないよう、Request IDの再利用とPeripheral側の重複処理を製品仕様で決めます。

### 二つのWrite Typeを使い分ける

`.withResponse`では、対応するDelegate CallbackでATT Writeの結果を受け取れます。`.withoutResponse`では、書き込みごとの結果Callbackはありません。これは、無線リンクに再送があるかないかという単純な区別ではなく、ATT ServerからWrite Responseを受け取るProcedureかどうかの違いです。

大量の`.withoutResponse`を続けて送る場合は、`canSendWriteWithoutResponse`を確認します。`false`になったら送信を止め、`peripheralIsReady(toSendWriteWithoutResponse:)`で再開します。

```swift
func flushWriteQueue() {
    guard let peripheral else { return }

    while peripheral.canSendWriteWithoutResponse,
          let item = writeQueue.first {
        writeQueue.removeFirst()
        peripheral.writeValue(
            item.data,
            for: item.characteristic,
            type: .withoutResponse
        )
    }
}

func peripheralIsReady(
    toSendWriteWithoutResponse peripheral: CBPeripheral
) {
    flushWriteQueue()
}
```

設定やコマンドで結果確認が必要なら、本書では`.withResponse`を基準にします。高頻度のストリームや転送では`.withoutResponse`を検討できますが、順序、流量制御、再開、完全性確認を製品プロトコルへ追加します。
