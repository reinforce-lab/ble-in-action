# iOSからBLEデバイスを使う {#sec:ch8}

第6章では、Device Control ServiceをnRF52840上のGATT Serverとして実装しました。第7章では、そのValueをLED、センサー、製品状態へ接続しました。本章では、同じ製品をiOSアプリから利用します。

iOSアプリがBLEデバイスを使うときは、Core Bluetoothフレームワークを通してCentralとして動作します。アプリはPeripheralを発見し、接続し、ServiceとCharacteristicを探索します。その後、Read、Write、NotifyなどのGATT Procedureを使ってデータを交換します。

```text
iOSアプリ
  Core Bluetooth API
        ↓
iOSが管理するBluetooth処理
        ↓
BLE接続とATT／GATT
        ↓
nRF52840
  Device Control Service
        ↓
LED／センサー／製品ロジック
```

Core Bluetoothは、Link Layerの接続イベントやATT PDUをそのままアプリへ公開しません。代わりに、`CBCentralManager`、`CBPeripheral`、`CBService`、`CBCharacteristic`というオブジェクトと、非同期のDelegate Callbackを提供します。アプリ開発者は簡潔なAPIを使えますが、そのAPIがBLEのどの処理に対応するかを見失うと、問題のある層を切り分けにくくなります。

本章では、APIを機能ごとに並べるのではなく、次の順に一つのクライアントを完成させます。

1. Bluetoothを利用できる状態か確認します。
2. Device Control Serviceを公開するPeripheralを発見します。
3. 接続して、必要なServiceとCharacteristicを探索します。
4. GATT Valueを製品データへ変換します。
5. 状態をReadし、設定とコマンドをWriteします。
6. 状態、コマンド結果、イベントをNotify／Indicateで受け取ります。
7. 切断、再接続、キャッシュ、バックグラウンド動作を扱います。

最小アプリは、接続状態、LED State、Measurement Value、Measurement Interval、Command Response、Device Eventを表示します。UIそのものより、Core Bluetoothから受け取った事実をどのように製品状態へ反映するかを中心にします。

本章のコードは、説明を短くするために一つの`DeviceSession`へまとめます。実製品では、BLE操作、Valueの変換、永続化、UI状態を必要に応じて分割してください。
