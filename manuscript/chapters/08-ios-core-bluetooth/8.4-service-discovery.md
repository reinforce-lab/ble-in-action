## 8.4 ServiceとCharacteristicを探索する {#sec:ch8-service-discovery}

接続直後の`CBPeripheral`には、アプリが使う`CBCharacteristic`がそろっていません。最初にServiceを探索し、目的のServiceが見つかった後でCharacteristicを探索します。

Device Control Serviceでは、次のUUIDをアプリ側の製品仕様としてまとめます。ここでは説明用のUUIDを使います。ファームウェアとアプリで同じ定義から生成するか、互いに照合できる仕様書を正本にしてください。

```swift
enum DeviceUUID {
    static let service = CBUUID(string: "7A4A0001-6E2C-4B7A-9A32-2A1D6F3C9000")
    static let ledState = CBUUID(string: "7A4A0002-6E2C-4B7A-9A32-2A1D6F3C9000")
    static let measurement = CBUUID(string: "7A4A0003-6E2C-4B7A-9A32-2A1D6F3C9000")
    static let interval = CBUUID(string: "7A4A0004-6E2C-4B7A-9A32-2A1D6F3C9000")
    static let commandRequest = CBUUID(string: "7A4A0005-6E2C-4B7A-9A32-2A1D6F3C9000")
    static let commandResponse = CBUUID(string: "7A4A0006-6E2C-4B7A-9A32-2A1D6F3C9000")
    static let deviceEvent = CBUUID(string: "7A4A0007-6E2C-4B7A-9A32-2A1D6F3C9000")
}
```

### 必要なServiceだけを探索する

```swift
func peripheral(
    _ peripheral: CBPeripheral,
    didDiscoverServices error: Error?
) {
    if let error {
        fail("Service Discovery", error: error)
        return
    }

    guard let service = peripheral.services?.first(
        where: { $0.uuid == DeviceUUID.service }
    ) else {
        fail("Device Control Serviceがありません")
        return
    }

    peripheral.discoverCharacteristics([
        DeviceUUID.ledState,
        DeviceUUID.measurement,
        DeviceUUID.interval,
        DeviceUUID.commandRequest,
        DeviceUUID.commandResponse,
        DeviceUUID.deviceEvent
    ], for: service)
}
```

`nil`を指定してすべてを探索する方法もありますが、製品アプリでは利用するUUIDを明示すると、必須要素の不足を検出しやすくなります。

### UUIDとPropertiesを照合する

```swift
private var characteristics: [CBUUID: CBCharacteristic] = [:]

func peripheral(
    _ peripheral: CBPeripheral,
    didDiscoverCharacteristicsFor service: CBService,
    error: Error?
) {
    if let error {
        fail("Characteristic Discovery", error: error)
        return
    }

    for characteristic in service.characteristics ?? [] {
        characteristics[characteristic.uuid] = characteristic
    }

    guard validateRequiredCharacteristics() else {
        fail("必須Characteristicが不足しています")
        return
    }

    beginInitialSynchronization()
}
```

UUIDが存在するだけでなく、Propertiesも確認します。たとえばMeasurement Valueには`.read`と`.notify`、Measurement Intervalには`.read`と`.write`、Command Requestには`.write`、Command Responseには`.notify`または`.indicate`が必要です。期待と異なる場合は、互換性のないファームウェアへ接続した可能性があります。

探索が終わっただけでは`ready`にしません。Notifyの購読結果と、状態・設定の初期Readを受け取ってから操作可能にします。

### Characteristic参照は接続セッションに属する

切断後に、以前の`CBCharacteristic`を使ってWriteを再開しません。再接続後は、必要に応じてServiceとCharacteristicを探索し直し、新しいセッションの参照へ置き換えます。

ファームウェア更新によってGATT構成を変えると、OS側のGATTキャッシュと実機の構成が一致しないことがあります。開発中にUUIDを頻繁に変更する問題と、出荷後の互換性設計は分けて扱います。キャッシュと再接続は[@sec:ch8-reconnect-cache]で整理します。
