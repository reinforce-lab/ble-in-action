## 8.5 GATT Valueを製品データへ変換する {#sec:ch8-value-format}

Core Bluetoothは、Characteristic Valueを`Data`としてアプリへ渡します。`Data`はバイト列であり、それだけでは測定値、設定、コマンド結果の意味を持ちません。アプリは、第4章で決めたValue Formatに従って検証し、製品データへ変換します。

本章では、例として次の形式を使います。

| Value | 形式 |
|---|---|
| LED State | `UInt8`。`0`がOFF、`1`がON |
| Measurement Value | Version `UInt8`、Sequence `UInt16`、測定値 `Int16` |
| Measurement Interval | `UInt16`、単位は秒 |
| Command Response | Version、Request ID、Status、Result |
| Device Event | Version、Event ID、Sequence、Payload |

実際のバイト配置は、ファームウェア側と共有するプロファイル仕様を正本にします。Swiftの`struct`をメモリー上の表現のまま送受信すると、PaddingやAlignmentに依存します。各フィールドを明示的に読み書きします。

### 長さを確認してから読む

`withUnsafeBytes`で型を直接Loadすると、バイト数やAlignmentを誤ったときに安全ではありません。短いValueでは、バイト単位で変換すると前提が明確になります。

```swift
enum ValueDecodeError: Error {
    case invalidLength(expected: Int, actual: Int)
    case unsupportedVersion(UInt8)
    case invalidValue
}

extension Data {
    func byte(at offset: Int) throws -> UInt8 {
        guard offset >= 0, count > offset else {
            throw ValueDecodeError.invalidLength(
                expected: offset + 1,
                actual: count
            )
        }
        return self[index(startIndex, offsetBy: offset)]
    }

    func uint16LE(at offset: Int) throws -> UInt16 {
        let low = try byte(at: offset)
        let high = try byte(at: offset + 1)
        return UInt16(low) | (UInt16(high) << 8)
    }

    func int16LE(at offset: Int) throws -> Int16 {
        Int16(bitPattern: try uint16LE(at: offset))
    }
}
```

Measurement Valueを次の型へ変換します。

```swift
struct Measurement: Equatable {
    let sequence: UInt16
    let value: Double

    static func decode(_ data: Data) throws -> Measurement {
        guard data.count == 5 else {
            throw ValueDecodeError.invalidLength(expected: 5, actual: data.count)
        }
        let version = try data.byte(at: 0)
        guard version == 1 else {
            throw ValueDecodeError.unsupportedVersion(version)
        }

        let sequence = try data.uint16LE(at: 1)
        let raw = try data.int16LE(at: 3)
        return Measurement(
            sequence: sequence,
            value: Double(raw) / 100.0
        )
    }
}
```

`Int16`を使うのは負の値を表すためです。`100`で割るのは、このValueが小数第2位までを固定小数点で表す契約だからです。エンディアン、符号、倍率、単位のどれかが抜けると、通信は成功していても値が一致しません。

### UUIDごとに型を分ける

すべてのValueを一つの汎用Dictionaryへ入れると、どのCharacteristicにどの形式が対応するか分かりにくくなります。UUIDで受信経路を選び、それぞれのDecoderへ渡します。

```swift
private func decodeValue(
    for characteristic: CBCharacteristic,
    data: Data
) throws -> DeviceUpdate {
    switch characteristic.uuid {
    case DeviceUUID.ledState:
        guard data.count == 1 else {
            throw ValueDecodeError.invalidValue
        }
        let value = try data.byte(at: 0)
        guard value <= 1 else {
            throw ValueDecodeError.invalidValue
        }
        return .ledState(value == 1)

    case DeviceUUID.measurement:
        return .measurement(try Measurement.decode(data))

    case DeviceUUID.interval:
        return .measurementInterval(try data.uint16LE(at: 0))

    case DeviceUUID.commandResponse:
        return .commandResponse(try CommandResponse.decode(data))

    case DeviceUUID.deviceEvent:
        return .deviceEvent(try DeviceEvent.decode(data))

    default:
        throw ValueDecodeError.invalidValue
    }
}
```

不正な長さや未知のVersionは、BLE切断とは別のデータエラーです。すぐ切断するか、そのValueだけを無視するかは製品要件で決めます。少なくとも、`Data`が短いときに既定値`0`へ置き換えて正常値のように表示しないでください。

### DecoderをBLEから独立して試験する

Decoderは`CBPeripheral`を必要としない純粋な処理にします。これにより、正常値だけでなく、短いValue、未知のVersion、最大値、負値を単体試験できます。

```swift
func testMeasurementDecode() throws {
    let data = Data([1, 0x2A, 0x00, 0xC4, 0x09])
    let value = try Measurement.decode(data)

    assert(value.sequence == 42)
    assert(value.value == 25.0)
}
```

旧原稿ではCore Bluetoothアプリを「デバイスドライバーに相当する部分を持つ」と説明していました。この視点は現在も有用です。アプリは画面を表示するだけでなく、UUID、Value Format、互換性、エラーを理解し、製品固有のデータをOS APIとの境界で変換します。

### 書き込み可能長は実行時に確認する

ATT MTUの既定値だけから「一回20バイト」と固定しません。Core Bluetoothには`maximumWriteValueLength(for:)`があり、Write Typeごとに書き込み可能な最大長を取得できます。

```swift
let limit = peripheral.maximumWriteValueLength(for: .withResponse)
guard payload.count <= limit else {
    throw DeviceCommandError.payloadTooLarge(limit: limit)
}
```

この値以下なら、製品プロトコル上の任意長データを無条件に送ってよいわけではありません。Value Formatで決めた最大長、バージョン、分割、再開、完全性確認は別に設計します。
