## 8.8 切断、再接続、キャッシュを扱う {#sec:ch8-reconnect-cache}

BLE接続は、利用者の移動、電波環境、Peripheralの再起動、Bluetooth OFF、アプリ操作によって終了します。切断を例外的な故障としてだけ扱わず、製品の状態遷移へ入れます。

```swift
func centralManager(
    _ central: CBCentralManager,
    didDisconnectPeripheral peripheral: CBPeripheral,
    error: Error?
) {
    invalidateConnectionSession()

    if shouldReconnect, central.state == .poweredOn {
        state = .recovering
        scheduleReconnect(to: peripheral)
    } else if let error {
        state = .failed(error.localizedDescription)
    } else {
        state = .idle
    }
}
```

`invalidateConnectionSession()`では、接続に属するCharacteristic参照、購読状態、進行中のRead／Writeを無効にします。一方、製品ID、利用者が設定した自動接続方針、最後に確定したDevice Stateは、必要に応じて保持します。

### 切断理由をアプリの方針へ変換する

Core BluetoothからErrorを受け取れる場合でも、その値だけで利用者の意図まで分かるとは限りません。アプリ自身が接続解除を要求したかを記録し、少なくとも次を分けます。

- 利用者が切断を選んだ
- アプリが別のデバイスへ切り替えるため切断した
- Peripheralまたは通信路の都合で切断した
- Bluetoothが利用できない状態へ変化した
- アプリがBackground／Suspended／Terminatedへ移行した

利用者が切断した直後に自動再接続すると、UIの意図と逆になります。通信断では再接続しても、明示的な切断では停止する、といった方針を先に決めます。

### 再接続後はReadyまで進め直す

再接続に成功しても、直前の`ready`へそのまま戻しません。接続後の処理を再実行します。

```text
Connecting
    ↓ didConnect
Discovering
    ↓ 必須Characteristicを確認
Synchronizing
    ↓ Notify購読と初期Readを確認
Ready
```

Core BluetoothがService情報を保持している場合でも、アプリの初期化処理は、探索済みか、購読済みか、値を同期済みかを確認して不足分から再開できるようにします。この性質は、状態復元にも使えます。

### 保存した識別子と再スキャンを使い分ける

`retrievePeripherals(withIdentifiers:)`は、アプリが保存した`CBPeripheral.identifier`から既知のPeripheralを取得する入口です。`retrieveConnectedPeripherals(withServices:)`は、システム上で接続済みのPeripheralをService UUIDから取得します。どちらも「現在近くにあり、すぐ接続できる」ことを保証する探索ではありません。

既知の製品へ再接続する場合は取得APIを試し、見つからない、または製品選択が必要ならスキャンへ戻します。Local Nameだけを永続IDとして保存しません。

### GATTキャッシュと互換性を分ける

OSは探索したGATT情報を保持することがあります。ファームウェア更新でServiceやCharacteristicを変更すると、アプリが期待する構成と見えている構成が一致しない場合があります。

開発中に毎回UUIDを変えて回避する方法は、製品の更新設計にはなりません。出荷後にGATT構成を変更するなら、次を決めます。

- ServiceとCharacteristicのUUIDを維持したままValue Versionを上げる範囲
- 必須Characteristicと任意Characteristic
- 古いアプリと新しいファームウェアの互換範囲
- Service Changedを利用する構成と、その前提
- Bonding、GATTキャッシュ、工場出荷状態へのリセットの関係

Core Bluetoothには、任意のPeripheralのGATTキャッシュをアプリから消去する公開APIはありません。非公開の回避策へ依存せず、アプリは探索結果とVersionを検証し、互換性がない場合は理由を表示して操作を止めます。

再接続間隔は固定の短周期にしません。即時再試行、段階的な待ち時間、利用者操作待ちを、製品の利用状況から選びます。長期間の接続待ちは、次節のBackground ModeとState Preservation and Restorationも含めて設計します。
