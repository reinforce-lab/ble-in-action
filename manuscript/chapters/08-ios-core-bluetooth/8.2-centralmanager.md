## 8.2 Bluetoothの利用可否とアプリ状態を管理する {#sec:ch8-central-state}

`CBCentralManager`は、Peripheralの発見と接続を管理する入口です。生成直後からBLE操作を始めるのではなく、まずManagerの状態を確認します。Appleの公開APIでは、`CBManager.state`の初期状態は`.unknown`であり、状態が更新されると`centralManagerDidUpdateState(_:)`が呼ばれます。

```swift
import CoreBluetooth

final class DeviceSession: NSObject {
    private var central: CBCentralManager!

    override init() {
        super.init()
        central = CBCentralManager(delegate: self, queue: nil)
    }
}

extension DeviceSession: CBCentralManagerDelegate {
    func centralManagerDidUpdateState(_ central: CBCentralManager) {
        switch central.state {
        case .poweredOn:
            handleBluetoothAvailable()
        case .poweredOff:
            handleBluetoothUnavailable(reason: "BluetoothがOFFです")
        case .unauthorized:
            handleBluetoothUnavailable(reason: "Bluetoothの利用が許可されていません")
        case .unsupported:
            handleBluetoothUnavailable(reason: "BLEを利用できません")
        case .resetting, .unknown:
            handleBluetoothUnavailable(reason: "Bluetoothの準備中です")
        @unknown default:
            handleBluetoothUnavailable(reason: "未知のBluetooth状態です")
        }
    }
}
```

`.poweredOn`は、端末がBLEを利用でき、Bluetoothが有効になっている状態です。スキャンや接続は、この状態を確認してから始めます。`.poweredOff`、`.unauthorized`、`.unsupported`は、いずれも「接続できない」という結果になりますが、利用者が取れる行動は異なります。

必要に応じて`CBManager.authorization`も確認します。これはBluetoothの利用許可を示し、Bluetooth無線がONかどうかを示す`state`とは別の情報です。利用目的のInfo.plist KeyやOSの権限表示は、対象とするiOSとSDKで出版前に再確認します。

### 接続状態だけでは足りない

アプリが`CBPeripheralState.connected`を確認できても、必要なCharacteristicをまだ探索していないことがあります。そこで、本章のアプリは次の状態を区別します。

```swift
enum DeviceSessionState: Equatable {
    case bluetoothUnavailable
    case idle
    case scanning
    case connecting
    case discovering
    case synchronizing
    case ready
    case recovering
    case failed(String)
}
```

`ready`は、接続だけでなく、必須Characteristicの探索、Notify購読、初期Readまで終わった状態です。UIは`CBPeripheral.state`を直接表示するのではなく、このアプリ状態を表示します。

### 行いたい操作を状態変化まで保持する

利用者がBluetooth OFFの状態で「接続」を押した場合、その場でスキャンを呼んでも動作しません。アプリは、利用者が行いたい操作と、Bluetoothを現在利用できるかを分けて保持します。

```swift
private var shouldConnect = false

func start() {
    shouldConnect = true
    if central.state == .poweredOn {
        startScanning()
    }
}

private func handleBluetoothAvailable() {
    if shouldConnect {
        startScanning()
    }
}
```

Core BluetoothのDelegate Queueに`nil`を指定した場合、CallbackはMain Queueで受け取ります。専用Queueを指定する場合は、UI更新をMain Actorへ渡し、状態の所有者を複数Queueから無秩序に変更しない構成にします。

【アプリ開発者の方へ】

「接続済み」と「操作可能」を一つのBoolにすると、探索途中や再接続直後にWriteできるように見えてしまいます。`ready`へ到達する条件を製品仕様の必須Characteristicと初期同期から決めてください。
