## 8.7 Notify／Indicateで更新とイベントを受け取る {#sec:ch8-notify}

値が変化したかをCentralが短い周期でReadし続けると、変化がないときにも通信が発生します。Peripheral側で変化を検出できる値は、NotifyまたはIndicateを購読すると、必要なときに更新を受け取れます。

本章では、Measurement Value、Command Response、Device Eventを購読します。

```swift
private func subscribe(_ uuid: CBUUID) {
    guard let characteristic = characteristics[uuid] else {
        fail("Characteristicがありません: \(uuid)")
        return
    }

    let supportsUpdates =
        characteristic.properties.contains(.notify)
        || characteristic.properties.contains(.indicate)

    guard supportsUpdates else {
        fail("Notify／Indicateに対応していません: \(uuid)")
        return
    }

    peripheral?.setNotifyValue(true, for: characteristic)
}
```

`setNotifyValue(true, for:)`の呼び出し直後に購読済みとして扱いません。設定結果は`didUpdateNotificationStateFor`で確認します。

```swift
func peripheral(
    _ peripheral: CBPeripheral,
    didUpdateNotificationStateFor characteristic: CBCharacteristic,
    error: Error?
) {
    if let error {
        recordFailure(operation: "subscribe", uuid: characteristic.uuid, error: error)
        return
    }

    subscriptionState[characteristic.uuid] = characteristic.isNotifying
    updateReadyStateIfPossible()
}
```

Core Bluetoothでは、NotifyとIndicateの受信はどちらも`didUpdateValueFor`へ届きます。IndicateのATT Confirmationをアプリが個別に送るAPIはありません。どちらを使うかは、Peripheral側のCharacteristic Propertiesを含む製品仕様で決めます。

### 更新を製品状態へ反映する

Valueを受け取ったら、[@sec:ch8-value-format]のDecoderへ渡し、Device Stateを更新します。

```swift
struct DeviceState: Equatable {
    var ledOn: Bool?
    var measurement: Measurement?
    var measurementInterval: UInt16?
    var commandResults: [UInt16: CommandResponse] = [:]
    var lastEvent: DeviceEvent?
}

private func apply(_ update: DeviceUpdate) {
    switch update {
    case .ledState(let on):
        deviceState.ledOn = on
    case .measurement(let value):
        deviceState.measurement = value
    case .measurementInterval(let seconds):
        deviceState.measurementInterval = seconds
    case .commandResponse(let response):
        pendingCommands.removeValue(forKey: response.requestID)
        deviceState.commandResults[response.requestID] = response
    case .deviceEvent(let event):
        deviceState.lastEvent = event
    }
    publish(deviceState)
}
```

UIが直接`CBCharacteristic.value`を読む構成にすると、Read、Notify、再接続後の初期同期が別々の経路になります。Device Stateへ集約すれば、値の由来が違っても同じ画面状態を作れます。

### 通知頻度と表示頻度を分ける

センサー値を`100 ms`ごとに受信しても、画面グラフを毎回再描画する必要はありません。受信、保存、表示の頻度を分けます。

```text
BLE受信: 100 msごと
    ├─ 最新値をDevice Stateへ反映
    ├─ 必要な値を保存Queueへ渡す
    └─ UIは250 msごとにまとめて更新
```

間引く場所を曖昧にすると、Peripheralが送信していないのか、iOSで受信していないのか、UIが表示していないのか分からなくなります。受信Sequenceを記録し、表示の間引きとは別に欠落を判断します。

### 購読中でもすべてを受け取れるとは限らない

NotifyはATTの応答を伴いません。Indicateは一件ずつConfirmationを伴いますが、アプリが過去のすべてのイベントを必ず取得できることを意味しません。切断中の更新、Peripheral内のQueueあふれ、アプリの状態、製品独自の上書き方針があります。

現在状態は再接続後にReadできるようにします。失ってはいけないイベントは、Sequence、履歴、ACK、再取得手順などを製品仕様へ追加します。

購読を止める場合は`setNotifyValue(false, for:)`を使います。ただし、切断する直前に必ず解除する、という順序をアプリの正しさの前提にはしません。切断後は、接続セッションの購読状態を無効として扱い、再接続時に必要な購読を成立させます。
